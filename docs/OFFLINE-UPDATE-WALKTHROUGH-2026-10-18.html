02

인터넷이 연결된 준비 PC에서 받은 파일을 승인된 반입 절차로 옮깁니다.

  1. ZIP과 게시된 SHA256을 함께 반입합니다.
  2. 서버에서 ZIP의 SHA256을 다시 계산합니다.
  3. 일치하면 D:\SAW-media-20261018에 압축을 풉니다.
  4. 그 폴더 바로 아래에 update.ps1과 release-manifest.json이 있는지 확인합니다.
ZIP 지문 계산 · 경로는 실제 반입 위치로 변경

다른 버전 ZIP에는 해당 버전의 공개 지문을 사용합니다.

압축을 푼 전체 매체 검증

03

분석 작업을 마치고 전체를 중지합니다

사용자 접속을 잠시 막고 업로드·분석이 끝난 것을 확인합니다. 설치 방식에 맞는 절차만 사용합니다.

서비스 설치: 관리자 PowerShell

세 서비스가 이 설치를 가리키는지 먼저 확인
Get-CimInstance Win32_Service |
  Where-Object { $_.Name -in @("saw","saw-opensearch","saw-postgresql") } |
  Select-Object Name,State,StartMode,PathName |
  Format-List

세 서비스가 모두 있고 각 PathName이 실제 C:\SAW 아래의 실행 파일을 가리키는지 확인하세요. 서비스가 없거나 다른 설치를 가리키면 중지·시작 명령을 진행하지 않습니다.

웹 → 검색 → DB 순서로 중지
Stop-Service -Name "saw" -ErrorAction Stop
(Get-Service "saw").WaitForStatus("Stopped", [TimeSpan]::FromSeconds(180))
Stop-Service -Name "saw-opensearch" -ErrorAction Stop
(Get-Service "saw-opensearch").WaitForStatus("Stopped", [TimeSpan]::FromSeconds(180))
Stop-Service -Name "saw-postgresql" -ErrorAction Stop
(Get-Service "saw-postgresql").WaitForStatus("Stopped", [TimeSpan]::FromSeconds(180))
Get-Service -Name "saw","saw-opensearch","saw-postgresql"

세 항목 모두 Stopped인지 확인합니다. 중지 실패나 시간 초과가 나면 다음 단계로 넘어가지 않습니다. 점검 중 재부팅하거나 다른 감시 도구·예약 작업이 다시 켜지 않도록 유지보수 절차를 적용하세요.

사용자 프로세스 설치: 기존 실행 계정

앱·검색·DB 전체 중지
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\SAW\saw-ctl.ps1" stop
중지 상태 확인
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\SAW\saw-ctl.ps1" status
이 절차는 원래 -NoAdmin으로 설치한 경우입니다. 서비스 설치를 사용자 프로세스 방식으로 바꾸는 명령이 아닙니다.

중지 전에 남길 메모

  • 평소 접속하던 주소
  • 확인할 기존 조사 이름과 건수
  • 원문·노트가 있는 조사 하나
  • 업데이트 전 버전·설치 경로
  • 유지보수 담당자와 시간

비밀번호·OTP·비밀키는 메모나 화면 캡처에 넣지 않습니다.

중지되지 않으면 적용하지 않습니다.
브라우저만 닫아도 서버는 실행 중일 수 있습니다. plan은 프로세스·서비스·포트가 남아 있으면 변경 없이 거부합니다.
검증 범위
서비스 명령은 설치 코드에 따른 운영 안내입니다. 별도 합성 사용자 프로세스 시험 결과를 실제 관리자 서비스 시험 성공으로 표시하지 않습니다.
04

먼저 점검만 실행합니다

-Action plan은 설치 조건·변경 여부·필요 공간을 확인합니다. 앱 버전은 바꾸지 않습니다. PowerShell의 현재 위치도 C:\SAW 밖으로 옮깁니다.

중지된 기존 설치를 점검
Set-Location "D:\SAW-media-20261018"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\SAW-media-20261018\update.ps1" -Action plan -InstallRoot "C:\SAW" -BundleDir "D:\SAW-media-20261018"
다음 단계로 갈 수 있는 상태
"status": "ready_stopped"

예상 상태값 설명입니다. 이 안내를 열었다는 뜻이 아니라 실제 명령 출력에서 확인해야 합니다.

출력 항목뜻
snapshot_bytes복구본에 담을 기존 설치 전체 크기
required_free_bytes이번 적용에 필요한 여유 공간
free_bytes설치 드라이브에 남은 공간
C:\SAW의 복구본은 같은 C:에 둡니다.
새 매체를 D:에 놓아도 C:의 복구 공간은 따로 필요합니다. 공간 부족을 피해 복구본만 D:로 바꾸는 것은 지원하지 않습니다.

예를 들면

기존 설치 전체가 30GB라면 적용에 약 30GB와 새 앱 등의 공간이 필요합니다. 되돌리기까지 준비하려면 시작 전 C:에 약 60GB와 새 앱·추가 자료를 위한 여유를 확보하세요. 정확한 적용 최소치는 required_free_bytes로 확인합니다.

되돌릴 때도 복구본 전체를 한 번 더 준비할 공간과 64MiB가 필요합니다. plan 통과만으로 되돌리기 공간까지 보장되지는 않습니다. 적용 후 자료 증가분도 고려합니다.

기존 버전을 못 찾는 경우

installed-release-manifest.json이 없는 구형 설치라면 원래 사용한 매체를 정확히 지정합니다.

위 plan/apply 명령 끝에 추가할 인수
-BaselineBundleDir "D:\SAW-media-original"

폴더 이름이나 비슷한 날짜로 추정하지 않습니다. 잘못된 매체를 넣거나 기존 소스를 직접 수정했다면 점검에서 거부될 수 있습니다.

05

전체 복구본을 만든 뒤 새 앱을 적용합니다

복구본 경로는 아직 존재하지 않는 새 폴더여야 합니다. 같은 명령을 무작정 반복하지 마세요.

복구본 생성 + 앱 전환
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\SAW-media-20261018\update.ps1" -Action apply -InstallRoot "C:\SAW" -BundleDir "D:\SAW-media-20261018" -RecoveryPoint "C:\SAW-r-20261018"
기존 설치 전체 복사→내용·권한 확인→새 앱으로 전환→중지 상태 유지
적용 완료 후 예상 상태
"status": "applied_stopped_schema_pending"

앱 파일 전환까지 끝났다는 뜻입니다. DB 변경과 정상 기동 확인은 다음 단계입니다.

계정·MFADB·검색 색인증거 원본환경 설정·비밀키모델 파일

복구본에는 기존 설치의 계정·데이터·비밀키까지 들어 있습니다. 권한이 제한된 서버 내부에 보관하고 GitHub나 공유 자료실에 올리지 않습니다.

오래 걸려도 창을 닫지 않습니다

원본 자료와 모델이 클수록 전체 복사·검증 시간이 늘어납니다. 설치 폴더를 건드리거나 두 번째 업데이트를 동시에 실행하지 마세요.

오류나 중단이 발생하면
기존 설치와 새 복구본을 그대로 보존합니다. 파일을 지우거나 app만 수동 교체하지 않습니다. 결과·로그를 확인해 복구 여부를 결정하세요.

이 앱 업데이트는 서비스 등록·방화벽·기존 서비스 설정이나 Python/DB/검색 런타임을 새로 설치하지 않습니다. 런타임 조합 변경은 별도 절차가 필요합니다.

06

DB와 검색이 준비된 뒤 앱을 시작합니다

기존 주소·인증서·계정을 그대로 사용합니다. 첫 시작에 필요한 DB 마이그레이션이 실행됩니다.

DB → 검색 순서로 시작
Start-Service -Name "saw-postgresql" -ErrorAction Stop
(Get-Service "saw-postgresql").WaitForStatus("Running", [TimeSpan]::FromSeconds(180))
Start-Service -Name "saw-opensearch" -ErrorAction Stop
(Get-Service "saw-opensearch").WaitForStatus("Running", [TimeSpan]::FromSeconds(240))

시작 실패나 시간 초과가 나면 다음 명령으로 넘어가지 않습니다. 서비스의 Running만으로 검색 준비가 끝났다고 판단하지 말고 기존 로그와 아래 상태 조회로 준비를 확인합니다.

기존 설정의 검색 포트로 상태 확인

Invoke-RestMethod -Uri "http://127.0.0.1:$($cfg.opensearchPort)/_cluster/health" -TimeoutSec 10 |

Start-Service -Name "saw" -ErrorAction Stop
(Get-Service "saw").WaitForStatus("Running", [TimeSpan]::FromSeconds(180))
Get-Service -Name "saw","saw-opensearch","saw-postgresql"

상태 확인
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\SAW\saw-ctl.ps1" status

준비 확인

  • DB가 정상적으로 기동했습니다.
  • OpenSearch가 응답합니다.
  • 검색 상태가 red가 아닙니다.
  • 앱 시작 오류가 없습니다.
  • 평소 주소에서 로그인 화면이 열립니다.

단일 노드 환경은 복제본 배치 때문에 yellow일 수 있습니다. 기존 운영 기준과 로그를 함께 확인합니다.

관리자 계정을 다시 만들거나 초기 비밀번호로 바꾸지 않습니다. 기존 계정으로 로그인합니다. 인증서 오류를 우회하기 위해 검증을 끄지 마세요.
시작이 실패하면 분석가의 접속을 다시 열지 않습니다. 현재 상태와 로그를 보존하고 8단계의 전체 복구를 검토합니다.
07

로그인과 기존 분석 자료를 함께 확인합니다

파일 적용 결과만으로 끝내지 않고, 분석가가 실제로 쓰는 흐름을 확인합니다.

  1. 기존 계정·비밀번호·MFA로 다시 로그인합니다.
  2. 업데이트 전에 기록한 조사와 분석 건수를 비교합니다.
  3. 기존 증거의 원문을 열고, 저장한 노트를 확인합니다.
  4. 승인된 합성 로그·PCAP로 분석 작업을 실행합니다.
  5. 전체를 다시 중지·시작한 뒤 같은 자료를 확인합니다.

정상 확인 후에만 접속을 다시 엽니다

로그인만 되지만 원문·검색·분석이 안 되는 상태도 있을 수 있습니다. 실제 업무 흐름과 재시작 후 보존을 함께 확인해야 합니다.

업데이트 직후부터 새 업무 자료를 계속 입력하면, 전체 시점 복구 시 그 자료를 따로 처리해야 합니다. 검수가 끝날 때까지 일반 분석가 접속을 제한하는 편이 안전합니다.

실제로 확인한 범위

Windows 11 · 사용자 프로세스 설치 · 합성 자료로 실제 적용, 한 번 더 종료·시작, 전체 복구를 실행했습니다. 실제 PostgreSQL·OpenSearch·HTTPS 로그인/MFA와 기존 자료를 비교했습니다.

이번 측정: 점검 453.81초 / 적용 748.02초 / 복구 601.58초. 실제 서버의 자료량·디스크·부하에 따라 달라집니다.

제품 브라우저 접속은 시험 인증서 신뢰 문제로 차단됐고 우회하지 않았습니다. 실제 C: 운영 서버·LTSC 2019·관리자 서비스·새 로그/PCAP 업로드 분석·모델 실행을 이번 결과로 완료 처리하지 않습니다.

08

문제가 있으면 업데이트 직전 전체로 복구합니다

3단계처럼 전체를 중지하고 PowerShell의 현재 위치를 C:\SAW 밖으로 옮깁니다. 구버전 app 폴더만 덮어쓰지 않습니다.

새 매체에서 원래 C:\SAW로 전체 시점 복구
Set-Location "D:\SAW-media-20261018"

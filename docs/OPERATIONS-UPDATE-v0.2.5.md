# SAW 0.2.5 운영 업데이트 절차 (2026-11-10)

기존 SAW 0.2.4 설치를 0.2.5로 올리는 운영자용 절차입니다. 폐쇄망 Windows 10 Enterprise LTSC 2019 x64를 대상으로 씁니다. 화면 그림과 자세한 설명은 매체 안의 `app/docs/DOUBLE-CLICK-UPDATE-GUIDE.md`, `app/docs/OFFLINE-UPDATE-GUIDE.md`를 함께 봅니다.

## 0. 먼저 알아둘 것

- 매체: `SAW-0.2.5-pilot.<날짜>-model-free-win-x64.zip`. 모델 가중치는 들어 있지 않습니다. 크기와 SHA-256은 함께 전달된 `SHA256SUMS.txt`와 릴리스 설명에 적혀 있습니다.
- **이 매체는 후보입니다.** 개발 PC(Windows 11 Pro 26200)의 격리 시험 설치에서 0.2.4 → 0.2.5 업데이트·복구를 실제로 실행했습니다. **대상 LTSC 2019에서의 실행, 관리자 서비스 방식, 재부팅 뒤 동작은 아직 확인하지 못했습니다(PENDING_ENV).** 운영 서버에 적용하기 전에 같은 환경의 시험 서버에서 이 절차를 먼저 한 번 실행하세요. 그 결과가 나오기 전에는 "운영 적용 검증 완료"로 부르지 않습니다.
- 0.2.5에서 달라지는 것
  - 분석 사례집 W01~W60: 사례 60개, 단계 300개, 화면 그림 120장, 사례별 원본 ZIP 60개(각각 fw.csv·ndr.csv·followup.json). 모두 가상 자료입니다.
  - 골든셋 후보함: 사례집 사례나 조사를 한 번 눌러 후보로 모으고, 고른 것만 골든셋으로 저장·내보내기.
  - 데이터베이스에 표 1개(골든셋 후보)를 **추가만** 합니다(스키마 0025 → 0026). 기존 계정·조사·증거·탐지·설정은 바뀌지 않습니다. 사례집을 열어도 운영 자료 건수는 늘지 않습니다.

## 1. 반입과 압축 해제

1. ZIP과 `SHA256SUMS.txt`를 폐쇄망으로 반입합니다.
2. PowerShell에서 `Get-FileHash .\SAW-0.2.5-...zip -Algorithm SHA256` 결과가 `SHA256SUMS.txt`의 값과 같은지 확인합니다.
3. 기존 설치 폴더 **밖의** 새 빈 폴더에 압축을 풉니다. 예: `D:\SAW-media-0.2.5`. 기존 설치 폴더나 이전 매체 폴더 위에 풀지 않습니다.
4. 설치 드라이브의 여유 공간을 확인합니다. 업데이트는 적용 전에 설치 전체의 복구본을 같은 드라이브에 만들므로, 현재 설치 폴더 크기만큼의 공간이 더 필요합니다.

## 2. 업데이트

1. 분석가에게 접속 중단을 알리고, 진행 중인 업로드·분석 작업이 끝났는지 확인합니다.
2. 압축을 푼 폴더의 **UPDATE-SAW.cmd**를 더블클릭합니다. 창 제목은 "SAW 기존 설치 업데이트 · 계정과 분석 자료 유지"입니다.
   - 일반 사용자 방식(NoAdmin) 설치는 설치할 때 쓴 **같은 Windows 계정**으로 실행합니다.
   - Windows 서비스 방식 설치는 창의 안내에 따라 **관리자 권한으로 열기**를 누릅니다.
3. **기존 설치 폴더**를 선택합니다(예: `D:\SAW`). 새 매체 폴더는 자동으로 표시됩니다.
4. **복구본 폴더**에 아직 없는 새 이름을 지정합니다(예: `D:\SAW-r-20261110`). 설치와 같은 드라이브여야 하고, 설치·매체 폴더 안에 두지 않습니다. 이 경로를 적어 둡니다.
5. **설치 점검**을 누릅니다. 서버를 멈추거나 파일을 바꾸지 않고 설치 방식·파일·설정·공간을 확인합니다. 점검이 막히면 표시된 사유를 해결한 뒤 다시 점검합니다. 복구본을 지워서 공간을 만들지 않습니다.
6. **서버 중지 동의**를 체크하고 **업데이트 시작**을 누릅니다.
7. 매체 확인 → 서버 중지 → 전체 복구본 생성 → 새 앱 적용(스키마 0026) → 서버 시작·접속 확인 순서로 진행됩니다. 진행 중에는 창을 닫거나 전원을 끄지 않습니다.
8. 완료 화면에서 **복구본 위치**가 4번에서 적은 경로와 같은지 확인합니다.

적용 중 실패하면 프로그램이 업데이트 직전 상태로 스스로 되돌리고 결과 화면에 상태를 표시합니다. 이때는 **기록 폴더** 단추로 기록 위치를 확인해 전달합니다.

## 3. 업데이트 뒤 확인

| 확인 | 기대 |
|---|---|
| 로그인 | 기존 계정·비밀번호·MFA 그대로 로그인됨 |
| 업데이트 창 결과 | 완료로 표시되고 적용한 버전이 0.2.5, 스키마가 0026 |
| 조사 목록 | 기존 조사·관계사·증거가 그대로 보임 |
| 왼쪽 메뉴 **분석 사례집** | 사례 60개(W01~W60)가 목록에 보이고 검색됨 |
| 사례 하나 열기(예: W26) | 단계 5개와 화면 그림이 보이고, **이 사례 원본 ZIP 받기**로 fw.csv·ndr.csv·followup.json이 든 ZIP이 받아짐 |
| 왼쪽 메뉴 **골든셋 후보함** | 빈 목록이 열림. 사례 화면의 **골든 후보로 담기**를 누르면 한 건이 생기고, 다시 눌러도 한 건 |
| 조사 건수 | 사례집을 열고 닫은 뒤에도 조사·증거·탐지 건수가 업데이트 전과 같음 |
| 종료·재시작 | 정상 종료 뒤 다시 시작해도 자료와 후보가 남아 있음 |

확인에는 가상 자료만 씁니다. 사례 ZIP을 실제 조사에 올려 보려면 운영 조사와 섞이지 않게 시험용 조사를 따로 만듭니다.

## 4. 문제가 있을 때 되돌리기

1. 같은 새 매체의 **UPDATE-SAW.cmd**를 다시 실행합니다.
2. 기존 설치 폴더를 선택하고, **복구본 선택**으로 2절 4번에서 만든 복구본 폴더를 선택합니다.
3. **서버 중지 동의**와 **계정·자료를 백업 시점으로 되돌린다는 확인**을 체크합니다.
4. **이전 상태 복구**를 누릅니다. 0.2.4 앱과 업데이트 직전의 계정·자료로 돌아갑니다.
5. **SAW 열기**로 기존 계정과 자료를 확인합니다.

- 복구는 전체 시점 복구입니다. 업데이트 뒤에 담은 후보, 새 조사·업로드, 바꾼 비밀번호·MFA·권한도 복구본 시점으로 돌아갑니다.
- 복구 직전 상태는 별도 보관 폴더에 남고 창에 위치가 표시됩니다. 두 시점의 자료를 자동으로 합치지 않습니다.
- 복구본·설치·보관 폴더를 직접 지우거나 덮어쓰지 않습니다. 복구가 실패해도 자동 삭제·자동 반복은 없습니다. **기록 폴더**의 기록을 전달해 주세요.
- 같은 0.2.5 매체를 한 번 더 적용해도 안전합니다. 자료와 후보는 그대로이고 중복이 생기지 않습니다.

## 5. 실제로 확인한 범위

- 개발 PC(Windows 11 Pro 26200, NoAdmin 사용자 프로세스 방식, 합성 자료)에서 게시된 0.2.4 매체로 설치한 뒤 이 절차의 창 단추 동작으로 0.2.5 업데이트, 주입한 실패 뒤 자동 복구, 업데이트 성공 뒤 이전 상태 복구, 두 번째 업데이트, 같은 매체 재적용, 사례집 60개 확인, 후보 담기·저장·내보내기 유지를 단계별로 실행했습니다. 결과는 `app/docs/verification/golden-candidates-20261105.md`와 릴리스 설명에 있습니다.
- 확인하지 못한 것(PENDING_ENV): 대상 LTSC 2019(17763)에서의 실행, 관리자 서비스 설치·재부팅, 운영 규모 자료에서의 업데이트 시간과 성능, native OpenSearch/PostgreSQL 운영 구성.
- 운영 서버는 업데이트하지 않았습니다.

# 탐지 룰을 등록하고 결과를 확인하는 방법

2026-10-14 새 복사본 기준입니다. 메뉴 **탐지 룰 → 등록·탐지 사용법**에도 이 순서가 있습니다. 실제 사건 원문을 예제나 공유 파일에 무심코 넣지 말고 합성 자료로 먼저 시험하세요.

## 1. 먼저 룰 종류를 확인하세요

| 종류 | 들어 있는 위치 | 변경·적용 |
|---|---|---|
| 웹 시그니처 | `saw/detectors/packs/web_signatures.yaml` | 조건과 examples/benign를 편집 → 합성 시험/검토 → 서버 재시작 → 기존 증거 다시 처리 |
| 공격 흐름 | `saw/detectors/packs/scenarios.yaml` | 같은 개체의 단계·순서·시간을 정의 → 시험/검토 → 재시작/재분석 |
| NDR 연결 기준 | `saw/detectors/packs/ndr_policies.yaml` | 내부망/허용 포트/업무시간/전송량을 조직 기준으로 검토한 뒤 켬. 기본은 꺼짐 |
| 기본 행동 탐지기 | `saw/detectors`의 Python | 서버 기능이므로 코드 검토·시험·배포 필요 |
| 직접 작성하는 Sigma | 탐지 룰 후보 화면과 DB의 버전 기록 | 화면 작성 → 시험 → 다른 사람 승인 → 이후 조사 분석에 적용 |

파일의 `version: 1`은 묶음 형식입니다. 내용을 바꿀 때는 배포 소스와 변경 기록도 함께 관리하세요. 내보낸 JSON/YAML은 확인용이며 업로드만으로 서버 설정을 자동 교체하지 않습니다.

## 2. 예시 룰을 만들어 보세요

1. **탐지 룰 → 탐지 룰 후보 → 새 Sigma 룰**을 누릅니다. 작성 권한이 필요합니다.
2. 기본 예시는 합성 경로 `/saw-demo/restricted-export`에 POST하고 HTTP200인 기록입니다. 반복 조건은 같은 출발지에서 10분 동안 5건 이상입니다. 실제 적용 전 보호할 업무 경로와 허용 작업을 확인해 바꾸세요.
3. **구문 검사**를 누릅니다. 구문 통과는 오탐이 없다는 뜻이 아닙니다.
4. **일치·정상 예제**에 합성 정규화 기록을 적습니다. `expected`는 `match` 또는 `no_match`, `event`에는 필드를 넣습니다. 예제 편집 반영 후 **저장**합니다.

```json
[
  {"expected":"match","event":{"data_source":"web","url_path":"/saw-demo/restricted-export","method":"POST","status_code":200}},
  {"expected":"no_match","event":{"data_source":"web","url_path":"/saw-demo/health","method":"GET","status_code":200}}
]
```

예제 일치 검사는 개별 기록의 조건을 확인합니다. 5회 반복 같은 집계 조건은 충분한 건수와 시각·출발지가 있는 합성 조사에 적용해 따로 확인하세요. 평범한 `/api/`, `admin`, `login` 또는 HTTP200만으로 광범위하게 잡는 룰은 피하세요.

## 3. 시험하고 승인하세요

1. **접근 가능한 과거 자료 시험**을 실행합니다. 현재 계정이 접근 가능한 조사만 대상입니다.
2. 일치 건수와 검사 건수, 정상/공격 판정 사례, 예제 결과를 확인합니다. 라벨이 없으면 정탐·오탐 비율을 안다고 할 수 없습니다. 일부 범위만 검사했거나 오류가 있으면 승인 근거로 사용하지 않습니다.
3. 작성자와 다른 Senior 또는 SOC Manager가 현재 버전을 검토하고 승인합니다. 작성자가 자기 룰을 승인할 수 없습니다.
4. 승인된 지원 Sigma는 다음 조사 분석에 사용됩니다. 기존 조사에서는 **재분석**하고 Finding의 룰 ID/버전과 실제 일치 원문을 확인합니다. 규칙 변경 뒤에는 새 버전으로 다시 시험·승인해야 합니다.

Suricata 형식 기록이나 문자열 시험을 실제 Suricata 엔진 replay 성공으로 세지 마세요. 현재 내부 자동 적용 대상은 지원 조건의 승인된 Sigma입니다. 외부 SIEM/보안 장비에는 사람이 변경 절차로 배포하며 SAW는 자동 배포하지 않습니다.

## 4. 룰을 파일로 내려받으세요

- **기본 탐지 목록 → 전체 기본 룰 JSON/YAML 다운로드**: 검색 필터와 관계없이 전체입니다. 시그니처의 실제 match/all/regex/제외조건·메서드·응답조건·전체 일치/정상 예제, 켜짐 상태, 공격 흐름, NDR 기준을 포함합니다. 코드 탐지기는 ID/버전/지원 자료 설명만 포함합니다.
- **탐지 룰 후보 → 현재 룰 묶음 JSON 다운로드**: 사용자 룰의 현재 버전·논리·임계값·예외·상태를 포함합니다. 과거 시험 이벤트·원문·조사 스냅샷은 포함하지 않습니다.
- **개별 룰 → 원본 룰 파일 다운로드**: 해당 룰의 원본 논리를 받습니다. SAW의 별도 임계값·예외까지 확인하려면 위의 묶음 JSON도 함께 받으세요. 원본 Sigma 파일만 외부 엔진에 넣으면 SAW 반복 조건이 자동 전달되지 않습니다.
- 변환 미리보기는 지원하는 문법에 한합니다. Logpresso 등 미지원 변환은 오류를 표시합니다. 내보내기는 승인·배포 상태를 바꾸지 않으며 감사 기록을 남깁니다.

한 파일은 최대2MiB, 사용자 묶음은 최대1000개입니다. 초과하면 일부를 성공 파일처럼 내보내지 않고 오류를 표시합니다. 개별 룰로 범위를 나누어 받으세요.

## 5. 결과를 읽는 기준

일치 자체가 정탐 확정은 아닙니다. 승인된 점검/배치/백업, 프록시·NAT의 여러 사용자, 수집 누락과 중복을 함께 보세요. 차단된 악성 시도는 차단됐다는 이유로 오탐이 아니며, HTTP200도 침해 성공의 증거가 아닙니다. Story에서 흐름을 보고 Evidence의 비교 근거를 확인한 뒤 Raw로 해당 기록을 점검하세요.

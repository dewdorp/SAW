## 프로그램 업데이트와 전체 복구

실제 기존10/12 매체 설치를 대상으로 다음 순서를 모두 통과했습니다.

1. 전체 중지 후 파일27,672개·1,559,873,128바이트의 복구본을 만들고 내용·DACL을 대조했습니다.
2. 새 앱 적용 후 DB0011→0014를 실제 실행했습니다. 기존 이벤트9건·Finding8건·노트·TLS·MFA·암호화 키·원본 증거가 유지됐습니다.
3. 합성 사례A를 새로 반입해 행위 분석과 SVG가 든 HTML 보고서를 생성했습니다. 종료·시작 후 저장된 결과 SHA가 일치했습니다.
4. DB·색인·앱을 함께0011 시점으로 복구했습니다. 이전 조사·MFA·키는 유지됐고 업데이트 후 만든 조사는 복구 시점에 없었습니다. 최신 상태는 retained 폴더에 별도 보존됐습니다.
5. 새 복구 지점을 사용해 다시0014를 적용하고, 새 행위 분석·종료·재시작·결과 SHA 보존을 확인했습니다.

합성 사례의10초 요청40건,60초 경로40개,60초404응답40건을 계산했습니다. 이는 탐색 행위의 확인 후보이며 실제 침해·도구·AI 사용 확정이나 은행 자료의 정확도 평가가 아닙니다.

업데이트는 동일한 런타임과 의존성 조합의 중지한 로컬 설치만 지원합니다. 파일 해시·DACL을 보존하며 소유자/SACL 보존은 지원·검증 범위가 아닙니다. 복구 시 업데이트 후 자료는 retained 폴더에 남고, 이전 시점에 자동 병합되지 않습니다. retained의 설정에는 원래 절대경로가 남으므로 직접 기동하지 않습니다.

## 자동 검증과 독립 검토

최종 서버 **1079통과·2건너뜀(559.62초)**, 화면 **177통과(31파일,41.69초)**, TypeScript·UI build 성공. 주요 오류 대상 Ruff 검사와 PowerShell4파일 구문 검사도 통과했습니다. 화면 코드는 해당 검증 후 변경하지 않았습니다. 업데이트56·설치/번들28·매체27개 집중 시험은 전체 시험과 중복되므로 합산하지 않습니다.

독립 검토에서 프로세스 조회 접근 거부, WinSW 실행기 검증 누락, 기존 폴더 소유자 확인 누락, 읽을 수 없는 하위 폴더의 조용한 누락을 발견해 회귀시험과 함께 수정했습니다. 실제 Windows 목록 조회 거부를 적용해 업데이트·매체 inventory/seal/verify가 실패하는지 확인했고, 각 finding의 독립 재검토를 마쳤습니다. 설명서의 매체 루트 링크·기존 설치 재실행·manifest 해시·PostgreSQL 로그/권한 설명도 실제 코드와 맞췄습니다.

최초 전체 서버 시험은 안내 문서 기대값을 수정하는 동안 실행해 해당 시험1개가 실패했습니다(1003통과2건너뜀). 이후 파일을 고정한 전체 실행 결과를 위에 별도로 기록합니다. 이 중간 결과를 통과로 바꾸지 않았습니다. 기존 Starlette/React Router 경고·큰 UI chunk 경고와 과거 History503 원인 미확정 상태는 유지합니다.

## 실제 전환에서 발견한 문제

후보2 첫 적용은 복구본의 DACL 상속 상태가 원본과 달라 앱 교체 전에 거부됐습니다. 동일 ACE라도 AUTO_INHERITED 상태가 사라지는 현상을 합성 다층 권한으로 재현했고, 원본 권한을 정확히 유지하는 수정과 재검증을 진행했습니다. [Microsoft 제어 비트 문서](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-descriptor-control)를 참고하되 실제 Win32 왕복 비교를 유지했습니다.

사용자 지정 설치 경로의 넓은 상위 권한이 앱·암호화 키로 이어지는 별도 문제도 확인했습니다. 신규 설치 루트 보호와 기존 설치 권한 사전 검사를 보완하며, 업데이트 staging에 미디어의 넓은 권한을 가져오지 않도록 했습니다. 기존 합성 QA 설치만 별도로 권한을 정비하고 원래 앱·키·환경·증거 파일 해시가 그대로임을 확인했습니다. 운영 설치의 권한을 수정하거나 자동 정비 완료로 보고하지 않습니다.

후보4의 실제 복구에서는 임시 이름이 길어져 폴더 길이251에서 WinError206이 발생했습니다. 원래 설치 교체 전 중단됐고 부분 staging과 완전한 복구본을 보존했습니다. [Microsoft 경로 제한](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation)에 맞춰 짧은 임시 이름과 사전 경로 검사를 추가했습니다. 도구의 보수적 한도는 UTF-16 기준 폴더247·파일259이며, 운영 레지스트리를 변경하지 않습니다. 수정 후 실제 결과는 위 업데이트·복구 항목에 별도로 기록합니다.

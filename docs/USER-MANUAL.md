## 2026-10-15 추가 기능 안내

- **오프라인 룰·파서**: 외부 준비 PC에서 JSON을 작성하고 폐쇄망에 반입해 시험·별도 승인·적용·되돌리기를 수행한다. [r1 → r2 → 복구 실습과 파일](OFFLINE-CONTENT-GUIDE.md)을 따른다.
- **조사 안내·참고 보기 → 조사 안내**: 같은 조사 안에서 IP·탐지·시간 범위에 맞는 사실과 미확인 자료를 읽고, 실제 확인 기록을 종결과 Experience에 재사용한다. [화면과 사례 A 사용법](GUIDANCE-GOLDEN-GUIDE.md)을 따른다.
- **SOC 지식 → SOC 경험 → 정답 사례 보기**: 다른 검토자가 채택한 버전을 입력·정답으로 나누어 내보낸다. 모델 훈련은 실행하지 않는다.
- 새 기능은 스키마 0013이 필요하며 기존 10/12 설치 ZIP에는 미포함이다. [최신 검증 범위와 남은 환경 조건](GUIDANCE-CONTENT-VALIDATION-2026-10-15.md)을 먼저 확인한다.

**SAW (SOC Analysis Workbench)** — 보안관제 분석가가 로그·패킷·IOC를 "이야기(Story) → 근거(Evidence) → 원본(Raw)" 순서로 분석하도록 돕는 분석 도구입니다.

> SAW는 **분석을 돕는 도구**입니다. 자동 차단, 방화벽 정책 변경, 탐지 룰 배포는 하지 않습니다. 최종 판단과 대응은 항상 사람이 합니다.

## 1. 시작하기 — 접속과 로그인

### 1.1 접속 주소

| 환경 | 주소 |
|---|---|
| 개발/데모 (로컬) | http://localhost:5180 |

### 1.2 처음 로그인 (MFA 등록)

SAW는 **비밀번호 + 일회용 코드(MFA)** 두 단계로 로그인합니다. 처음 로그인할 때 한 번만 인증 앱을 등록하면 됩니다.

1. **사용자 ID**와 **비밀번호**를 입력하고 `로그인`을 누릅니다.
2. **"MFA 등록 (TOTP)"** 화면과 QR 코드가 나타납니다.
3. 휴대폰 인증 앱(Google Authenticator, Microsoft Authenticator 등)을 열고 **QR 코드를 스캔**합니다.
   - QR 스캔이 안 되면 앱에서 "키 직접 입력"을 고르고 화면 아래의 키(4자리씩 끊어진 영문·숫자)를 입력합니다.
4. 앱에 표시된 **6자리 숫자**를 입력하고 `확인`을 누릅니다.
5. Home 화면이 나오면 로그인 완료입니다.

### 1.3 두 번째 로그인부터

비밀번호를 입력한 뒤 인증 앱의 **SAW 6자리 코드**만 입력하면 됩니다. 코드는 30초마다 바뀝니다.

### 1.4 로그인 문제 해결

| 증상 | 해결 |
|---|---|
| 6자리 코드가 계속 틀리다고 나옴 | 휴대폰 시간이 **자동 설정**인지 확인하세요. 시간이 1분 이상 틀리면 코드가 맞지 않습니다. |
| 휴대폰을 바꿨거나 인증 앱을 지웠음 | 관리자에게 **MFA 재설정**을 요청하세요. 다음 로그인 때 QR 등록 화면이 다시 나옵니다. |
| 비밀번호를 5번 틀려 잠김 | 일정 시간 후 다시 시도하거나 관리자에게 문의하세요. |
| 6자리 코드를 5번 틀려 잠김 | 비밀번호와 같습니다. 15분 뒤 비밀번호부터 다시 로그인하세요. |
| "이미 사용한 인증 코드"라고 나옴 | 한 번 쓴 코드는 다시 쓸 수 없습니다(다른 사람이 엿본 코드로 로그인하는 것을 막기 위함). 인증 앱에 **새 코드**가 나오면(최대 30초) 그 코드를 입력하세요. |
| 비밀번호를 잊어버림 | 관리자에게 **임시 비밀번호**를 요청하고, 로그인 후 바로 변경하세요. |
| 30분 동안 아무것도 안 했더니 로그인 화면으로 돌아감 | 보안을 위해 30분간 사용이 없으면 자동 로그아웃됩니다. 다시 로그인하세요. |

### 1.5 비밀번호 변경

화면 오른쪽 위 **비밀번호** 버튼 → 현재 비밀번호와 새 비밀번호(12자 이상, 대·소문자·숫자·특수문자 중 3종류 이상)를 입력합니다.
변경하면 **다른 PC에 로그인된 세션은 모두 종료**됩니다. 처음 받은 임시 비밀번호는 첫 로그인 직후 바로 바꾸세요.

### 1.6 로그아웃

화면 오른쪽 위 **로그아웃** 버튼을 누릅니다. 공용 PC에서는 반드시 로그아웃하세요.

## 2. 계정과 권한

SAW는 **역할(Role)** 별로 할 수 있는 일이 다릅니다. 특히 **관리자(admin)는 분석 화면을 볼 수 없습니다.** 시스템 관리와 사건 분석을 분리하기 위한 보안 설계입니다.

| 역할 | 할 수 있는 일 | 할 수 없는 일 |
|---|---|---|
| **분석가** (analyst) | 사건 생성·분석·종결, 파일 업로드, 빠른 분석, Experience 초안 작성, 탐지 룰 작성 | Experience·탐지 룰 승인, 마스킹 해제 |
| **선임 분석가** (senior_analyst) | 분석가 기능 + **승인**(Experience, 탐지 룰), 자산 정보 편집, 마스킹 해제, 전체 범위 헌팅 | — |
| **관제 매니저** (soc_manager) | 선임 분석가 기능 + **모든 사건 조회**, 감사 로그 확인 | — |
| **조회자** (viewer) | 사건·케이스·지식 **읽기만** | 생성·수정 |
| **관리자** (admin) | 사용자 생성, **MFA 재설정**, 커넥터 설정, 감사 로그 | **사건 분석 전부** |

### 2.1 개발/데모용 계정

| 계정 | 역할 |
|---|---|
| `analyst` | 분석가 |
| `senior` | 선임 분석가 |
| `manager` | 관제 매니저 |
| `admin` | 관리자 |

비밀번호는 서버 폴더의 `var/dev-credentials.json` 파일에 있습니다(외부 공유 금지). SAW 폴더에서 아래 명령으로 확인할 수 있습니다. `analyst` 부분을 다른 계정 이름으로 바꾸면 됩니다.

```bash
python -c "import json;print(json.load(open('var/dev-credentials.json'))['analyst']['password'])"
```

### 2.2 4-eyes(두 사람 확인) 원칙

지식(SOC Experience)과 탐지 룰은 **작성한 사람이 아닌 다른 사람**(선임 분석가 이상)이 승인해야 반영됩니다. 혼자서 작성과 승인을 모두 할 수 없습니다.

| 왼쪽 메뉴 | 용도 |
|---|---|
| **홈** | 붙여넣기 분석, 파일로 새 조사 시작, 최근 조사·탐지 |
| **빠른 분석** | 붙여넣기 · IOC · HTTP 요청 · 페이로드 디코딩 · 로그 · 요청 비교 |
| **조사 목록** | 조사(사건) 목록과 새 조사 만들기 |
| **작업 상태** | 업로드 파일 처리 진행 상황 |
| **위협 헌팅** | 가설 기반 헌팅 |
| **케이스** | 보고·인계용 정리 |
| **SOC 지식** | 승인된 대응 경험, 승인 대기열, 자산 정보 |
| **탐지 룰** | Sigma 룰 작성·시험·승인, ATT&CK 커버리지 |
| **관리·감사** | 관리자·매니저 전용 |

왼쪽 아래 버튼: 🔑 **비밀번호 변경**, ◐ **밝은/어두운 화면**, **KST/UTC** 시간대 전환, ⏻ **로그아웃**.
메뉴 위쪽 화살표로 **메뉴를 접을 수** 있습니다. 조사 작업대에서는 화면을 넓게 쓰도록 자동으로 접힙니다(펼치면 그 설정을 기억합니다).

상단의 **검색**(Ctrl+K)으로 메뉴·조사를 이름으로 바로 찾습니다. 열어 본 조사는 상단에 **탭**으로 남아 여러 조사를 오갈 수 있습니다.

### 근거 유형 배지

SAW는 모든 내용에 **어떤 종류의 근거인지** 배지를 붙입니다.

| 배지 | 뜻 | 예 |
|---|---|---|
| **관측** (초록) | 증거에 있는 그대로의 사실 | 원본 로그 줄, 패킷, 필드 값 |
| **계산** (파랑) | 관측값에 대한 결정적 계산 | 건수, 비율, 기준선 대비 배수, 엔트로피, 해시 |
| **추론** (노랑) | 가설·해석 | "Potential …" 탐지, ATT&CK 매핑, 스토리 연결, AI 문장 |
| **판정** (보라) | 사람의 판단 | 분석가 피드백, 조사 종결 |

배지에 마우스를 올리면 설명이 나옵니다. **추론은 반드시 관측·계산 근거와 대조해 판단**하세요.

## 4. Home — 붙여넣기와 파일 업로드

### 4.1 무엇이든 붙여넣기

Home 가운데 입력창에 **로그, IOC 목록, HTTP 요청, 인코딩된 문자열** 등 무엇이든 붙여넣으면 SAW가 종류를 자동으로 판별합니다.

1. 입력창에 텍스트를 붙여넣습니다. 아래 **"감지(미리보기)"**에 판별 결과가 바로 표시됩니다.
2. 드롭다운에서 대상을 고릅니다.
   - **새 분석 (저장 안 함)**: 결과만 보고 저장하지 않음
   - **INV-…에 추가**: 기존 사건에 기록
3. `Analyze` 버튼 또는 **Ctrl+Enter**.

> `hxxp://`, `example[.]com` 같은 **defang 표기**도 자동으로 인식합니다.

### 4.2 파일 업로드

1. **Upload Files** 버튼을 누르거나, 파일을 입력창에 **끌어다 놓습니다**.
   Quick 버튼(Web Logs, WAF Logs, PCAP, IOC List, Security Logs)을 누르면 종류가 미리 선택됩니다.
2. **종류**를 고릅니다. 모르면 `자동 감지`.
   - 지원 종류: Web Logs, WAF Logs, PCAP, IOC List, Security Logs, Firewall Logs, DB Audit
3. **Investigation**을 고릅니다.
   - `＋ 새 조사`: 새 사건 생성 (제목 입력 가능)
   - 기존 사건 선택: 그 사건에 증거 추가
4. 업로드가 끝나면 **Job 화면**으로 이동해 처리 단계(파싱 → 정규화 → 탐지 → 스토리 생성)를 보여줍니다.
5. 완료되면 사건 작업대에서 결과를 확인합니다.

> **한 번에 한 종류**씩 올립니다. 웹 로그·WAF·PCAP를 함께 분석하려면 첫 파일로 사건을 만들고, 나머지는 같은 사건에 추가하세요.
> 압축 파일(.gz, .zip)은 그대로 올리면 됩니다. 업로드된 파일은 **신뢰할 수 없는 데이터**로 취급되어 실행되지 않습니다.

#### TXT / CSV 파일 자동 감지

| 파일 | 자동 처리 |
|---|---|
| **NDR 메타 검색 결과 CSV** (`flow time,source ipaddr,…,meta data`) | HTTP 요청·응답을 짝지어 웹 이벤트(메소드·호스트·경로·UA·응답코드)로, traffic 행은 네트워크 연결로 변환. **쿠키 값은 저장하지 않고 이름만** 남김 |
| **일반 CSV** (방화벽·IPS·SIEM 내보내기, 엑셀 저장본) | 열 이름으로 필드 매핑. 영문(`Source IP`, `src_ip`, `destination port` …)과 한글(`출발지 IP`, `목적지포트`, `발생시간`, `송신바이트`, `탐지명` …) 모두 인식 |
| 열 구성에 따른 분석 | URL/메소드 열이 있으면 **웹**(탐지명·조치 열이 있으면 **WAF**), 출발지·목적지 IP와 포트/바이트가 있으면 **네트워크 연결**로 분석. 그 외는 일반 로그(패턴 묶기) |

- 인코딩: UTF-8(BOM 포함)과 **CP949(엑셀 한글 저장)** 자동 판별
- 시간 형식: `2026-10-03 17:38:47`, `2026/10/03 17:38:47`, `2026.10.3. 오후 5:38:47`, `20261003173847`, `+0900` 등. 시간대 표기가 없으면 조사 기본 시간대(KST)로 해석
- 끝에 빈 칸(,,,)이 붙은 행, 마지막 열의 쉼표도 허용
- 따옴표 안에 줄바꿈이 있는 행(메시지 칸에 여러 줄이 든 SIEM·엑셀 내보내기)은 한 행으로 합쳐 처리(한 행 최대 64줄)
- 작업 화면의 **처리 범위** 표에서 파일의 모든 줄이 이벤트·이어진 줄·머리글/합쳐진 줄·빈 줄·실패 중 어디로 갔는지와 **분석 비율**을 확인할 수 있습니다. 실패한 줄은 바로 아래 표본(민감정보 가림)에서 원인을 봅니다.
- 처리 중 PC가 재부팅되면 작업이 이어서 진행됩니다. 이어 붙이는 지점이 맞는지(파서 버전·마지막 이벤트) 확인하고, 다르면 그 파일을 처음부터 다시 처리합니다.
- 형식을 확신하지 못하면 작업 화면에서 **파서 선택**을 요청합니다. 목록에서 맞는 형식을 고르면 이어서 처리합니다.

#### 파서 직접 만들기 (메뉴 **지식·탐지 → 파서 관리**)

자동 감지가 안 되는 장비 로그는 분석가가 형식을 직접 정의합니다. 코드는 실행하지 않고 설정으로만 해석합니다.

1. **샘플**: 로그 몇 줄을 붙여넣거나 파일에서 불러옵니다. 작업 화면의 **새 파서 만들기**로 오면 올린 파일의 앞부분이 자동으로 채워집니다.
2. **자동 제안**: 형식(구분자·정규식·키=값·JSON), 구분자, 머리글, 필드 연결, 펼칠 칸(`a=1;b=2`처럼 한 칸에 여러 값), 민감 열(쿠키 등)을 추천합니다.
3. **필드 연결**: 원본 열마다 표준 필드(시간, 출발지 IP, URL …)를 고르고, **저장 안 함**·**가림**을 지정합니다. 시간 형식(예: `%Y%m%d%H%M%S`)과 시간대도 정할 수 있습니다.
4. **자동 감지 조건**: 첫 줄에 들어 있어야 할 머리글 단어나 줄 정규식. 비워 두면 작업 화면에서 직접 고를 때만 쓰입니다.
5. **미리보기**로 해석 결과와 실패 줄을 확인하고 **저장**합니다. 저장한 파서는 **내 초안**(새 버전)이 됩니다.
6. **공용 요청** → 다른 분석가(선임·매니저)가 **승인**하면 공용 파서가 되어 모두의 자동 감지에 쓰입니다. 작성자는 자기 파서를 승인할 수 없고, 반려되면 사유와 함께 초안으로 돌아옵니다.

| 상태 | 누가 쓰나 | 자동 감지 |
|---|---|---|
| 내 초안 · 승인 대기 | 작성자만 (작업 화면에서 직접 선택) | 안 함 |
| 공용 · 사용 중 | 모든 분석가 | 함 (감지 조건이 있을 때) |
| 꺼짐 | 아무도 | 안 함 (선임·매니저가 끄고 켬) |

- 작업 화면에서 **다른 파서로 다시 처리**를 고르면 기존 이벤트를 지우고 새 파서로 다시 만듭니다.
- **내보내기/가져오기**로 파서를 파일 하나로 다른 분석 PC에 옮길 수 있습니다(감사 기록).
- 정규식은 줄마다 0.05초 제한이 있어, 잘못 만든 정규식이 작업을 멈추지 않습니다.

#### 처리 기록 (메뉴 **분석 → 처리 기록**)

증거를 처리할 때마다 **처리한 사람, 입력 파일 지문(SHA-256), 사용한 파서·버전, 설정 지문, 결과 지문**이 자동으로 남습니다. 로그 내용은 담지 않으며, 같은 내용이 감사 로그(해시 체인)에도 기록됩니다.

- **분석가**: 내가 참여한 조사의 처리 기록. **검증**을 누르면 지문을 다시 계산하고 감사 로그 사본과 비교해 기록이 바뀌지 않았는지 확인합니다.
- **관제 매니저**: **통합 보기** — 분석가별·파서별 처리 현황과 경고(**같은 입력 파일을 서로 다른 설정으로 처리**, **초안 파서로 처리**, **기간 중 파서 정의가 바뀜**).
- **관리자**: 통합 보기를 볼 수 있지만 **파일 이름·조사 제목·설정 내용은 보이지 않습니다**(업무 분리 — 관리자는 사건 내용을 보지 않음).

## 5. Investigation 작업대 — 사건 분석

사건을 열면 3단 화면이 나옵니다.

```
┌──────────────┬─────────────────────────────────────┬──────────────────┐
│ 왼쪽          │ 가운데: 탭                           │ 오른쪽            │
│ · Evidence   │ Overview│Findings│Attack Story│...  │ Context 패널      │
│ · 데이터소스  │                                     │ · 자산 정보        │
│ · 필드 facet │                                     │ · 유사 사건        │
│   (I / E)    │                                     │ · SOC Experience  │
│              │                                     │ · SOC Assistant   │
└──────────────┴─────────────────────────────────────┴──────────────────┘
```

### 5.1 왼쪽 — 증거와 필터

- **Evidence**: 이 사건에 올라온 파일 목록과 처리 상태(✓ 완료, … 처리 중)
- **데이터 소스 / 필드 값 목록**: 값 옆 버튼
  - `I` (Include): 이 값만 보기
  - `E` (Exclude): 이 값 빼고 보기
- 적용된 필터는 위쪽에 **태그**로 표시되고, 태그를 클릭하면 해제됩니다. 모든 탭에 같은 필터가 적용됩니다.

### 5.2 가운데 — 분석 탭

**권장 순서: 공격 스토리 → 탐지 결과 → 원본 로그** (이야기 → 근거 → 원본)

| 탭 | 내용 |
|---|---|
| **개요** | 조사 요약, 위험도, 시간 범위, **상관 분석**(같은 IP가 웹·WAF·네트워크에 동시에 나타나는 경우 등) |
| **탐지 결과** | 탐지 목록. 각 항목에 **근거 지표**(요청 수, 비율, 기준선 대비 배수 등), 신뢰도, **확인·대응 권고** |
| **공격 스토리** | 탐지 결과를 공격 단계(정찰 → 침투 → 유입 → 데이터 접근 → 외부 유출 등)로 연결한 흐름도 |
| **타임라인** | 시간순 이벤트 |
| **관계 그래프** | IP·도메인·사용자 간 관계. 클라우드/ASN/국가별로 묶어 보기 가능 |
| **HTTP** | 웹 요청 분석 (URI 패턴, 파라미터, 상태 코드) |
| **PCAP 포렌식** | PCAP 증거의 요약 판단, 추출 파일, 평문 인증, 캡처 정보, 보고서 (**PCAP 증거가 있을 때 활성화**, 5.4절) |
| **DNS / TLS / 연결** | 네트워크 분석 (**PCAP 또는 네트워크 로그가 있을 때 활성화**) |
| **ATT&CK** | 근거가 있는 MITRE ATT&CK 기법만 매트릭스로 표시 (공식 Enterprise 19.2 카탈로그), Navigator 레이어 내보내기 |
| **원본 로그** | 원본 로그 라인 (`.` 키) |
| **메모** | 분석 메모 |

#### Findings 읽는 법

탐지 결과는 단정하지 않고 **"Possible(가능성 있음)" / "Potential(잠재적)"**로 표현하며, 항상 근거 숫자를 함께 보여줍니다.

예시 — `F-1001 Possible API Enumeration` (API 순차 조회 의심)

| 지표 | 값 | 의미 |
|---|---|---|
| Requests | 1,200 | 요청 수 |
| Unique objects | 1,200 | 모두 다른 고객 ID 조회 |
| Sequential ratio | 1.0 | ID가 100% 순서대로 증가 |
| HTTP 2xx ratio | 92% | 대부분 **성공** 응답 |
| Source IPs | 43 | 여러 IP로 분산 |
| Request rate | 81.2/분 (기준선 18–32, **2.5배**) | 이 API의 평소 사용량보다 많음 |

위험도는 **행위 심각도 × 신뢰도 × 자산 중요도 × 성공 여부**로 계산되며, 각 요소가 함께 표시됩니다.

탐지 상세 화면의 **확인·대응 권고** 상자에는 다음에 확인할 일과 대응 방법이 정리되어 있습니다. SAW가 직접 차단하거나 설정을 바꾸지 않으며, **분석가가 판단해 수행**합니다. 판정은 아래 **분석가 판정** 버튼(유효 / 정상 활동 / 오탐 / 중복)으로 기록합니다.

#### 엔티티(IP·도메인 등) 클릭 메뉴

화면의 IP, 도메인, UA 등을 클릭하면 메뉴가 나옵니다.

- **＋ Filter include / － Filter exclude**: 필터 추가
- **⏱ Timeline**: 이 값의 시간 흐름
- **⛓ Graph focus**: 관계 그래프에서 이 값 중심으로 보기
- **ℹ Entity detail**: 상세 정보

#### 세션 PCAP 다운로드

PCAP에서 나온 네트워크 이벤트(Connections·DNS·TLS·HTTP)를 열면 이벤트 상세 창 위쪽에 **⬇ 세션 PCAP** 버튼이 있습니다.
그 연결의 원본 패킷만 잘라 `.pcap` 파일로 받아 Wireshark 등에서 열 수 있습니다. 다운로드는 감사 로그에 기록됩니다.
(Zeek/Suricata **로그**를 올린 경우에는 원본 패킷이 없어 받을 수 없습니다.)

같은 자리의 **⇄ 스트림 보기**는 그 연결에서 오간 내용을 클라이언트→서버 / 서버→클라이언트로 나눠 보여 줍니다(Wireshark의 "Follow TCP Stream"과 같은 기능). 텍스트는 비밀번호·토큰 등을 가려서 보여 주고, 바이너리는 16진수로 표시합니다. 열람은 감사 로그에 기록됩니다.

> 복사하면 기본적으로 **defang** 형태(`1[.]2[.]3[.]4`)로 복사되어 실수로 접속하는 것을 막습니다.

### 5.3 오른쪽 — Context 패널

**내부 정보를 먼저** 보여줍니다. 외부 위협 정보보다 우리 조직의 맥락이 더 중요하기 때문입니다.

1. **자산 정보**: 대상 자산 정보 — 담당 부서, 데이터 등급(개인정보 등), 평소 요청량, 허용 국가, **배치 작업 일정**
   → "정기 배치 작업 아닌가?"를 바로 확인할 수 있습니다.
2. **유사 사례**: 과거 비슷한 조사와 그 판정 결과 (공통점·차이점 표시)
3. **우리 SOC 경험 (승인됨)**: 승인된 과거 대응 지식 (확인 절차, 대응 방법, 탐지 아이디어)
4. **SOC Assistant**: 탐지를 하나 선택하면 근거 요약·추가 확인·보고서 초안을 제공합니다. **판단은 분석가**가 합니다. `오프라인 템플릿 (LLM 아님)`과 실제 모델 초안을 구별하며 저장은 `노트로 저장`을 눌러야 합니다. [단계별 사용법과 화면](ASSISTANT-EVIDENCE-GUIDE.md).

### 5.4 PCAP 포렌식 탭

PCAP/PCAPNG 파일을 증거로 올리면 SAW가 패킷을 직접 분석합니다(별도 설치 프로그램 불필요).

**자동으로 하는 일**

- TCP 연결 재조립(순서 뒤바뀜·재전송·유실 처리), 중복 수집 프레임 제거
- 연결·DNS·HTTP·TLS(서버 이름, JA3/JA4 지문) 기록
- HTTP 본문 해석(chunked, gzip/deflate 압축 해제), 업로드(PUT·multipart) 구분
- **전송 파일 추출**: 실제 형식(매직 바이트), 크기, 엔트로피, MD5·SHA1·SHA256, 확장자와 실제 형식이 다른 **위장 파일** 표시
- FTP 데이터 연결에서 파일 이름 연결(RETR/STOR)
- **평문 인증**: FTP·POP3·IMAP·SMTP·HTTP Basic·로그인 폼. **비밀번호는 저장하지 않고** 길이와 취약 여부만 기록
- ARP(한 IP에 여러 MAC), IOC 목록 대조

**자동 탐지 항목**

| 분류 | 탐지 | ATT&CK |
|---|---|---|
| 웹 공격 | SQL 인젝션·XSS·경로 탐색·명령어 삽입·Log4Shell·Shellshock (응답에 성공 징후가 있으면 위험도 상승) | T1190, T1059 |
| 웹셸 | 서버 스크립트 업로드(PUT·multipart·Tomcat Manager) → 그 경로 사용 | T1505.003 |
| 악성코드 유입 | 실행 파일·위장 파일·스크립트·Flash/Java·고엔트로피 페이로드, **익스플로잇 킷 연쇄**(랜딩 → 익스플로잇 → 페이로드) | T1105, T1036.008, T1189, T1203 |
| 계정 공격 | 평문 프로토콜 무차별 대입(실패 후 성공 시 심각), 암호화 서비스 반복 연결, 취약/기본 비밀번호 로그인 성공 | T1110, T1078.001 |
| 정보 노출 | 평문 인증 정보 노출 | (위험 요소) |
| 중간자 | ARP 스푸핑 | T1557.002 |
| C2 | DGA(존재하지 않는 도메인 다발), IP 직접 HTTP 통신, 주기 통신·DNS 터널링·대용량 송신(기존 탐지) | T1568.002, T1071 |
| IOC | 조사에 올린 **IOC 목록**(IP·도메인·해시)과 일치 | — |

**화면 구성**

1. **요약 판단** 띠: "침해 정황 의심 / 의심 활동 있음 / 특이 징후 낮음" (자동 탐지 기준이며 최종 판단은 분석가)
2. **숫자 타일**: 심각·높음·보통 건수, 연결 수, 추출 파일(위장 의심 수), 평문 인증 건수 — 타일을 누르면 해당 화면으로 이동
3. 하위 탭
   - **요약**: 네트워크 탐지 목록, 시간대별 연결, 파일 유형, 상위 통신 IP
   - **추출 파일**: 위험 유형만/전체 보기, 해시(마우스를 올리면 MD5·SHA1·SHA256), 다운로드
   - **평문 인증**: 프로토콜·계정·성공/실패·취약 비밀번호 여부
   - **캡처 정보**: 패킷 수, 중복 제외 수, 기간, 서비스별 연결 수, 원본 SHA-256
4. **보고서 (HTML)**: 요약·탐지·위험 파일·평문 인증을 한 장으로 저장(인쇄해 PDF로 보관 가능). **탐지/파일/인증 CSV**도 받을 수 있습니다.

> **추출 파일 다운로드**는 조사 수정 권한이 필요하고 감사 로그에 남습니다. 실행 파일 등 위험 유형에는 `.infected` 확장자가 붙습니다. **분석 PC에서 실행하지 마세요.** 해시로 내부 위협 정보를 먼저 조회하세요.

**TLS 인증서 탭**: TLS 1.2 이하 세션의 서버 인증서(발급 대상·발급자·유효 기간·SHA-1 지문)를 목적지별로 보여줍니다. 외부 목적지에서 **자체 서명**, **요청한 서버 이름과 불일치**, **접속 시점에 만료/아직 유효하지 않음**, **발급 3일 이내 사용**, **약한 키(RSA 2048 미만)** 가 보이면 `Potential Suspicious TLS Certificate` 탐지를 만듭니다. TLS 1.3은 인증서가 암호화되어 보이지 않습니다.

**연결된 기록 (이벤트 상세 하단)**: NDR 메타·웹 로그·WAF·PCAP에 남은 **같은 세션**(같은 IP·포트 쌍, ±5분)과 **같은 요청**(포트가 없는 웹 로그는 같은 출발지·경로, ±5초)을 모아 보여줍니다. 같은 시간대의 PCAP이 조사에 있으면 **NDR·로그 이벤트에서도 바로 ⇄ 스트림 보기와 세션 PCAP 받기**가 됩니다.

**IOC 목록 활용**: 증거 종류 **IOC 목록**으로 텍스트 파일(한 줄에 하나, `1[.]2[.]3[.]4` 같은 무력화 표기 가능)을 올리면, 같은 조사의 로그·PCAP과 자동으로 대조해 **IOC Match** 탐지를 만듭니다. 해시는 추출 파일뿐 아니라 TLS 지문(JA3·JA3S, 인증서 SHA-1·SHA-256)과도 대조합니다.

## 6. Analyze — 빠른 분석 도구

사건을 만들지 않고 바로 확인할 때 씁니다. 상단 **Analyze** 메뉴에서 고릅니다.

| 도구 | 입력 | 결과 |
|---|---|---|
| **Universal** | 아무 텍스트 | 종류 자동 판별 후 맞는 분석기로 연결 |
| **IOC** | IP, 도메인, URL, 해시, 이메일 목록 | 국가·ASN·클라우드 여부 + **내부 로그에서 관측된 이력**(어느 사건에서 몇 건) |
| **HTTP** | HTTP 요청 원문 | 헤더·파라미터 분해, UA 분류(브라우저/스크립트/스캐너), 민감 헤더 마스킹 |
| **Payload** | 인코딩된 문자열 | URL/Base64/Hex 등 디코딩 단계 자동 탐색, SQLi·XSS·경로 조작 패턴 표시, CyberChef 레시피 |
| **Diff** | HTTP 요청 여러 개 | 요청 간 변화(파라미터 값, 인증 헤더 제거, 우회 헤더 추가 등) |
| **Log** | 로그 일부 | 로그 형식 자동 판별, 상위 IP, URI 패턴 |

> **외부 위협 정보 조회**(RDAP, TI)는 자동으로 하지 않습니다. 조회하면 공격자에게 노출될 수 있으므로(OPSEC) 분석가가 버튼을 눌러 명시적으로 실행하고, 정책이 허용할 때만 동작합니다.

## 7. 사건 종결과 지식화

### 7.1 사건 종결 (Close)

작업대 위쪽의 **Close Investigation** 버튼을 누르면 종결 창이 열립니다.

1. **Final Verdict(최종 판정)**: `Attack`(공격) / `Normal`(정상) / `False Positive`(오탐) / `Unknown`(판단 불가)
2. **Analyst Comment (필수)**: 판단 근거. 비워 두면 종결할 수 없습니다.
3. **Checks Performed**: 수행한 확인 항목 체크
4. **Response**: 사람이 수행한 대응 기록 (예: "WAF rate-limit 적용 요청")
5. **Detection Idea**: 이 사건으로 얻은 탐지 아이디어
6. **Save as SOC Experience**: 체크하면 지식 초안(Draft)이 만들어집니다.

### 7.2 SOC Experience 승인 흐름

```
분석가: 초안 작성(Draft) → 검토 요청(Submit → Review)
                               ↓
선임/매니저(다른 사람): 검토 → 승인(Approved) 또는 반려
                               ↓
          이후 비슷한 사건의 Context 패널에 자동 표시
```

- **Knowledge → Experience**: 전체 목록 (✎ 초안, ◐ 검토 중, ✔ 승인, ⊘ 폐기)
- **Knowledge → Review Queue**: 내가 승인해야 할 항목
- **Knowledge → Asset**: 자산 정보 관리 (선임 이상 편집)

## 8. Hunting — 위협 헌팅

탐지되지 않은 위협을 **가설 → 질의 → 결과 → Pivot → 다음 질의** 순서로 찾아갑니다.

1. **새 Hunt**: 가설 입력 (예: "API 서버 10.10.1.21이 외부로 주기적인 통신을 한다")
2. 범위 선택: 특정 사건 / 전체(선임 이상)
3. **Next Query**: 필터와 집계 필드를 지정하고 실행합니다. 각 질의마다 **"왜 이 질의를 하는지"**를 기록합니다.
4. **Results**: 결과 건수와 필드별 상위 값
5. **Pivot Candidates**: 다음에 파볼 만한 값(목적지 IP, TLS 지문 등)을 클릭하면 다음 질의에 추가됩니다.
6. 의미 있는 결과는 **Finding으로 승격**할 수 있습니다.
7. **Conclude**: 결론을 기록하고 마칩니다.

모든 질의는 **읽기 전용**이며, 과정 전체가 흐름도로 남습니다.

## 9. Detection — 탐지 룰 관리

탐지 룰을 **Sigma** 형식으로 작성하고 검증합니다.

```
초안(draft) → 테스트(test) → 승인(approved) → 배포 표시(deployed) → 폐기(deprecated)
```

1. **New detection**으로 Sigma YAML을 작성합니다.
2. **Historical Test 실행**: 저장된 과거 이벤트에 룰을 돌려 몇 건이 걸리는지 확인합니다.
3. **Approve**: 다른 사람(선임 이상)이 승인합니다. 테스트를 통과해야 합니다.
4. **Export**: OpenSearch 쿼리 등으로 내보냅니다.
5. **Coverage (ATT&CK)** 탭: 보유 룰이 ATT&CK 기법을 얼마나 커버하는지 확인하고 Navigator 레이어로 내보냅니다.

> SAW는 룰을 **직접 배포하지 않습니다.** 실제 SIEM 배포는 운영 절차에 따라 사람이 수행합니다.

## 14. 자주 묻는 질문 (FAQ)

**Q. admin으로 로그인했는데 사건이 안 보여요.**
A. 정상입니다. 관리자는 분석 권한이 없습니다. analyst, senior, manager 계정으로 로그인하세요.

**Q. DNS / TLS / Connections 탭이 회색으로 눌리지 않아요.**
A. 그 사건에 PCAP(네트워크) 증거가 없어서입니다. PCAP 또는 Zeek/Suricata 로그를 추가하세요.

**Q. 배지에 "추론"이라고 붙은 건 무슨 뜻인가요?**
A. 가설이라는 뜻입니다. "관측"(원본)과 "계산"(지표) 근거를 확인한 뒤 판단하세요. 3장 끝의 근거 유형 배지 표를 참고하세요.

**Q. PCAP 파일을 그대로 올려도 되나요?**
A. 네. PCAP/PCAPNG를 올리면 SAW 내장 분석기가 연결·DNS·HTTP·TLS를 추출해 분석합니다. 큰 파일은 처리에 시간이 걸리며 상단 ⏳ Jobs에서 진행 상황을 볼 수 있습니다.

**Q. 업로드했는데 결과가 안 나와요.**
A. 상단 **⏳ Jobs**에서 처리 상태를 확인하세요. 실패하면 Job 상세에 실패한 줄 예시가 나옵니다. 로그 형식을 인식하지 못했다면 종류를 직접 지정해 다시 올려 보세요.

**Q. 일부 값이 ●●●●로 가려져 있어요.**
A. 쿠키, 인증 토큰, 개인정보 등은 자동 마스킹됩니다. 원문 확인(마스킹 해제)은 이벤트 상세 창에서 **사유를 입력**해야 하며, 선임 분석가 이상만 가능하고 감사 로그에 남습니다.

**Q. "Possible", "Potential"이라고만 나오고 공격이라고 확정하지 않아요.**
A. 의도된 설계입니다. SAW는 근거를 보여주고, 공격 여부는 분석가가 판단해 종결 시 기록합니다.

**Q. SAW가 공격 IP를 자동으로 차단하나요?**
A. 아니요. SAW는 차단·정책 변경·룰 배포를 하지 않습니다. 대응은 사람이 수행하고 Response 항목에 기록합니다.

**Q. AI(✦) 결과를 그대로 믿어도 되나요?**
A. AI는 보조 도구입니다. ✦ 표시된 내용은 반드시 근거(Findings, Raw)와 대조해 확인하세요.

### 확인 기록 — "열어 봤다"와 "확인했다"를 구분

기록을 열어 보는 것만으로는 아무것도 남지 않습니다. 확인한 것이 있을 때 **✓ 확인 기록**을 누릅니다.

| 어디서 | 대상 |
|---|---|
| 이벤트 상세 › **확인** 탭 | 그 기록 한 줄, 그 기록의 출발지·목적지 IP, 도메인, 경로, 계정, 세션 |
| 원본 로그 › **✓ 검색 결과 확인 기록** | 지금 검색 결과 묶음 (일부만 봤으면 표본, 다 봤으면 전체) |
| 엔티티 탭, 탐지 상세 | 그 IP·도메인, 그 탐지 |

창에서 고르는 것:

1. **무엇을 확인했나** (하나 이상): 요청 성격(공격인가) / 성공 여부 / 피해 여부 / 정상 업무 여부
2. **판단** (선택): 정상 / 의심 / 악성 / 판단 불가. 아직 모르면 "판단 없음"으로 두면 확인한 사실만 남습니다. 정상·악성은 근거 한 줄이 필요합니다.
3. **범위**: 검색 결과는 "표본 N건"과 "전체"를 구분합니다. 표본 확인은 전체 확인으로 세지 않고, 보고용 요약의 유의할 점에 나옵니다.

예: "요청 성격 확인 — 악성" + "성공 여부 확인 — 판단 없음"을 따로 남기면, 공격 시도는 맞지만 성공은 아직 모른다는 뜻이 그대로 남습니다.

표에 붙는 표시:

- `✓악성`, `✓정상`, `✓확인` : 그 기록을 직접 확인한 것
- `↑정상` (점선) : 그 기록의 **주소·이름**에 대한 확인. 이 기록 자체를 판단한 것은 아니므로 참고만 하세요.
- `·표본` : 일부만 본 확인

고치기와 취소: **판단 변경**은 작성자만 할 수 있고 이전 기록은 "이전 기록"으로 남습니다. 다른 사람은 자기 확인 기록을 따로 남깁니다(의견이 달라도 둘 다 보존). **내 표시 취소**는 이유와 함께 "취소됨"으로 남습니다.

확인 표시는 탐지를 지우거나 다음 탐지를 막지 않습니다.

### 팀 확인 정보 — 다른 조사의 확인 결과를 참고

IP·도메인 등에 대한 확인을 남길 때 **다른 조사에도 공유**를 고르면, 다른 사람의 조사에 같은 대상이 나올 때 참고로 표시됩니다. 공유할 때는 나눠 적습니다.

- 확인한 사실 (예: 정산 배치 서버로 사용됨)
- 확인한 범위 (예: 02~03시, 고객 조회 API 호출)
- 확인하지 않은 범위 (예: 그 밖의 시간·목적지)

보는 쪽에는 이벤트 상세의 확인 탭, 엔티티 탭, 오른쪽 패널에 **팀 확인 정보 N건**이 나옵니다.

| 항목 | 뜻 |
|---|---|
| 이번 조사와 다른 점 | 시간대·상대 주소·포트·경로가 확인 때와 **같음 / 다름 / 비교 불가**. 비교할 정보가 없으면 "같음"이 아니라 "비교 불가"입니다. |
| 미검토 참고 / 재확인 필요 / 오래된 확인 | 공유 결과의 상태. 정상 확인은 90일, 악성 확인은 180일이 지나면 "오래된 확인"이 됩니다. |
| 확인 1건 · 인용 N회 | 한 사람의 확인을 여러 조사가 인용해도 독립된 확인 여러 건으로 세지 않습니다. |

할 수 있는 일:

- **현재 기록과 비교**: 공유된 근거 기록만 가린 상태로 봅니다(그 조사 전체는 열리지 않으며, 열람은 감사 로그에 남습니다).
- **내 조사에 근거로 연결**: 내 조사에 "다른 조사 참고"로 기록됩니다. 내가 직접 확인한 것으로 세지 않고, 내 조사의 판단을 정하지도 않습니다. 오래됐거나 재확인이 필요한 확인은 연결할 수 없습니다.
- **재확인 요청**: 이유를 적으면 작성자의 홈 화면에 알림이 갑니다.

공유한 확인을 고치거나 취소하면, 그것을 근거로 연결한 조사에 "참고한 확인이 바뀜 / 철회됨"이 표시되고 그 조사 담당자의 홈 화면에 알림이 갑니다. 보고용 요약의 유의할 점에도 나옵니다.

조사 작업대의 **확인·검토** 탭에 세 가지가 모여 있습니다: 중요한 판단의 검토, 분석 지원, 확인 기록 전체.

### 검토 요청 — 중요한 결론만 다른 사람이 본다

모든 조사, 모든 기록에 승인을 받지 않습니다. 아래 두 경우에만 자동으로 **검토 대상**이 됩니다.

| 경우 | 왜 |
|---|---|
| 위험도 높음·매우 높음 탐지를 **정상 활동·오탐**으로 평가 | 위험을 낮추는 판단이 틀리면 놓치게 됨 |
| 조사를 **공격**으로 종결 | 결론이 보고에 쓰임 |

- 검토 대상이 되어도 **일은 막히지 않습니다**(급한 대응이 서명을 기다리지 않도록). 대신 검토가 끝날 때까지 확인·검토 탭, 현황판의 "검토 대기", 보고용 요약의 유의할 점에 계속 표시됩니다.
- **검토자 지정해 요청**: 결론 한 줄과 확인한 범위를 적고 검토자를 고릅니다. 자신은 고를 수 없습니다. 검토자에게는 그 조사의 읽기 권한이 주어지고, 자료의 한계(빠진 자료, 표본 확인 등)가 자동으로 함께 전달됩니다.
- 그 밖의 판단도 **검토 요청** 단추로 자유롭게 요청할 수 있습니다.
- 검토자는 홈 화면의 "검토 요청받은 것"에서 답합니다: `근거가 결론을 지지함 / 결론 범위가 너무 넓음 / 자료 부족 / 보완 요청` 중 하나와, **어떤 근거를 확인했고 어디까지 동의하는지 한 줄**(필수).
- 승인은 **그때의 결론**에 대한 것입니다. 승인 뒤에 평가나 판정이 바뀌면 "결론이 바뀜 — 다시 검토 필요"로 표시되고 승인으로 세지 않습니다.
- 규칙으로 생긴 검토 대상은 요청을 취소해도 사라지지 않고 "검토자 지정 필요"로 돌아갑니다. 판단을 되돌리면(예: 다시 '유효'로 평가) 대상에서 빠집니다.

### 분석 지원 — 예외적으로, 질문 하나를 맡긴다

기본은 한 사람이 한 조사를 맡습니다. 급하거나 복잡해서 **따로 떼어 동시에 확인할 수 있는 질문**이 있을 때만 지원을 요청합니다(예: "응답·패킷에서 실행 성공 여부 확인"). 기록이 많다는 이유만으로는 요청하지 않습니다.

- 요청은 조사 담당자나 관제 매니저만 할 수 있습니다. 지원자에게 그 조사의 편집 권한이 주어집니다.
- 지원자는 홈 화면의 "지원 요청받은 것"에서 **맡아서 진행 / 완료 보고 / 맡을 수 없음**을 고릅니다. 완료 보고에는 결과 한 줄이 필요하고, 확인하지 못한 것을 따로 적을 수 있습니다. 확인한 내용은 조사 안에 확인 기록으로 남깁니다(지원자 이름으로).
- 조사 담당과 결론은 담당자에게 그대로 남습니다. **지원자는 그 조사의 결론을 검토할 수 없습니다**(분석에 참여한 사람은 독립된 검토자가 아니므로).

### 종결 전 점검 — 다섯 가지만

**조사 종결**을 누르면 먼저 다섯 가지를 보여 줍니다. 열려 있는 것이 있어도 종결은 막지 않습니다.

1. 조사 범위와 확인하지 못한 영역 (빠진 자료, 표본만 본 확인, 직접 확인 기록 없음)
2. 핵심 탐지 평가와 서로 다른 판단 (평가 안 한 높은 위험 탐지, 같은 대상·같은 질문에 정상과 악성이 함께 있음)
3. 시도 · 성공 · 피해 구분 (성공 여부·피해 여부를 확인한 기록이 있는가)
4. 조치와 남은 일 (처리 중인 작업, 끝나지 않은 지원 요청)
5. 검토와 보고 내용 (끝나지 않은 검토)

확인하지 못하고 닫는 것은 **범위 제한** 칸에 적습니다. 적은 내용은 보고용 요약의 유의할 점에 "종결할 때 남긴 범위 제한"으로 나옵니다. 자료를 확보할 수 없을 때는 판정을 **판단 보류**로 두면 됩니다("영향 없음"으로 바꾸지 마세요).

## 부록: 기본 탐지 묶음 — 알려진 흔적과 공격 흐름 (2026-10-11 추가)

행동을 세어 보는 탐지(대량 조회, 로그인 반복 등) 외에, **한 요청만 봐도 알 수 있는 알려진 흔적** 166종과 **탐지가 순서대로 이어지는 공격 흐름** 8종이 기본으로 들어 있습니다. 웹 서버 로그, WAF 로그, NDR 요청 기록, 패킷 속 HTTP에 똑같이 적용됩니다.

| 묶음 | 무엇을 찾나 | 예 |
|---|---|---|
| 공격·취약점 점검 도구 | 도구가 스스로 밝힌 이름 | sqlmap, Nikto, Nuclei, WPScan, AntSword |
| 인터넷 수집 서비스 | 인터넷 전체를 훑는 서비스 | Censys, Shodan |
| 공개 취약점 공격 | 널리 쓰인 원격 실행 취약점의 경로·구문 | Log4Shell, Spring4Shell, Struts, Exchange, Citrix, F5, Fortinet, Ivanti, vCenter, WebLogic, Confluence |
| 운영체제 명령 | 요청에 담긴 명령 | wget·curl로 받아 실행, 역방향 접속, 인코딩된 PowerShell, 채굴 프로그램 |

| 정보 노출 | 설정·저장소·백업·디버그 화면 | /.env, /.git/config, /actuator/env, backup.zip |
| 값 조작 | SQL 주입·XSS 외의 주입 | NoSQL, LDAP, 응답 분할, 프로토타입 오염 |
| CMS 취약점 | 워드프레스·Joomla 등 | File Manager 올리기, 설정 노출 |

탐지 목록에 나오는 방식:

- **성공 응답(2xx)을 받은 것은 규칙마다 따로** 나오고 제목에 "성공 응답 있음"이 붙습니다. 위험도가 더 높습니다.
- **모두 거부된 시도는 묶음당 한 줄**로 접힙니다. 스캐너가 수백 개 경로를 두드려도 "정보 노출 경로 접근 12종 (성공 응답 없음)" 한 줄입니다.
- 백업 파일 내려받기처럼 성공했을 때만 의미가 있는 규칙은 성공 응답이 있을 때만 나옵니다.
- 2xx는 요청이 받아들여졌다는 뜻이지 공격 성공의 확정은 아닙니다. 각 탐지의 "확인·대응 권고"를 따라 확인하세요.

**공격 흐름**은 같은 IP의 탐지들이 단계 순서대로 이어질 때 하나로 묶어 보여 줍니다(예: 탐색 → 취약점 공격 → 웹셸). 묶인 탐지는 그대로 남고, 흐름은 "이어서 보라"는 안내입니다.

알아 둘 점:

- 규칙은 **증거를 처리할 때** 적용됩니다. 묶음이 들어오기 전에 처리한 조사는 증거를 다시 처리해야 반영됩니다.
- 우리 환경의 정상 경로와 겹쳐 시끄러운 규칙은 선임 분석가·관제 매니저가 끌 수 있습니다(이유 필수, 감사 기록). 끈 뒤 다시 분석하면 그 규칙의 탐지가 빠지고, 켜고 다시 분석하면 돌아옵니다. **탐지 룰 → 기본 탐지 목록**에서 켜고 끄며, 끄는 이유는 5자 이상 적습니다.
- 규칙을 더하려면 `saw/detectors/packs/web_signatures.yaml`에 한 항목을 추가합니다. 형식 설명은 그 파일 맨 위에 있고, 일치해야 하는 예(`examples`)와 걸리면 안 되는 예(`benign`)를 반드시 같이 적습니다. 예가 맞지 않으면 자동 시험이 실패해 잘못된 규칙이 배포되지 않습니다.

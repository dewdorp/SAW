# 오프라인 매체 실제 검증 기록 — 2026-10-12

이 기록은 새 복사본의 격리된 가상 데이터 시험입니다. 원본 `F:\claude\saw`와 실제 은행 자료는 사용하지 않았습니다. 개발 PC는 Windows 11 Pro build 26200, RAM 31.7GB이며 대상 LTSC 2019와 다릅니다.

## 매체·설치

- 고정 공개 입력: Python 3.12.10 embeddable, 62개 wheel, PostgreSQL 16.15-1, OpenSearch/nori 2.19.6, 번들 JDK 21.0.11+10, WinSW 2.12.0.
- drain3 0.9.11은 빌드 PC의 격리된 Python에서 공식 해시 확인 sdist를 wheel로 만들었습니다. 대상 PC에 소스 컴파일을 요구하지 않습니다.
- Python 의존성 전체를 새 embeddable 런타임에 `--no-index --no-cache-dir`로 실제 설치했고 `pip check`가 통과했습니다.
- 정적 llama.cpp 실행기와 고지를 포함합니다. MSVC 개발 PC의 DLL을 별도로 수집하지 않습니다. 모델 가중치는 제외합니다.
- 전체 manifest 검사, 필수 파일 누락·변조·추가 파일·경로 별칭·모델/운영 상태 제외 시험을 수행했습니다.

## 세 번째 설치와 저장 보존

새 경로 `installed-3`에서 실제 매체만 사용한 설치가 종료 코드 0으로 끝났습니다. 필수 파일 518개, 총 1,489,242,733바이트의 시험 매체를 먼저 검증했습니다. 대상에 미리 설치된 Python/Node/Git에 의존하거나 소스를 컴파일하지 않았으며 Python 3.12.10과 62개 wheel, PostgreSQL, OpenSearch/nori, UI를 매체에서 설치했습니다.

- HTTPS 인증서 검증을 끄지 않고 자체 CA 신뢰 체인과 localhost SAN을 확인했습니다.
- 새 합성 `claude-check` 계정의 MFA와 6줄 로그·HTTP PCAP 업로드/분석을 실제 실행했습니다. 두 작업이 완료되어 9개 이벤트, 8개 Finding과 노트 1개를 저장했습니다.
- 설치된 제어기로 API·OpenSearch·PostgreSQL을 종료하고 다시 기동했습니다. 이후 이벤트 9개, Finding 8개, 같은 노트가 유지됨을 확인했습니다.
- 로그아웃 뒤 인증 API가 401을 반환했고 합성 점검 계정은 비활성화했습니다.
- 모든 검증을 마친 뒤 이 설치의 사용자 프로세스만 종료했습니다. 시험 포트 58443/55432/59200/59300의 LISTEN 상태가 없음을 확인했습니다.

설치 로그와 검증 보조 도구는 로컬 QA 영역에 보존합니다. 운영 정보 없는 공개 결과는 [검증 JSON](verification/offline-release-2026-10-12.json)에 있습니다. 시험 매체 manifest SHA256은 `0881f1710f1c44b33e88551b98d6da6def9ea8db10abfb77f7bb415208981588`입니다. 이는 세 번째 시험 이력이며 최종 배포의 payload 동등 비교 기준은 아래 네 번째 매체입니다.

## 실제 합성 백업과 별도 복원

설치된 `backup.ps1`을 실제 실행했습니다. PostgreSQL custom dump 104,923바이트의 `pg_restore --list` 확인 및 별도 신규 DB 복원이 성공했습니다. 조사 1개, 증거 2개, Finding 8개, 노트 1개, 작업 2개의 집계가 원본과 일치했습니다. OpenSearch snapshot은 `SUCCESS`였으며 새 이름의 5개 색인에 9개 이벤트를 복원했습니다. 증거 파일 6개는 원본과 백업의 SHA256이 같았습니다.

복원 검증 도구가 처음에는 OpenSearch의 기본 alias 복원을 허용하여 새 색인이 원본 `saw-events` alias에도 잡혔습니다. 이 상태를 격리 복원 성공으로 세지 않았습니다. 새로 만든 복원 색인의 alias만 해제한 뒤 원본 alias 경유 9건, 별도 복원 색인 9건, 공유 alias 0개를 다시 확인했습니다. 원본 색인과 원본 alias는 삭제하지 않았습니다.

별도 이름으로 시험 복원할 때는 요청에 `include_aliases: false`와 `include_global_state: false`를 명시해야 합니다. 이번 검증은 합성 자료를 별도 DB/색인으로 복원한 개발기 시험이며 운영 장비 교체·전체 재해 복구·운영 전환 인수를 뜻하지 않습니다.

## 네 번째 매체: LTSC 기본 curl 의존 제거 후 최종 재검증

LTSC 기본 curl의 TLS 기능 차이에 의존하지 않도록 상태 확인과 OpenSearch flush를 매체에 포함된 Python의 전용 도구로 바꿨습니다. TLS 검증을 끄지 않으며 인증서 체인·이름 검증, 고정 loopback 연결, 프록시/redirect 거부, 전체 시간 제한을 적용합니다. 단위 검증 46개와 Windows 매체/제어기 집중 검증 35개가 통과했습니다. 서비스 설치기의 인증서 이름 전달은 가상 시험으로 확인했고 관리자 서비스 설치는 실행하지 않았습니다.

# 기본 탐지 목록 사용과 확장

작업본은 `F:\codex\SAW-Claude-main`입니다. `F:\claude\saw`는 읽기 전용 원본입니다. 이 문서는 2026-10-11 증분 구현의 사용법이며 운영 설치·인수 승인서는 아닙니다.

## 화면에서 확인하기

1. 로그인 후 왼쪽 **탐지 룰 → 기본 탐지 목록**을 엽니다.
2. **시그니처**에서 묶음을 고르거나 `Docker`, `TeamCity`, `T1190` 등을 검색합니다.
3. 규칙 이름을 누르면 설명, 가상 예시, 관련 ATT&CK 기술, 추가 확인 항목이 표시됩니다.
4. 선임 분석가·관제 매니저의 `detection.approve` 권한으로 켜고 끌 수 있습니다. 끄는 이유는 앞뒤 공백을 제거한 뒤 5자 이상입니다. 이 설정은 모든 조사에 적용되고 감사 기록이 남습니다.
5. 이미 태그가 있는 규칙을 켜고 끈 경우 **재분석**합니다. 새 규칙을 추가한 경우 기존 자료에는 새 태그가 없으므로 **증거 다시 처리**가 필요합니다.
6. **NDR 연결 정책** 탭에서 조직별 기준과 기본 꺼짐 상태를 확인합니다. 이 탭은 조회용이며 시그니처 켜기·끄기 API를 사용하지 않습니다.
7. **공격 흐름**에서 각 단계, 시간 범위, 추가 확인 항목을 봅니다. 관련 흐름은 개별 탐지의 근거를 대신하지 않습니다.

HTTP 2xx는 공격 성공을 보장하지 않습니다. 차단된 악성 요청은 차단됐다는 이유만으로 오탐이 되지 않습니다. 관리 API 접근 역시 승인된 운영 작업일 수 있습니다.

## 폐쇄망에서 웹 규칙 추가하기

`saw/detectors/packs/*_signatures.yaml`은 서버가 직접 읽는 규칙 목록입니다. 외부 서비스나 LLM은 필요 없습니다.

- 기존 묶음의 형식을 따르고 ID가 겹치지 않게 합니다.
- 넓은 단어만 쓰지 않고 제품 경로 경계와 필요한 HTTP 메서드·문자열 조합을 좁힙니다.
- `examples`에 탐지해야 하는 가상 예시, `benign`에 정상·유사 경로의 반례를 반드시 넣습니다.
- `explain`과 `checks`에는 관찰 가능한 범위와 다음 확인을 적습니다. 요청 본문이나 임의 헤더는 현재 웹 시그니처의 검사 범위가 아닙니다.
- 개발/검증 장비에서 `.venv/Scripts/python.exe -B -m pytest tests/unit/test_signature_pack.py -q -p no:cacheprovider`를 실행합니다.
- 조직 검토 후 규칙 파일을 배포하고 서버를 재시작합니다. 기존 자료는 다시 처리합니다.

정규식·규칙 내용을 바꾸면 전수 검사와 최적화 검사의 동등성 시험도 수행하세요. 현재 지원 범위와 공식 근거는 [출처 문서](detection-rule-sources.md)에 있습니다. 정상 예시 통과나 실제 자료의 일치 0건은 모든 미래 자료에서의 오탐 0%를 뜻하지 않습니다.

## NDR 기준을 조정하기

파일은 `saw/detectors/packs/ndr_policies.yaml`입니다. **새 정책 5종은 모두 기본 비활성**입니다. 기존에 있던 일반 네트워크 탐지기를 일괄 끄는 설정은 아닙니다.

| 정책 | 무엇을 비교하는가 | 먼저 확인할 기준 |
|---|---|---|
| `large_outbound` | 내부 출발지별 송신 바이트 합계 | 내부 CIDR, 구간, 최소 송신량, 백업·동기화 |
| `unexpected_port` | 승인된 서비스 포트 목록 밖의 연결 | 허용 포트와 `baseline_note`; 비어 있으면 활성화 불가 |
| `foreign_destination` | 수집된 목적지 국가와 기준 국가 | 국가 필드 출처·정확도, 해외 업무·CDN |
| `off_hours_admin` | 관리 포트와 업무요일·시간 | 시간대, 0=월~6=일, 시작 이상/종료 미만 |
| `internal_admin` | 서로 다른 내부 시스템 사이 관리 포트 | 내부 CIDR, 관리 포트, 승인 관리 단말 |

설정의 내부망·시간·포트 값은 예시입니다. 조직의 실제 기준으로 바꾸고 필요한 정책의 `enabled`를 `true`로 바꾼 뒤 서버를 재시작하세요. 허용 포트는 관측된 과거 이력을 자동 학습한 목록이 아닙니다. 따라서 '처음 등장한 포트'라고 단정하지 않습니다.

집계는 UTC 기준 **고정 구간**입니다. 구간 경계에 걸친 송신은 나뉠 수 있습니다. `bytes_out`은 출발지의 송신, `bytes_in`은 수신이며 서로 바꾸지 않습니다. 국가·시간·포트·송신량 등 필요한 정보가 없으면 추정하지 않고 검사 범위 안내를 확인합니다.

이벤트·그룹·탐지 결과·근거 표본에는 상한이 있습니다. 상한에 도달한 결과를 전체 검사가 끝난 결과로 보지 마세요. 근거 링크는 일치 기록의 제한된 표본이며 전체 관측 건수와 구분해서 표시합니다.

## 공격 흐름 해석하기

기존 8종에 내부 관리 접속·자료 반출·업무시간 밖 관리 접속 뒤 송신의 **연관 후보 3종**이 추가됐습니다.

- 기본 시간 범위는 4시간이며 YAML의 `max_span_seconds`로 바꿀 수 있습니다.
- 신규 3종은 명시적인 **같은 출발지 역할**과 증가하는 시작 시각을 요구합니다. 출발지·목적지를 구분할 수 없으면 새 흐름에 억지로 연결하지 않습니다.
- 입력의 시간대가 없거나 시간값이 잘못되면 순서를 확정하지 않습니다.
- 흐름은 인과관계·침투 성공·내부자 판정을 확정하지 않습니다. 원 탐지와 원문을 확인하세요.
- 끈 규칙의 검토 전 탐지는 재분석에서 정리된 뒤 흐름을 계산합니다. 분석가가 검토·피드백·사건 연결한 기록은 보존합니다.

## 승인된 Sigma를 조사에 적용하기

탐지 룰 후보 작성 → 과거 자료 시험 → **다른 사람의 승인** 순서를 유지합니다. 승인되거나 배포 기록이 있는 **현재의 정확한 Sigma 버전**만 다음 조사 분석에서 자동 검사합니다. 외부 SIEM·센서에 규칙을 배포하거나 차단하는 기능은 아닙니다.

- 작성자·현재 버전 작성자·검토자의 상태와 권한을 확인합니다. 규칙의 원본 조사와 대상 조사 접근 범위도 적용합니다.
- 수정으로 초안이 된 버전, 시험이 불완전한 버전, 미지원 조건은 자동 적용하지 않습니다.
- 미지원 필드·modifier·logsource·timeframe을 조용히 무시하지 않습니다. 오류를 고쳐 다시 시험하세요.
- 실행 시간·이벤트 수·규칙 수·정규식 실행에는 상한이 있습니다. 한도·실패는 별도의 검사 범위 안내로 남습니다.
- 승인 규칙 일치 결과도 분석 후보입니다. ATT&CK는 후보이며 최종 판단·조치는 분석가에게 남습니다.
- 시험 통과는 지원된 로직을 정해진 범위에서 실행했다는 뜻입니다. 탐지 품질이나 오탐률이 개선됐다는 뜻은 아닙니다.

## 검증과 운영의 차이

복사본의 가상 자료 시험과 원본 저장소의 허용된 읽기 전용 집계를 구분했습니다. 실제 은행 자료 원문은 복제·출력하지 않았습니다. 이번 작업은 깨끗한 LTSC 2019의 오프라인 설치·재시작 시험, 운영 데이터 도입, 운영 배포 승인을 대체하지 않습니다.

실제 화면별 예시는 [6단계 사용 안내](DETECTION-LIVE-WALKTHROUGH.md), 후속 실행 결과는 [2026-10-12 검증 기록](DETECTION-VALIDATION-2026-10-12.md)을 참고하세요.

# SAW 사용 안내 — 헌팅 / 시나리오 / 자산·업무 (0.2.6, 2026-11-14)

**이 문서가 현재 기준 사용 안내입니다.** 이전 안내(`ANALYST-WORKFLOW-GUIDE-20261029.md` 등)는 이력이며, 그 안의 화면 이름은 "도구·설정" 아래로 옮겨졌을 수 있습니다. 설계 배경은 [ADR-0020](adr/0020-hunting-platform-structure.md), 검증 결과는 [검증 기록](verification/hunting-platform-20261114.md)에 있습니다.

주 메뉴는 세 개입니다: **헌팅 / 시나리오 / 자산·업무**. 그 밖의 도구와 관리 기능은 **도구·설정**에 있습니다.

## 1. 헌팅

의심 IP·가설·시나리오·자산을 먼저 정하지 않아도 됩니다.

1. **새 헌팅**: 관계사와 로그 파일(NDR·FW·WAF·IPS·DDoS·애플리케이션 CSV)을 고릅니다. 제목은 자동으로 붙고 나중에 고칠 수 있습니다.
2. 올리면 자동으로 분석하고 **확인할 활동**이 열립니다.
3. 맨 위 한 줄에서 범위를 확인합니다: 관계사, 관측 기간, 선택 자료 건수(원천별), 진행 상태, 분석 버전, 전체 처리/일부 처리.
   - **분석 방법 N개와 실제 처리 범위**를 펼치면 방법마다 계산 결과와 실제로 읽은 건수, 필요한 자료가 나옵니다.
   - 계산 결과는 여섯 가지입니다: 후보 있음 / 조건 일치 없음 / 자료 부족 / 일부 처리 / 실패 / 미지원. "조건 일치 없음"은 정상이라는 뜻이 아니고, "자료 부족"·"미지원"은 계산하지 못한 것입니다.
4. 왼쪽 목록에서 활동을 고르면 오른쪽에 여섯 부분이 나옵니다.
   1. 무엇을 관측했나
   2. 왜 확인할 만한가
   3. 정상 업무로 설명될 가능성 (등록 자산이 있으면 여기에 함께 표시)
   4. 아직 확인되지 않은 것
   5. 시간 흐름과 관련 원문 — **근거 기록 표**(이 활동을 계산한 기록 최대 20건, 전체 건수, 고른 기준; 줄마다 원문 열기), **관련 원문 N건 보기**, 업무 흐름, 타임라인, 전체 로그 검색
   6. 판단 남기기 — 추가 확인 필요 / 정상 업무로 확인 / 위협 확인(뒤 두 가지는 근거를 적어야 함), 확인 요청·회신, 보고서
5. 원문을 보고 돌아와도 고른 활동, 걸러 보기, 목록 위치, 쓰던 판단 메모가 남습니다(같은 브라우저 창 안에서).
6. 자료나 지식이 바뀌면 "이 결과는 최신이 아닙니다"가 뜹니다. **다시 분석**하면 새 버전이 생기고 판단은 그대로 이어집니다.

헌팅 목록은 남은 일로 나뉩니다: 진행 중 / 확인 필요(미검토·추가 확인·분석 전) / 검토 끝 / 완료(종결).

**기본 분석 · AI 미연결**이라고 표시된 결과는 모델 없이 계산한 것입니다. 현재 방법: 웹 요청 패턴, 대량 전송, 반복 접속, 여러 대상 접촉, 조회 대상 변화, 업무 흐름(등록한 업무 의미가 있을 때), 사용 중인 시나리오, 저장된 탐지.

### 분석 기준 — 무엇을 찾고 어떤 기준으로 활동을 만드는가

헌팅 목록이나 헌팅 작업대 위쪽의 **분석 기준**을 엽니다(도구·설정에도 있습니다).

- **적용 범위**: 모든 관계사 공통, 또는 관계사 하나. 관계사 기준이 있으면 그 관계사에는 공통 기준 대신 그것이 적용되고, 둘 다 없으면 기본 기준입니다.
- **방법 켜고 끄기**: 웹 요청 패턴 / 대량 전송 / 반복 접속 / 여러 대상·포트 접촉 / 조회 대상 변화 / 업무 흐름 / 시나리오 / 저장된 탐지. 끈 방법은 헌팅에 "사용 안 함"으로 표시됩니다. "조건 일치 없음"과 다릅니다.
- **기준 값**: 앞의 네 가지는 "기준 값 보기·고치기"에서 로그 종류·개수·제외할 주소 등을 고칩니다. 조회 대상 변화는 "서로 다른 대상 N개 이상, 같은 기능 이용자 중앙값의 M배 이상"을 고칩니다. 바꾼 값에는 표시가 붙고 "기본값으로"로 되돌립니다.
- 업무 흐름·시나리오·탐지 룰은 각자의 화면에서 내용을 고칩니다(여기서는 켜고 끄기와 바로 가기).
- **저장**하면 다음 분석부터 적용됩니다. 끝난 헌팅에는 "분석 기준이 바뀌었습니다"가 뜨고 **다시 분석**을 눌러야 바뀝니다. 이전 분석 결과는 그대로 남습니다.
- 헌팅 맨 위 줄에 적용된 기준(기본 / 공통 vN / 이 관계사 vN)이 표시됩니다. 활동 상세의 "이 활동을 만든 분석 방법"과 방법 표의 "고치기"에서 해당 기준으로 바로 갑니다.
- 고치려면 지식 쓰기 권한이 필요합니다(분석가 이상). 조회자는 보기만 합니다.

### AI 조사

활동 목록 위의 **AI 조사**를 펼칩니다.

- 상태는 네 가지입니다: AI 미연결 / 연결됨 · 추론 검증 필요 / AI 사용 가능 / 실행 실패. **모델 추론 확인**은 실제로 한 번 답을 받아 봅니다.
- **AI 조사 시작**을 누르면 모델이 자료 개요부터 읽기 조회를 요청하고, 결과를 보고 다음 조회를 정합니다. 질문은 비워도 됩니다.
- 모델은 이 헌팅의 관계사·기간 안에서만 조회할 수 있고, 숫자는 모두 엔진이 계산합니다. 차단·설정 변경·코드 실행 도구는 없습니다.
- 단계마다 요청한 조회와 결과, 거부된 요청이 남습니다. 끝나면 모델의 주장마다 "근거 일치 / 확인 실패"가 붙습니다. 자동 확인은 인용한 단계가 있는지와 수치가 그 결과에 있는지만 봅니다.
- 오프라인 템플릿 응답기는 AI가 아니며 AI로 표시되지 않습니다. 모델 연결은 관리자가 도구·설정 > 로컬 모델에서 합니다.

## 2. 시나리오

"이런 흐름을 어떤 자료로 확인할지"를 저장해 다음 헌팅에서 다시 씁니다. 코드·조건식·JSON을 쓰지 않습니다.

1. **직접 만들기**(빈 양식) 또는 **제공 예제에서 만들기**의 "실행 가능" 예제로 시작합니다. "설명 자료(실행기 없음)"는 읽는 자료입니다.
   - 직접 만들 때는 이름을 적고 **찾는 방식**을 고릅니다: 요청이 이 순서로 이어짐 / 앞 요청 뒤 대상을 바꿔 가며 반복 / 같은 곳으로 반복 통신 / 여러 대상·포트 접촉 / 보안장비 경보 뒤 통신 / DDoS 시간대의 접속. 방식은 나중에 바꿀 수 있습니다.
   - 단계는 카드로 하나씩 넣거나 **단계를 글로 한꺼번에 적기**에 한 줄에 하나씩 적습니다. 경로만 적어도 됩니다.
     예: `로그인: POST /login` · `/report/*`(이 경로로 시작) · `전체 내려받기: GET /report/export?mode=all`(? 뒤는 "이 글자 포함").
   - 순서 방식은 2~6단계, 단계마다 "요청에 이 글자가 있을 때만" 조건을 붙일 수 있습니다.
2. **무엇을 찾을까요?** — 이름과 목적.
3. **어떤 흐름인가요?** — 단계 카드(이름·경로), 같은 대상으로 묶는 기준(출발지 IP는 후보, 세션은 연결 기준이 등록된 서비스), 시간 범위, 세는 단위(서로 다른 값 / 중복을 뺀 요청), 기준 값. 아래에 "이 시나리오가 찾는 것"이 한 문장으로 나옵니다.
4. **현재 자료로 확인** — 헌팅을 골라 **한 번 시험하기**. 조건을 만족한 흐름, 기준 미달·순서 반대·시간 범위 밖 예, 필요한 자료가 없으면 "자료 부족"이 나옵니다. 저장되지 않습니다.
5. **저장** — 초안(시험만) 또는 **다음 헌팅부터 사용**. 고치면 새 버전이 되고, 끝난 헌팅은 당시 버전을 유지합니다.

예: "인증 관련 접근 뒤 조회 대상 변화"는 인증 **성공**을 확인하지 않습니다. 인증 관련 접근이 있었다는 것만 봅니다.

**분석 예시**에서 분석 사례집(업무 흐름 F01~F07, 플랫폼 분석 W01~W60, 로그 예제 C001~C100)을 엽니다. 사례는 읽는 자료이며, 사례 수만큼 자동 분석기가 있는 것은 아닙니다.

## 3. 자산·업무

등록하지 않아도 헌팅은 됩니다. 등록하면 활동의 "정상 가능성" 옆에 함께 보여 줍니다(활동을 숨기지 않습니다).

- **등록**: 이름과 IP·도메인·호스트 중 하나. 담당자·업무·중요도는 나중에 채웁니다.
- **기본 정보**: 담당자, 정보 출처, 마지막 확인일, 다음 확인일, 상태, 주소의 유효 기간. 주소를 다른 자산으로 옮길 때는 지우지 말고 종료일을 적습니다. 과거 기록은 그때 유효했던 자산으로 연결됩니다.
- **서비스 기능·정상 업무**: 업무 설명, 운영 시간·정기 작업, 경로의 업무 의미(헌팅의 기록 상세에서 "메모하고 기억하기"로 추가).
- **변경 이력·확인할 내용**: 고친 이력과 확인이 필요한 항목.
- **파일로 갱신(CSV)**: 파일 선택 → 열 연결 확인 → 신규/변경/변경 없음/충돌/오류 미리 보기 → 적용.
  - 자산 ID가 같으면 같은 자산으로 갱신합니다. IP만으로는 덮어쓰지 않습니다.
  - 빈 칸은 기존 값을 유지합니다(비우려면 선택). 파일에 없는 자산은 지우지 않습니다. 같은 파일을 다시 적용해도 중복되지 않습니다.
  - Excel 파일은 CSV로 저장해 올립니다.
- **확인할 변경**: 같은 관계사에서 같은 주소가 두 자산에 동시에 배정됨, 담당자 미확인, 확인 기한 지남, 업무 설명 없음.
- 같은 사설 IP가 다른 관계사에 있어도 서로 섞이지 않습니다.

## 4. 지식 저장

원문을 보던 자리에서 저장합니다: 기록 상세의 **메모하고 기억하기**(업무 의미·연결 기준·이번 사건의 판단을 따로 저장), 업무 흐름의 **의미 기억하기**·**이 순서를 흐름으로 기억하기**. 저장한 지식은 다음 분석에서 검색·적용되는 것이며 모델을 재학습하지 않습니다. 이력·중지·복원은 도구·설정 > 업무 의미·흐름 이력에 있습니다.

## 5. 도구·설정

- 분석 도구: 붙여넣기 분석(HTTP·페이로드·IOC·비교), 수동 질의, 사건 묶음, 작업 상태, 처리 기록
- 지식·사전: 업무 의미·흐름 이력, 관계사·장비 공격명 사전, SOC 경험·유사 사례, 분석 사례집
- 평가 자료(전문가): 골든셋 후보함, 정답 사례·반출, 탐지 룰
- 관리자: 파서, 오프라인 콘텐츠, 로컬 모델, 사용자·권한·감사, 자료 삭제
- 이전 화면: 이전 홈, 조사 목록, 현황판 — 자료는 그대로이고 주소도 계속 열립니다.

헌팅 작업대 안의 기존 영역(① 전체 현황 ~ ④ 확인 및 판단, 전문 분석)도 그대로 쓸 수 있습니다.

## 6. 역할과 권한

관제 매니저와 관리자는 모든 기능을 쓰고 모든 헌팅을 엽니다. 선임 분석가·분석가·조회자는 이전과 같습니다. 승인처럼 작성자와 다른 사람이 해야 하는 일은 역할과 관계없이 다른 사람이 해야 합니다.

## 7. 버전 확인

왼쪽 메뉴 아래와 분석 사례집 맨 위에 앱·화면·사례 콘텐츠 버전이 표시됩니다. 서버가 업데이트됐는데 화면이 이전 버전이면 위쪽에 "새로 고침" 안내가 뜹니다.

## 8. 알아 둘 한계

- WAF·IPS·DDoS·애플리케이션 입력은 열 이름을 정한 가상 프로필이며 실제 장비 지원이 아닙니다.
- 실제 AI 모델로는 검증하지 못했습니다(이 문서 기준 환경에 모델이 없음).
- 대상 Windows 10 LTSC 2019에서의 설치·업데이트는 확인하지 못했습니다(PENDING_ENV). 0.2.6 매체는 아직 만들지 않았습니다.

# 설치 위치 선택과 안전한 재실행

대상은 Windows 10 Enterprise LTSC 2019 x64, PowerShell 5.1, 폐쇄망의 공동 접속 서버다. 관리자 서비스 설치와 실제 대상 OS 인수는 개발기 시험과 구분한다.

## C: 또는 D: 선택

Windows PowerShell을 **관리자 권한으로 실행**하고 설치 매체 최상위 폴더로 이동한다. 관리자 계정으로 로그인한 것만으로는 충분하지 않다. 아래 호스트명과 분석가 대역은 예시이며 승인된 실제 값으로 바꾼다.

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -InstallRoot "D:\SAW" -HostName "saw.corp.local" -AllowFrom "10.20.0.0/16"
~~~

C:에 설치하려면 InstallRoot를 C:\SAW로 바꾼다. 드라이브 여유 공간을 보고 입력으로 선택할 수도 있다.

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -ChooseInstallLocation -HostName "saw.corp.local" -AllowFrom "10.20.0.0/16"
~~~

D:\SAW처럼 절대 경로를 입력한다. D:\SOC\SAW처럼 중첩 경로를 쓰려면 상위 D:\SOC 폴더가 먼저 존재해야 한다. Enter는 표시된 기본 경로다. 드라이브 최상위 자체, 네트워크 공유, 링크·정션은 거부한다. 설치 매체와 설치 폴더는 겹치면 안 된다. 공백·한글 경로를 처리하며, 명령/설정 해석에 영향을 주는 일부 특수문자는 거부한다. 짧은 경로를 권한다. SYSTEM 계정으로 무인 설치할 때는 D:\SAW처럼 영문·숫자 경로를 사용한다. 한글 경로의 PostgreSQL 초기화 보완은 일반 관리자/사용자 세션에서만 임시 별칭을 사용하도록 제한한다.

| 내용 | D:\SAW 선택 시 |
|---|---|
| 프로그램·내장 Python | D:\SAW\app, D:\SAW\venv |
| PostgreSQL | D:\SAW\data\postgresql |
| OpenSearch 색인 | D:\SAW\data\opensearch |
| 로그·PCAP 원본 | D:\SAW\data\objects |
| 앱 데이터·모델 작업 | D:\SAW\data\saw |
| 별도 반입 모델 | D:\SAW\models |
| 실행 로그·백업 | D:\SAW\logs, D:\SAW\backup |

설치 최소 여유 공간은 20GB다. 원본·색인·모델·백업/복구 사본과 매체를 풀 공간은 별도로 확보한다. 20GB는 운영 용량 보장이 아니다. 모델 가중치는 본체 매체에서 제외된다. Windows 임시 폴더나 사용자 프로필까지 옮기지는 않는다. 중단 런타임을 보존한 venv.retained-* 또는 OpenSearch 보관 폴더는 자동 삭제하지 않으므로 추가 공간을 사용한다. 복구 결과를 확인하고 조직의 보존 정책에 따라 별도로 정리한다.

NoAdmin은 한 PC의 사용자 프로세스 시험용이다. 여러 분석가가 공동 접속하는 운영 서버 구성을 대신하지 않는다.

대용량 구성요소 압축 해제·파일 무결성 검사에는 수 분 이상 걸릴 수 있다. 화면 출력이 잠시 없다는 이유로 설치 창을 강제 종료하거나 두 번째 설치를 동시에 시작하지 않는다.

## 실패 후 재실행

오류 단계와 원인을 확인한 뒤 **같은 매체·같은 설치 경로·같은 옵션**으로 다시 실행한다. Python, data, secrets 또는 설치 폴더를 지우지 않는다.

- 비밀값 없는 설치 상태 기록과 중복 실행 잠금을 사용한다.
- 이전 완료 표시만 믿지 않고 Python·파일·DB·설정을 다시 검증한다.
- 정상 Python은 재사용한다. SAW 소유가 확인된 중단 파일은 보존 후 로컬 매체로 복구한다.
- 개발용·공용 Python, 다른 버전, 출처 불명 파일은 덮어쓰지 않는다.
- 기존 DB·비밀번호·계정·키는 재생성하지 않는다. 수정·손상·충돌이 발견되면 해당 경로를 보존하고 중단한다.
- DB 초기화 도중 중단되어 데이터 폴더가 비어 있지 않고 불완전하면 자동 재초기화하지 않는다. 반복 실행만으로 복구되지 않는 경우이므로 폴더를 보존하고 오류 기록과 초기화 상태를 검토한다.
- NoServices 구성 시험은 사용 가능한 설치 완료로 표시하지 않는다.

이전 설치기에 상태 기록이 없다면 원래 매체로 출처를 확인한다. 일치하는 원래 매체를 보존한 경우 새 설치 명령에 -BaselineBundleDir "E:\원래 매체"를 추가한다. 원래 앱 버전을 보존하여 설치를 이어가며, 앱 버전 업데이트는 별도 update.ps1을 사용한다. 출처가 없거나 기존 앱이 수정되었으면 자동 복구하지 않는다.

## 정상 설치본과 드라이브 이전

이번 개발·시험에서 사용자의 기존 C:\SAW는 변경하지 않는다. 수동 조치 후 이미 정상 동작하는 설치본을 이 수정 때문에 다시 설치할 필요는 없다.

정상 설치본에 보완 설치기를 재실행하면 파일·구성·인증서 및 실행 상태를 점검하고 종료한다. 계정·키·정상 설정·서비스 실행 상태를 보존한다. 중지 상태에서는 실행 중 검증을 미실행으로 명확히 표시한다.

C:\SAW를 D:\SAW로 옮기려고 새 경로로 설치 명령을 실행하지 않는다. DB·서비스·실행 설정에 경로가 저장되어 있어 별도 이전 절차와 복구 검증이 필요하다. 다른 경로의 같은 이름 서비스는 충돌로 중단한다. 같은 경로의 앱 업데이트와 전체 복구는 [업데이트·복구 안내](OFFLINE-UPDATE-GUIDE.md)를 따른다.

## 보완 내용과 검증 구분

OpenSearch는 전용 JDK, 자식 Java 환경변수 두 개, 서비스·JVM·설정 경로를 확인한다. PostgreSQL은 실제 Windows 실행 SID에 해당 비밀번호 파일의 읽기·상위 폴더 이동 권한과, 초기화에 필요한 런타임 읽기/실행·신규 데이터 권한을 제한적으로 임시 부여한다. 정상 종료·처리 가능한 오류에서 원래 ACL을 복원한다. 강제 종료·전원 중단은 복원을 보장하지 않으므로 재개 전에 임시 ACL과 한글 경로 별칭을 점검한다. DB의 postgres 역할과 Windows 계정은 다르다.

탐지·분석·룰·모델·업무 스키마는 변경하지 않는다. 실제 실행 결과와 남은 LTSC·관리자 서비스·조직 서명 인수 항목은 [이번 설치기 검증 기록](verification/installer-recovery-2026-10-18.md)을 따른다.

# SAW 0.2.7 운영 업데이트 절차 (2026-11-17)

기존 SAW 0.2.6(또는 0.2.5·0.2.4) 설치를 0.2.7로 올리는 운영자용 절차입니다. 대상은 폐쇄망 Windows 10 Enterprise LTSC 2019 x64입니다. 화면 그림과 자세한 설명은 매체 안의 `app/docs/DOUBLE-CLICK-UPDATE-GUIDE.md`와 `app/docs/OFFLINE-UPDATE-GUIDE.md`를 함께 보세요. 화면 사용법은 `app/docs/HUNTING-GUIDE.md`에 있고, 웹 서버 로그 붙여넣기는 그 문서 5절에 있습니다.

## 0. 먼저 알아둘 것

- 매체 이름은 `SAW-0.2.7-pilot.<날짜>-model-free-win-x64.zip`입니다. 모델 가중치는 들어 있지 않습니다. 크기와 SHA-256은 함께 전달한 `SHA256SUMS.txt`에 있습니다.
- **이 매체는 후보입니다.** 이 문서를 넣어 매체를 만든 시점에는 0.2.7 매체로 설치·업데이트·복구 리허설을 실행하지 않았습니다.
- **대상 LTSC 2019에서의 실행, 관리자 서비스 방식, 재부팅 뒤 동작은 확인하지 못했습니다(PENDING_ENV).** 운영 서버에 적용하기 전에 같은 환경의 시험 서버에서 이 절차를 먼저 한 번 실행하세요.
- 0.2.7에서 달라지는 것
  - **웹 서버 로그 붙여넣기 분석**: 도구·설정 → 붙여넣기 분석 → 로그에 Apache·Nginx·IIS·Tomcat·WebtoB·JEUS·HAProxy·Caddy 접근 로그, JSON 접근 로그, Apache·Nginx 오류 로그를 붙여넣으면 조사와 같은 웹 탐지 기준으로 판단합니다. 붙여넣은 내용은 저장하지 않습니다.
  - **사례 WL01~WL11**(가상): 같은 화면의 "이 사례 넣기"로 바로 분석해 볼 수 있습니다.
  - **새로 읽는 웹 로그 형식 5개**(헌팅 자료 올리기에도 적용): Apache vhost_combined, HAProxy HTTP, JSON 접근 로그, Apache 오류 로그(ModSecurity 포함), Nginx 오류 로그.
  - **대형 조사 수정**: 탐지 결과가 아주 많은 조사(예: 10만 행 업로드)에서 공격 스토리 단계가 `derived_source_scope_limit`로 실패하던 것을 고쳤습니다.
  - User-Agent 열이 없는 웹 로그 형식에서 빈 값을 자동화 도구로 세지 않습니다. 이미 분석한 조사의 결과는 다시 분석해야 바뀝니다.
  - **데이터베이스 스키마는 바뀌지 않습니다**(0029 그대로). 0.2.5 이하에서 올리면 0.2.6 때와 같이 0029까지 표를 추가만 합니다.

## 1. 반입과 압축 해제

1. ZIP과 `SHA256SUMS.txt`를 폐쇄망으로 반입합니다.
2. PowerShell에서 `Get-FileHash .\SAW-0.2.7-...zip -Algorithm SHA256`을 실행하고, 결과가 `SHA256SUMS.txt`의 값과 같은지 확인합니다.
3. 기존 설치 폴더 **밖의** 새 빈 폴더에 압축을 풉니다(예: `D:\SAW-media-0.2.7`). 기존 설치 폴더나 이전 매체 폴더 위에 풀지 마세요.
4. 설치 드라이브의 여유 공간을 확인합니다. 업데이트는 적용 전에 설치 전체의 복구본을 같은 드라이브에 만들므로 현재 설치 폴더 크기만큼 공간이 더 필요합니다.

## 2. 업데이트

1. 분석가에게 접속 중단을 알립니다. 진행 중인 업로드·분석 작업이 끝났는지 확인합니다.
2. 압축을 푼 폴더의 **UPDATE-SAW.cmd**를 더블클릭합니다. 창 제목은 "SAW 기존 설치 업데이트 · 계정과 분석 자료 유지"입니다.
   - 일반 사용자 방식(NoAdmin) 설치라면 설치할 때 쓴 **같은 Windows 계정**으로 실행합니다.
   - Windows 서비스 방식 설치라면 창의 안내에 따라 **관리자 권한으로 열기**를 누릅니다.
3. **기존 설치 폴더**를 선택합니다(예: `D:\SAW`).
4. **복구본 폴더**에 아직 없는 새 이름을 지정합니다(예: `D:\SAW-r-20261117`). 설치와 같은 드라이브여야 하고, 설치 폴더나 매체 폴더 안에 두면 안 됩니다. 이 경로를 적어 둡니다.
5. **설치 점검**을 누릅니다. 서버를 멈추거나 파일을 바꾸지 않고 설치 방식·파일·설정·공간만 확인합니다. 막히면 표시된 사유를 해결하고 다시 점검합니다. 공간을 만들려고 복구본을 지우지 마세요.
6. **서버 중지 동의**를 체크하고 **업데이트 시작**을 누릅니다.
7. 매체 확인 → 서버 중지 → 전체 복구본 생성 → 새 앱 적용 → 서버 시작·접속 확인 순서로 진행합니다. 진행 중에는 창을 닫거나 전원을 끄지 마세요.
8. 완료 화면의 **복구본 위치**가 4번에서 적은 경로와 같은지 확인합니다.

적용 중 실패하면 프로그램이 업데이트 직전 상태로 스스로 되돌리고 결과 화면에 상태를 표시합니다. 이때는 **기록 폴더** 단추로 기록 위치를 확인해 전달해 주세요.

## 3. 업데이트 뒤 확인

열어 둔 브라우저 화면은 이전 화면 파일로 계속 동작합니다. 확인하기 전에 **브라우저를 새로 고침(Ctrl+F5)** 하세요.

| 확인 | 기대 |
|---|---|
| 로그인 | 기존 계정·비밀번호·MFA로 그대로 로그인됨 |
| 업데이트 창 결과 | 완료로 표시되고, 적용한 버전이 0.2.7, 스키마가 0029 |
| 헌팅 목록 | 기존 조사·헌팅이 그대로 보이고 관계사·기간이 같음 |
| 도구·설정 → 붙여넣기 분석 → 로그 | "웹 서버 로그 사례로 해 보기 (11)"이 보이고, WL01 "이 사례 넣기" → "기대한 결과와 같음" |
| 도구·설정 → 분석 사례집 | 사례 60개(W01~W60)가 그대로 보임 |
| 시나리오·자산·업무·분석 기준 | 업데이트 전에 저장한 것이 그대로 있음 |
| 조사 건수 | 화면을 둘러본 뒤에도 조사·증거·탐지 건수가 업데이트 전과 같음 |
| 종료·재시작 | 정상 종료 뒤 다시 시작해도 자료가 남아 있음 |

붙여넣기 분석 확인에는 사례(WL01~WL11)나 가상 자료만 쓰세요.

## 4. 문제가 있을 때 되돌리기

1. 같은 새 매체의 **UPDATE-SAW.cmd**를 다시 실행합니다.
2. 기존 설치 폴더를 선택하고, **복구본 선택**으로 2절 4번에서 만든 복구본 폴더를 고릅니다.
3. **서버 중지 동의**와 **계정·자료를 백업 시점으로 되돌린다는 확인**을 체크합니다.
4. **이전 상태 복구**를 누릅니다. 업데이트 전의 앱과 업데이트 직전의 계정·자료로 돌아갑니다.
5. **SAW 열기**로 기존 계정과 자료를 확인합니다.

- 복구는 전체 시점 복구입니다. 업데이트 뒤에 만든 자료와 바꾼 비밀번호·MFA·권한도 복구본 시점으로 돌아갑니다.
- 복구 직전 상태는 별도 보관 폴더에 남고 창에 그 위치가 표시됩니다.
- 복구본·설치·보관 폴더를 직접 지우거나 덮어쓰지 마세요. 복구가 실패하면 **기록 폴더**의 기록을 전달해 주세요.
- 같은 0.2.7 매체를 한 번 더 적용해도 자료는 그대로이고 중복이 생기지 않습니다.

# 반복 FW·NDR CSV 업로드와 시나리오 확인
사용자 요청: 제공한 두 CSV와 같은 형식을 계속 업로드하고 그 자료로 시나리오를 검증할 수 있게 한다. 기존 P1~P5와 릴리스 작업의 증분이다. 질문 생략과 최선의 판단에 따른 연속 구현은 이미 승인됐다.

## 결정
전용 내장 CSV 어댑터와 기존 분석 실행 이력을 연결한다. 일반 별칭 확장은 다른 CSV의 의미를 바꿀 위험이 있고, 사용자 파서 DSL 확장은 이번 두 형식보다 범위가 크다. 강한 헤더 조합을 인식하는 두 어댑터로 기존 CSV의 인용·개행·원문 위치 보존을 재사용한다. 승인 사용자 파서의 우선순위를 유지한다.
NDR의 올바른 HTTP 요청행만 web/http_access로 연결한다. 나머지는 connection/conn으로 보존한다. 공격명은 원천 장비의 주장이고 탐지/허용/200은 침해 성공이나 정답이 아니다. FW 세션시간 단위나 누적/차분, 장비/관계사 귀속은 자동 확정하지 않는다.
기존 실행 이력에 형식별 관측 건수·필드 준비도·검사 한계를 보관하고, 기존 scenario.flow의 실제 실행에 시나리오별 후보 수와 단계 근거 유무를 추가한다. 파싱 성공, 자료 준비, 흐름 적중, 정오탐 검증은 별도다. 무적중은 정상 판정이 아니다. 다단계 selected_truth 지원을 새로 주장하지 않는다.

## 범위와 경계
- 새 DB/schema/제품 Phase 없음. 기존 권한·원문·세대·분석 스냅샷·4-eyes 유지.
- 원본 Claude, 운영 설치/계정/은행 자료는 변경하지 않는다.
- 두 첨부는 읽기 전용 형태/집계 검증만 수행한다. 행·식별값·요청값은 출력/복사/학습/소스/배포에 넣지 않는다. 합성 자료만 테스트와 안내에 쓴다.
- 불투명 목적지는 그대로 보존하며 IP·국가·내외부·두 장비의 동일 자산으로 추론하지 않는다. 여러 원천 장비가 섞이면 단일 검증 프로필 적용 전 분리 확인을 안내한다.
- 실제 분석기·시나리오 matcher를 합성 입력으로 검증한다. 스키마가 맞는다는 것만으로 공격 정답·정확도나 전체 시나리오 지원을 주장하지 않는다.
- 기존 봉인 후보 .release/affiliate-p5-built-20261025는 보존한다. 최종 새 소스에는 별도 빌드·검증·릴리스가 필요하다.


## 형식 확인에 따른 증분 결정
첨부의 요청 표기에는 버전이 있는 HTTP 요청행과 HTTP 버전 없이 메서드·경로만 기록한 요약이 함께 있다. 알려진 대문자 메서드와 origin-form 경로의 정확한 요약 문법을 지원하되 버전을 만들지 않는다. 준비도는 전체 HTTP 요청 표기 중 요청행과 요약을 나누어 센다. 헤더·본문·패킷 재구성 또는 침해 성공의 근거로 간주하지 않는다.
전용 파서는 필수 헤더를 포함한 최대199개 원천 열을 지원한다.200열 이상 또는 중복 필수 헤더는 전용 형식으로 주장하지 않는다. 기존 범용 파서 fallback 자체를 성공한 전용 형식 검증으로 해석하지 않는다.

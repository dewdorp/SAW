# SAW 0.2.6 운영 업데이트 절차 (2026-11-14)

기존 SAW 0.2.5(또는 0.2.4) 설치를 0.2.6으로 올리는 운영자용 절차입니다. 대상은 폐쇄망 Windows 10 Enterprise LTSC 2019 x64입니다. 화면 그림과 자세한 설명은 매체 안의 `app/docs/DOUBLE-CLICK-UPDATE-GUIDE.md`와 `app/docs/OFFLINE-UPDATE-GUIDE.md`를 함께 보세요. 0.2.6 화면 사용법은 `app/docs/HUNTING-GUIDE.md`에 있습니다.

## 0. 먼저 알아둘 것

- 매체 이름은 `SAW-0.2.6-pilot.<날짜>-model-free-win-x64.zip`입니다. 모델 가중치는 들어 있지 않습니다. 크기와 SHA-256은 함께 전달한 `SHA256SUMS.txt`와 릴리스 설명에 있습니다.
- **이 매체는 후보입니다.** 이 문서를 넣어 매체를 만든 시점에는 0.2.6 매체로 설치·업데이트·복구 리허설을 아직 실행하지 않았습니다. 리허설 결과는 저장소의 검증 기록과 릴리스 설명에 따로 적습니다.
- **대상 LTSC 2019에서의 실행, 관리자 서비스 방식, 재부팅 뒤 동작도 확인하지 못했습니다(PENDING_ENV).** 운영 서버에 적용하기 전에 같은 환경의 시험 서버에서 이 절차를 먼저 한 번 실행하세요. 그 결과가 나오기 전에는 "운영 적용 검증 완료"로 부르지 않습니다.
- 0.2.6에서 달라지는 것
  - 주 메뉴가 **헌팅 / 시나리오 / 자산·업무** 3개로 바뀝니다. 나머지 화면(조사 작업대, 분석 사례집, 골든셋 후보함 등)은 **도구·설정**에 있습니다. 기존 주소와 자료는 그대로입니다.
  - 헌팅 실행, 분석 기준, 시나리오(직접 만들기, 기준을 넘는 통신·기록), 자산·업무 등록, 업무 의미·흐름, AI 조사 화면이 생깁니다. AI 조사는 실제 모델로 검증하지 않았고, 모델 가중치가 없으면 "기본 분석 · AI 미연결"로 표시됩니다.
  - 관제 매니저와 관리자는 모든 조사를 열 수 있습니다. 승인자가 작성자와 달라야 하는 규칙은 그대로입니다.
  - 데이터베이스에 표를 **추가만** 합니다. 스키마는 0.2.5의 0026에서 0029로 바뀝니다(업무 지식 0027, 헌팅 0028, AI 조사 0029). 기존 계정·조사·증거·탐지·설정은 바뀌지 않습니다.

## 1. 반입과 압축 해제

1. ZIP과 `SHA256SUMS.txt`를 폐쇄망으로 반입합니다.
2. PowerShell에서 `Get-FileHash .\SAW-0.2.6-...zip -Algorithm SHA256`을 실행하고, 결과가 `SHA256SUMS.txt`의 값과 같은지 확인합니다.
3. 기존 설치 폴더 **밖의** 새 빈 폴더에 압축을 풉니다(예: `D:\SAW-media-0.2.6`). 기존 설치 폴더나 이전 매체 폴더 위에 풀지 마세요.
4. 설치 드라이브의 여유 공간을 확인합니다. 업데이트는 적용 전에 설치 전체의 복구본을 같은 드라이브에 만듭니다. 그래서 현재 설치 폴더 크기만큼 공간이 더 필요합니다.

## 2. 업데이트

1. 분석가에게 접속 중단을 알립니다. 진행 중인 업로드·분석 작업이 끝났는지 확인합니다.
2. 압축을 푼 폴더의 **UPDATE-SAW.cmd**를 더블클릭합니다. 창 제목은 "SAW 기존 설치 업데이트 · 계정과 분석 자료 유지"입니다.
   - 일반 사용자 방식(NoAdmin) 설치라면 설치할 때 쓴 **같은 Windows 계정**으로 실행합니다.
   - Windows 서비스 방식 설치라면 창의 안내에 따라 **관리자 권한으로 열기**를 누릅니다.
3. **기존 설치 폴더**를 선택합니다(예: `D:\SAW`). 새 매체 폴더는 자동으로 표시됩니다.
4. **복구본 폴더**에 아직 없는 새 이름을 지정합니다(예: `D:\SAW-r-20261114`). 설치와 같은 드라이브여야 하고, 설치 폴더나 매체 폴더 안에 두면 안 됩니다. 이 경로를 적어 둡니다.
5. **설치 점검**을 누릅니다. 이 단계는 서버를 멈추거나 파일을 바꾸지 않고, 설치 방식·파일·설정·공간만 확인합니다. 점검이 막히면 표시된 사유를 해결하고 다시 점검합니다. 공간을 만들려고 복구본을 지우지 마세요.
6. **서버 중지 동의**를 체크하고 **업데이트 시작**을 누릅니다.
7. 진행 순서는 매체 확인 → 서버 중지 → 전체 복구본 생성 → 새 앱 적용(스키마 0029) → 서버 시작·접속 확인입니다. 진행 중에는 창을 닫거나 전원을 끄지 마세요.
8. 완료 화면의 **복구본 위치**가 4번에서 적은 경로와 같은지 확인합니다.

적용 중 실패하면 프로그램이 업데이트 직전 상태로 스스로 되돌리고, 결과 화면에 상태를 표시합니다. 이때는 **기록 폴더** 단추로 기록 위치를 확인해 전달해 주세요.

## 3. 업데이트 뒤 확인

업데이트 전에 열어 둔 브라우저 화면은 이전 화면 파일로 계속 동작합니다. 확인하기 전에 **브라우저를 새로 고침(Ctrl+F5)** 하세요. 0.2.6 화면은 열어 둔 창이 오래된 화면이면 "새로 고침" 안내를 띄웁니다.

| 확인 | 기대 |
|---|---|
| 로그인 | 기존 계정·비밀번호·MFA로 그대로 로그인됨 |
| 업데이트 창 결과 | 완료로 표시되고, 적용한 버전이 0.2.6, 스키마가 0029 |
| 왼쪽 주 메뉴 | 헌팅 / 시나리오 / 자산·업무가 보이고, 그 아래 도구·설정이 있음 |
| 헌팅 목록 | 기존 조사가 헌팅 목록에 그대로 보이고 관계사·기간이 같음 |
| 도구·설정 → 분석 사례집 | 사례 60개(W01~W60)가 보이고 검색됨 |
| 도구·설정 → 골든셋 후보함 | 업데이트 전에 담은 후보가 그대로 있음 |
| 시나리오 | 예제 목록이 열리고, "빈 양식에서 새로 만들기"로 양식이 열림. 저장하지 않으면 아무것도 바뀌지 않음 |
| 자산·업무 | 빈 목록 또는 기존 목록이 열림. 업데이트만으로 자산이 생기지 않음 |
| 조사 건수 | 화면을 둘러본 뒤에도 조사·증거·탐지 건수가 업데이트 전과 같음 |
| 종료·재시작 | 정상 종료 뒤 다시 시작해도 자료가 남아 있음 |

확인에는 가상 자료만 쓰세요. 헌팅 실행이나 시나리오 시험을 해 보려면 운영 조사와 섞이지 않게 시험용 조사를 따로 만들어 사례집의 원본 ZIP을 올립니다.

## 4. 문제가 있을 때 되돌리기

1. 같은 새 매체의 **UPDATE-SAW.cmd**를 다시 실행합니다.
2. 기존 설치 폴더를 선택하고, **복구본 선택**으로 2절 4번에서 만든 복구본 폴더를 고릅니다.
3. **서버 중지 동의**와 **계정·자료를 백업 시점으로 되돌린다는 확인**을 체크합니다.
4. **이전 상태 복구**를 누릅니다. 업데이트 전의 앱(0.2.5 등)과 업데이트 직전의 계정·자료로 돌아갑니다.
5. **SAW 열기**로 기존 계정과 자료를 확인합니다.

- 복구는 전체 시점 복구입니다. 업데이트 뒤에 만든 헌팅·시나리오·자산·업무 의미, 새 조사·업로드, 바꾼 비밀번호·MFA·권한도 복구본 시점으로 돌아갑니다.
- 복구 직전 상태는 별도 보관 폴더에 남고, 창에 그 위치가 표시됩니다. 두 시점의 자료를 자동으로 합치지는 않습니다.
- 복구본·설치·보관 폴더를 직접 지우거나 덮어쓰지 마세요. 복구가 실패해도 자동으로 지우거나 다시 시도하지 않습니다. 이때는 **기록 폴더**의 기록을 전달해 주세요.
- 같은 0.2.6 매체를 한 번 더 적용해도 안전합니다. 자료는 그대로이고 중복이 생기지 않습니다.

## 5. 확인한 범위

- 소스 시험: 서버 전체 3,103건 중 3,084건 통과, 19건 건너뜀(환경 조건), 실패 0. 화면 시험 67파일 446건 통과.
- 개발 PC의 격리 QA 서버(합성 자료)에서 헌팅·시나리오·자산·업무 흐름·분석 기준 화면을 실제 브라우저로 확인했습니다. 결과는 `app/docs/verification/hunting-platform-20261114.md`에 있습니다.
- 확인하지 못한 것:
  - 0.2.6 매체의 설치·업데이트·복구 리허설(매체 빌드 시점 기준)
  - 대상 LTSC 2019(17763)에서의 실행, 관리자 서비스 설치·재부팅
  - 운영 규모 자료에서의 업데이트 시간과 성능
  - native OpenSearch/PostgreSQL 운영 구성
  - 실제 AI 모델
- 운영 서버는 업데이트하지 않았습니다.

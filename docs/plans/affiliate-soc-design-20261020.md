**2026-10-20 사용자 설계 승인:** P1→P5 구현·검증·검토·새 릴리스를 단계별 재질문 없이 진행한다.
최신 실행 상태는 STATE.md와 단계별 검증 기록을 따른다.

아래는 승인 당시 P0 검토 내용이다. **현재 상태는 P0 점검·설계이다. 아래 P1–P5 기능은 아직 구현하지 않았다.**
제품 코드·스키마·설치 매체·운영 데이터는 이 단계에서 변경하지 않는다.
최신 두 요구문서의 내용은 동일한 업무 목표와 승인 순서를 가진다. 붙여넣은 요청을 우선하고 Markdown 첨부를 함께 대조했다.
최신 지시의 “먼저 설계와 단계별 계획을 제시”, “설계 승인 후 … 실제 구현”에 따라 이 검토본 승인 이후 구현한다.
여기의 P0–P5는 이번 증분의 작업 순서이며 기존 제품 Phase 0–14를 재시작하는 의미가 아니다.

## 1. 사용자에게 달라지는 업무

서비스명과 의심 IP를 모르는 상태에서도 **A사 → FW-01 → 하루치 로그**만 선택하면 시작한다.
자료 의미를 먼저 확인하고, 가능한 분석과 불가능한 분석을 구분한 뒤 확인할 후보를 보여준다.
분석가는 원문·통계·시간 흐름을 보고 정상 설명과 추가 확인을 남긴다.
같은 분석 버전에서 보고서와 Excel을 만들고, 기존 경험 검토에서 좋은 사례를 Golden으로 채택한다.
외부 개발팀용 전달은 별도의 반출 승인과 비식별화 검증을 거친다.

정상/공격을 자동 확정하거나 장비 정책·예외·차단을 실행하지 않는다.
기본 파싱·탐지·통계·Excel·Golden 흐름에는 모델이 필요하지 않다.
기존 Foundation-Sec·MITRE·PCAP·사용자/MFA·원본/증거 계약과 업데이트 기능을 유지한다.

## 3. 관계사·장비·자료 문맥

### 3.1 관계사

기존 Investigation.org_unit의 의미를 유지하면서 안정된 OrgUnit 식별자를 연결한다.
새로운 company/affiliate/tenant 문자열을 각각 만들지 않는다.
권장 이관: OrgUnit(id, display_name, state), Investigation.org_unit_id(nullable).
기존 org_unit은 호환용 원래 문자열로 보존하고 이관표로 ID에 연결한다.
동명이거나 불확실한 문자열을 자동 병합하지 않으며 미분류도 조회/분석을 막지 않는다.

기존 생성 API의 org_unit 입력은 계속 받되, ID 입력과 충돌하면 오류로 표시한다.
신규 UI는 ID를 선택하고 표시 이름을 보여준다. 응답/수정/필터/Export가 같은 해석을 사용한다.
관계사 분류 변경은 접근권한을 추가하지 않는다. 조사 멤버십·역할 검사를 계속 적용한다.

### 3.2 장비 및 업로드 문맥

Device와 불변 DeviceProfileVersion을 둔다. 소유·운영 조직, 관측 대상, 제품/제조사/버전,
기능(FW/WAF/IPS/DDoS/NDR), 가상영역·망, 관측 위치, 수집 경로를 구분한다.
Evidence/EvidenceFile에는 적용한 장비 프로필·자료 문맥 버전을 연결한다.
장비 등록 수정으로 과거 업로드의 문맥을 소급 변경하지 않는다.

한 조사에 여러 장비가 가능하다. 원본 기록의 귀속은 조사 대상과 별도로 저장한다.
공용·혼합 파일은 승인된 행별 매핑을 적용하며 충돌/미확인은 unresolved로 남긴다.
상충된 항목은 특정 회사 통계에 넣지 않고 미분류 건수로 알린다.
같은 IP·장비명이더라도 관계사/망/가상영역이 다르면 다른 대상이다.
장비가 미확인인 이벤트를 전부 하나의 “unknown device” 세션으로 합치지 않는다.

### 3.3 권한

기존 require(investigation.read/write…)와 중앙 검색 범위를 유지한다.
집계·자산 조회·정상 예외·기준선·유사 Check·인용·원문·보고/파일 다운로드까지 원천 조사 ACL을 검사한다.
현 공유 Check는 원천 조사 비회원에게 내용이 보이는 의도된 공유 기능이 있으므로,
이번 범위에서는 조회·인용·근거·보고·Export 모두 원천 조사 ACL을 필수로 확인한다.
별도 공유 투영으로 이를 대체하지 않는다. 별도 공유 권한 모델은 이번 범위 밖의 후속 제안이다.
관리자 기술 역할에 분석/Golden/반출 권한을 자동 추가하지 않는다.

## 4. 정규화 계약과 자료 품질

기존 공통 이벤트의 시각·IP·포트·HTTP·raw_ref를 유지한다.
새 문맥은 버전 있는 ext.observation과 검색용 허용 필드로 확장한다.
기존 raw_event, 원본 hash·줄/offset·parser/version을 수정하지 않는다.
정규화/프로필/이관 버전과 각 필드의 출처를 함께 고정한다.

| 의미 묶음 | 보존할 값과 제한 |
|---|---|
| 소속·출처 | 조사 소속, 기록 귀속, 장비/프로필/가상영역/망, 실제 관측 제품과 수집 경로 |
| 시간 | 원본 문자열, 발생/수집/시작/종료, 시간대·정밀도·보정 근거. 비교 가능 여부 |
| 통신 | IPv4/IPv6, src/dst·포트·프로토콜, NAT 전후·보안존·인터페이스 |
| 기록 단위 | session_start/interim/end、request、alert、interval_summary、unknown; ID와 유효 범위 |
| 조치와 판단 | raw_action/정규화 action/매핑 프로필, 장비 정책ID·원본 시그니처ID/이름/버전, 관측 통신 결과, 분석가 행위 판단, 실제 영향 판단을 분리 |
| 측정값 | 방향별 byte/packet, duration, 단위·구간·누적/증가량·평균/최대·샘플링 |
| 수집 범위 | 전체 이력/경보만/차단만/표본/추출 필터/알 수 없음, 손실·중복·잘림 |
| 값 상태 | observed / recorded_empty / not_collected / unknown_semantics, 실제 숫자 0은 observed |
| 근거·버전 | raw_ref·source hash·처리 run·파서/정규화/문맥 버전, 필드 출처(원본/등록/명시 추정) |

일반 CSV를 Zeek로 위장하지 않는다. 실제 출처는 유지하고 공통 ConnectionObservation 어댑터가
검증된 필드만 기존 네트워크 탐지기에 제공한다. ext.zeek.*는 실제 Zeek 전용 의미로 남긴다.
CSV orig_bytes와 Zeek orig_bytes의 방향이 현재 다르므로 열 이름만 보고 방향을 이관하지 않는다.
과거 불명확한 bytes_in/out은 legacy/meaning_unknown으로 보존한다.

분석기별 필수 필드·자료 종류·시간/단위·기준선 조건을 DetectorSpec에 선언한다.
자료 품질은 위협 후보와 별도 출력이다. 분석 가능/제한적/필수 자료 부족/해당 없음과 사유를 보여준다.
실행 결과도 완료 일치/완료 무일치/부분/자료 부족/비활성·해당 없음/실패/취소로 남긴다.
관측되지 않은 필드 때문에 검사하지 못한 결과를 “정상 0건”으로 표시하지 않는다.

## 5. 장비별 계산

### FW 우선

세션 키는 관계사·망·장비·가상영역·세션ID·통신/NAT 문맥·시작시각/재사용 구간으로 구성한다.
같은 세션의 시작/중간/종료는 기록 수로는 보존하되 새 연결/주기성에서는 중복 계산하지 않는다.
검증된 누적 카운터는 세션의 완료값과 구간 변화량으로 처리하며 각 기록을 합산하지 않는다.
카운터 역전·초기화·종료 누락은 별도 품질 상태다. 모호하면 연결/전송 확정값을 만들지 않는다.
거부 접근은 시도 통계이며 성립 연결로 계산하지 않는다.
방향의 근거가 없으면 src→dst 전송이라고 표시한다.

첫 흐름은 탐색(고유 목적지/포트)·검증된 새 연결 주기성·전송 비대칭·장기 연결·거부→허용 후보를 다룬다.
신규/희소 통신은 비교 범위가 충분한 경우에만 제공한다.
승인된 정상 baseline이 없는 상태에서 기존 history_baseline의 빈 값을 정상 기준으로 만들지 않는다.

합성 예: A사 FW-01의 S7 시작(0/0), 중간(100/900), 종료(300/1200)는
기록 3건·세션 1건·src→dst 300bytes·dst→src 1200bytes다.
400/2100bytes로 합산하거나 중간 기록 간격을 C2 주기로 보지 않는다.
B사의 같은 S7/IP, 승인 백업, 거부 스캔, 의미 불명 카운터를 별도 반례로 둔다.

### WAF / IPS / DDoS / NDR

| 장비 | 계산과 경계 |
|---|---|
| WAF | 다경로 탐색·반복/변형·오류/응답 변화·공격 의심 허용·객체ID 변화·자동화와 공격성 근거 결합. 요청과 룰 적중·UA 미수집/빈값·Edge/Origin을 구분, 200≠침해 |
| IPS | 동일 패턴 반복·다수 대상 확산, 한 대상의 다양한 공격 패턴, 탐지 전용 중요 경보·연계 가능한 후속 통신 후보. detect/drop/reset·모드·집계구간 보존, 패킷 미확보 시 재검증 제한 |
| DDoS | 출발지 없이 급증·반복·지속·유형별 peak·집중 대상을 분석. 비교 가능한 완화 전후/잔여 트래픽을 제시. bps/pps/rps·평균/최대·샘플링·위치 구분, 비동시 peak 합산 금지 |
| NDR | 새 연결 주기성·장기 연결·전송량 변화·탐색·비교 가능한 신규 관계·DNS/HTTP/TLS 특성·복합 지표 변화 구간. 흐름/경보/PCAP·손실/양방향 수집 범위를 구별 |

제조사별 실제 매핑은 승인된 제품 샘플·필드 사전으로 검증하기 전까지 미검증이다.
각 장비에 이상 후보·승인된 정상 활동·자료 부족 사례를 함께 둔다.

## 6. 기본 탐지 설명·정책·룰 시험

DetectorSpec이 카탈로그 설명과 실행 검증의 공통 입력이다.
ID/엔진 버전, 적용 자료, 필수 필드와 의미, 실제 조건, 그룹/단위, 시간창과 경계,
기본/현재값과 출처, 한도, 예제·정상 반례·후속확인·미실행 사유를 제공한다.
현재 Sigma의 포함 경계, 행위 분석의 반열린 구간, NDR 고정 버킷은 각자 명시한다.
동일하게 바꾸려면 별도 엔진 버전·회귀가 필요하다.

기존 DetectionVersion 및 콘텐츠 패키지 검증/적용/복구를 사용한다.
정책은 불변 PolicyVersion과 범위별 PolicyBinding을 추가한다.
그룹 기본 → 관계사 승인 → 장비 명시 설정으로 결정하고 값별 출처를 보여준다.
일회성 분석 기준은 공용 정책을 바꾸지 않는다.
초안·승인·활성 포인터는 분리한다. 초안 v2 저장 실패/반려가 활성 v1을 중단하지 않는다.
기존 disabled 설정은 그대로 이관한다. 독립 검토가 없었던 legacy 설정은 승인 완료라고 기록하지 않는다.

적용: 초안 → 선택 사례 시험 → 변경 전후 비교 → 기여자 외 승인 → 별도 적용.
정확한 버전/정답/정책 hash에 승인하며, 동시 변경 시 재시험한다.
복구는 이전 승인 버전으로 활성 포인터를 바꾸는 새 이력이다.
실행 시작 후 정책을 바꿔도 진행 중 실행은 시작 시점의 값을 사용한다.

숫자·기간·범위·예외는 폼으로 제공한다. JSON은 문자열을 유지하고 검증/저장 때 파싱한다.
임의 Python/SQL/쉘 실행은 제공하지 않는다. 미지원 논리는 엔진 변경 필요로 표시한다.
Finding에서 만든 후보와 원 탐지의 조건 차이를 구조적으로 보여준다.

TestRun에는 선택 사례/구간/개체·입력 스냅샷·정답 버전·판정 단위를 고정한다.
expected_match / expected_no_match / unlabeled를 구별한다.
탐지 적중 정답과 침해/시도/정상·승인 활동/오탐/유보/자료 부족 판단 정답은 별개다.
승인 점검 스캔은 “탐색 적중 + 승인 활동”일 수 있다.
TP/FP/FN은 명시적 정답이 있는 단위만 계산한다. 관련 없는 공격 조사를 FN으로 만들지 않는다.
기존 조사 verdict 기반 수치는 legacy 방식으로 남기고 새 정확도 지표로 승격하지 않는다.

## 7. 실행·UI·확인 기록

기존 Job/lease/idempotency/cancel/progress와 ProcessingRun을 유지한다.
공통 AnalysisRun과 탐지기별 실행 결과에 입력 scope/data_epoch/manifest,
파서·정규화·엔진·룰·정책 버전, 실제 적용값, 처리/제외/미처리 건수, 단위·한계를 고정한다.
기존 Finding 식별자와 분석가 기록을 유지하면서 실행별 FindingSnapshot으로 과거 결과를 보존한다.
과거 실행 정보가 없으면 미기록으로 표시하고 만들어 채우지 않는다.

화면은 기존 조사 작업대 안에서 다음 순서로 배치한다.

1. 관계사·장비·기간·수집 범위, 품질·가능한 분석.
2. 기록/요청/세션/원본 경보/SAW 후보 수를 구분한 통계와 추이.
3. 우선 확인 후보 및 선별 조건·수치·정상 설명·필요 근거.
4. 구간 클릭 → 같은 실행 범위의 원문/요청·통신 비교.
5. Check·후속확인·판단 → 보고/Excel → 기존 경험·Golden 검토.

화면 필터와 서버 분석 실행 범위를 분명히 구분한다.
원문 전체를 브라우저에 올리지 않고 페이지/선택 근거만 조회한다.
클릭/열람은 확인 완료가 아니다. 개별 로그마다 확인함 체크박스를 만들지 않는다.

기존 Check와 연결된 후속항목에 안정된 ID/revision, 질문·사유·자료·우선순위,
담당 관계사/부서/사용자(nullable), 기한(nullable), 상태·회신 근거·검증자/시각을 둔다.
회신 수신과 검증 완료를 분리하고 기한 없음은 연체가 아니다.
미확인을 남긴 제한적 종결이 가능하며 종결≠영향 없음이다.
장비 간 연결은 확인된 연결/연관 후보를 구분한다.

## 8. 보고서와 실제 Excel

ReportVersion이 분석 결과 IDs/SHA, scope, 정확한 Check IDs/revision,
후속항목 버전, 자료·정책 버전, 마스킹 정책, 분모·단위·생성시점을 고정한다.
HTML과 XLSX는 이 snapshot만 읽는다. 승인 이후 새 자료나 Check 변경은 새 보고 버전이다.
P1에서는 FW 관측 결과용 최소 ReportVersion과 저장 HTML을 먼저 연결한다.
P3에서 같은 계약을 후속확인·판단 revision과 다중 조사 Excel까지 확장한다.
기존 A4 HTML 렌더러를 확장하고 단일 파일 오프라인 열람을 유지한다.

Excel 진입점은 조사 작업대, 선택 후속확인, 조사 목록의 선택 조사 내보내기다.
8개 시트: 요약 / 상세 / 확인 필요 / 통계 / 시간 추이 / 근거 / 적용 기준 / 범위·한계.
차트의 계열은 같은 단위·관측 위치/집계 의미끼리만 만든다.
관계사별 IP 고유수 합계와 전체 고유수, 기록/세션/요청 수의 분모를 분리한다.

작성기 후보는 XlsxWriter의 행 단위 메모리 제한 방식이다.
공식 문서상 constant_memory는 행 순서 작성이 필요하고 add_table/병합 제약이 있다.
따라서 합쳐진 셀 중심 레이아웃보다 autofilter·틀 고정·명시적 열 형식·단위별 차트를 사용한다.
원문·메모·IP·긴ID는 write_string, 자동 수식/URL/숫자 변환은 끈다.
안전한 앱 계산만 따로 허용하며 매크로/DDE/externalLinks가 없음을 ZIP 구조로 검사한다.
현재 의존성에는 없으므로 P3에서 정확한 버전/hash·BSD 2-Clause NOTICE·오프라인 wheel·LTSC를 검증한다.
이 설계 단계에서는 설치하거나 배포 잠금을 변경하지 않았다.
[공식 메모리 계약](https://xlsxwriter.readthedocs.io/working_with_memory.html) ·
[문자열 자동 변환 옵션](https://xlsxwriter.readthedocs.io/workbook.html) ·
[라이선스](https://xlsxwriter.readthedocs.io/introduction.html)

Excel 형식 한계 전에 나누고 분할 manifest/생략 수·이유·원본 참조를 제공한다.
원문 전체 재현은 별도 승인 evidence bundle로 구분한다. 조용한 셀/행 자르기는 금지한다.
Excel 수정 결과를 자동 재수입하지 않는다.

## 9. Golden과 외부 개발 패키지

GoldenVersion/Blob, Experience revision, 독립 채택, 사건군 split을 유지한다.
새 v2에는 관계사·장비·자료 의미·분석/정규화/정책 버전, 탐지 정답과 조사 판단 정답,
당시 제공 입력과 후일 확정 사실, interpretation_only/full_recalculation 용도를 추가한다.
대표 근거만 제공하는 사례는 서버가 interpretation_only로 고정한다.
full_recalculation은 전체 범위의 정규화 입력·분할 manifest·총건수·hash·필수 필드와
변환 후 재계산 결과가 일치한 경우에만 서버 검증으로 허용한다. 사용자가 표시만 바꿀 수 없다.
기존 v1 bytes/hash는 변경하지 않는다. 새로운 검토 버전에서만 확장한다.
Behavior의 EVENT_KEYS 공용 투영도 함께 수정하고 허용 목록을 무제한으로 열지 않는다.

train/dev/holdout의 사건·파생 사례 분리를 유지한다. 같은 IP만으로 사건을 묶지 않는다.
파일명·제목·노트·보고/경험/검색 결과의 라벨 우회 누출을 별도 검사한다.
holdout 평가 시도/버전/대상·결과 열람 이력을 남겨 튜닝 자료로 반복 소비하지 않게 한다.

골든셋 채택과 외부 반출은 다른 승인이다.
ReleaseVersion에 목적/수신처/사용 조건, 원본 Golden 버전·SHA, split,
가명화 프로필/검증 결과, 전체 파일 manifest와 최종 artifact digest를 동결한다.
비식별화 미리보기·재제공 권리 확인 → 독립 반출 승인 → 정확히 승인된 파일만 다운로드한다.
초안/변환 프로필/패키지 bytes 변경은 기존 승인을 무효화한다.
기존 agent export를 외부 반출 승인 없이 우회 사용하는 경로도 함께 차단한다.
내부 평가자 정답 조회 권한과 외부 입력 패키지 권한은 별개다.

일관된 가명 대응표는 내부에만 둔다. 관계사/망이 다른 동일 IP의 관계를 잘못 합치지 않는다.
시간·IP 변환으로 요일/업무시간/CIDR/국가·순서·정답 의미가 달라지면 재검증하거나 제외한다.
참조/ID/hash는 변환본으로 재생성하고 원본 연결은 내부에 유지한다.
가명화는 완전 익명화·반출 허가를 의미하지 않는다.

train, dev, holdout-input, internal-evaluator는 별도 생성물이다.
holdout 정답을 입력 ZIP의 다른 폴더/숨김 시트에도 넣지 않는다.
README·JSON Schema·필드 사전·방법론/자료셋 버전·한계·전체 파일 목록을 포함한다.
실제 도구 기록이 없으면 근거 해석 평가용으로 표시한다. 가짜 도구 실행/추론을 만들지 않는다.
새 훈련 시스템·외부 SaaS·자동 업로드/메일 전송은 이번 범위에 없다.

Export 요청에 schema_version과 purpose를 명시한다. 기존 v1 snapshot은 변형하지 않고 보존한다.
기존 외부 agent export 요청은 반출 승인 없이는 409 external_release_approval_required와 새 절차를 안내한다.
승인된 ReleaseVersion은 명시적 v1 호환 projection 또는 v2로 생성한다. v1에 없는 새 문맥은
manifest에서 미제공 한계로 표시하며 v1을 v2라고 가장하지 않는다. 내부 evaluator는 기존 독립 권한을 유지한다.
모델별 messages/input-output 변환은 가명화와 별도의 ModelConversionProfile(version, target, field mapping,
serialization contract, validation suite)로 관리한다. 승인 입력/정답과 split을 유지하며 미지원 변환은 거부한다.
변환 후 schema·참조·입력/정답 누출 검증을 통과한 결과 bytes에 다시 반출 승인을 받는다.
어떤 모델에도 즉시 학습 가능하다고 표시하지 않는다.

대량 출력은 Job으로 처리한다. JobSourceInvestigation 연결로 모든 원천 조사를 추적한다.
시작·완료 게시·다운로드 때 ACL/채택/반출 승인/hash/철회를 재검사한다.
취소·실패·만료·철회 결과는 다운로드 불가로 두고, 승인/감사/manifest를 보존한 채 임시파일을 정리한다.

## 10. 성능·이관·되돌리기

API는 작업 등록과 상태 조회만 한다. 원본 전체·전체 그룹을 API/브라우저 메모리에 올리지 않는다.
기존 스트리밍 파서·search_after/iter_events를 사용하고 그룹 상태는 디스크/전용 작업 저장소로 분산한다.
백만 건 검사는 전체 범위를 안정된 시각+event_id 순서로 순회한다.
그룹/시간/메모리/결과 상한은 명세·UI·보고서에 남긴다.
상위 N개 후보 표시와 전체 계산 완료 여부를 분리한다.
한도를 늘려 2MiB/3MiB 결과 문제를 숨기지 않고 요약+페이지+artifact로 나눈다.

P1 기본 제안은 서버당 대량 분석/내보내기 동시 1개, 조회용 자원을 별도 보존하는 큐다.
1,000/100,000/1,000,000 합성 기록, 고유IP/장비 수, 1/3 분석가 부하를 측정하여 조정한다.
16GB 목표의 RSS/디스크/지연·취소 시간 수치는 P5 실측으로 정하며 현재 성능 보장값은 없다.

마이그레이션은 0014 다음부터 단계별 additive·멱등 적용한다.
신규 nullable 참조/버전 테이블과 인덱스를 먼저 추가하고 old API 입력을 유지한다.
OrgUnit 이관표·문맥 매핑은 충돌 건수/미분류를 검토하고 예전 스냅샷을 재작성하지 않는다.
OpenSearch 동적 필드 폭증을 피하도록 허용된 명시 매핑을 둔다.
새 index generation에 재처리 → 수/원문 참조/의미/ACL 확인 → 명시적 전환; 실패하면 기존 generation 유지.
이전 generation의 보관 참조로 승인 결과를 계속 열 수 있게 한다.
테스트용 SQLite에도 동일 필터·집계 의미를 구현하되 운영 검증이라고 부르지 않는다.

파서 재처리는 새 정규화 generation, 룰 재분석은 같은 자료의 새 AnalysisRun이다.
새 코드는 구 스키마를 확인하고 필요한 이관을 명확히 안내한다.
DB와 색인·원본·버전 snapshot을 함께 백업한다.
업데이트 복구는 기존 전체 시점 복구를 사용한다. 이후 새 자료는 별도 보관하며 자동 병합하지 않는다.
운영 DB 변경·설치·관리자 서비스·반출·원본 삭제는 별도 승인 범위를 유지한다.

단계 중 독립적으로 가능한 작업은 병렬 처리하되 같은 파일/DB/시험 포트의 동시 변경은 피한다.

## 12. 검증·남은 환경

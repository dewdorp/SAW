# 분석가 작업 흐름 안내 (2026-10-29)

이 문서는 관계사별 조사 화면의 세 작업 영역, 후속 확인 회신 대조, 내부 골든셋, 공격명 등록부의 사용 방법을 설명합니다. 모든 예시는 가상 자료입니다.

## 1. 조사 만들기 — 관계사 1개 + 기간 1개

- 조사는 **관계사 하나와 조사 기간 하나**를 단위로 만듭니다. 조사 목록의 "새 조사"에서 관계사와 시작·종료 날짜를 함께 입력해야 만들 수 있습니다. 기간은 최대 400일입니다.
- 관계사가 목록에 없으면 관리자·SOC 관리자·선임 분석가가 상단 메뉴 **관계사·공격명 관리**에서 추가합니다. 관계사는 이름이 아니라 ID로 구분하므로 이름이 같은 관계사도 서로 섞이지 않습니다.
- 증거를 올린 뒤에는 조사의 관계사를 바꿀 수 없습니다. 다른 관계사 자료는 새 조사로 만드세요.
- 같은 사설 IP(예: 10.20.1.10)라도 관계사가 다르면 다른 자산입니다. IOC 조회·위협 헌팅 집계·자산 일치·연관 분석은 사설·CGNAT·링크로컬 주소를 관계사별로 나누어 보여 주며, 다른 관계사의 과거 판정을 이 조사에 합치지 않습니다. 같은 관계사 안에서도 DHCP·NAT·VPN으로 IP 사용자가 바뀔 수 있으므로 IP만으로 같은 호스트라고 단정하지 않습니다.

## 2. 세 작업 영역

조사 화면 상단에 관계사·조사 기간·실제 관측 기간이 항상 표시되고, 아래 세 영역으로 나뉩니다.

### ① 전체 현황
- **전체 요약**: 입력 행 수와 분석에 쓰인 행 수, 로그 종류별 건수, 일별·주별 추이, 기록이 0건인 날, 조사 기간 밖 기록, 시간 없는 기록, 출발지·목적지·포트·서비스·대응(허용/차단/탐지)·장비 공격명 상위 값과 "기록 없음" 건수를 한 화면에 보여 줍니다.
- 필터를 걸면 "기준: 필터 결과 N건 / 전체 M건"처럼 분모가 함께 바뀌어 표시됩니다. 분모가 조용히 바뀌지 않습니다.
- **최근 분석 실행** 칸은 끝나지 않은 분석과 그 이유를 보여 줍니다. 예: "기록의 장비(출처)가 등록·확인되지 않아 분석하지 않았습니다." 이것은 "분석했는데 이상 없음"과 다릅니다.
- 트래픽 개요·통계·원천 문맥·분석 실행 이력 탭도 이 영역에 있습니다.

### ② 조사
- **조사 제안**: 규칙이 만든 후보입니다. 각 후보에 어떤 규칙(탐지기 id·버전)이 어떤 근거로 만들었는지가 표시됩니다. 후보는 판정이 아닙니다.
- **로그 검색·원문**: 후보에 없는 기록도 직접 찾을 수 있습니다. 화면 위 검색 칸에서 출발지·목적지·포트·공격명 등을 골라 검색하고, 찾은 기록을 근거로 추가할 수 있습니다.
- 행위·타임라인과, 필요할 때 펼치는 전문 분석(공격 흐름·관계도·HTTP·포렌식·DNS·TLS·연결·ATT&CK)이 있습니다.

### ③ 확인 및 판단
- 확인 항목, 후속 확인 요청과 회신, 내부 골든셋, 메모가 있습니다.

## 3. 판단 상태 5가지

조사 종료 시 다음 중 하나를 고릅니다.

| 상태 | 뜻 |
|---|---|
| 정상(승인된 업무) | 범위가 맞는 회신·근거로 업무임이 설명됨 |
| 공격 시도 확인 | 공격 요청·탐지는 확인됐지만 성공 근거는 없음 |
| 침해 확인 | 실행·변경·유출 등 성공 근거가 있음 |
| 근거 부족 | 판단할 근거가 아직 부족함 |
| 자료 품질 한계 | 수집 누락·파싱 실패 등으로 판단할 수 없음 |

공격명, 장비 위험도, HTTP 200, 방화벽 허용만으로는 침해 확인을 고르지 마세요. 처리되지 않은 후속 확인(회신 대기, 범위 불일치, 일부만 설명)이 남아 있으면 "정상"으로 종료할 수 없습니다.

## 4. 후속 확인 요청과 회신 대조

1. 확인 항목에서 후속 확인을 만들 때 **대상(관계사·출발지·목적지·포트·행위)**과 **기간**, 질문을 적습니다.
2. 회신을 받으면 회신 문서가 다루는 범위(관계사·기간·출발지·목적지·포트)를 함께 입력합니다.
3. 화면이 요청 범위와 회신 범위를 비교해 결과를 표시합니다.
   - **일치**: 회신이 확인 대상 전체를 다룹니다. "확인됨"으로 검토할 수 있습니다.
   - **일부만 설명**: 다루지 않은 부분이 "남은 질문"으로 남습니다.
   - **불일치**: 다른 관계사·기간·대상입니다. 이 회신으로 해당 행위를 설명할 수 없고 "확인됨"으로 닫을 수 없습니다.
   - **범위 미기재**: 회신에 범위가 없어 같은 행위인지 알 수 없습니다. 근거 기록을 붙여도 "확인됨"으로 닫을 수 없습니다.
4. 범위가 일치해도 회신 내용(업무인지, 공격인지)의 판단은 분석가가 합니다. 이 기능은 이메일·메신저를 실제로 보내지 않습니다.

## 5. 공격명 등록부

- **관계사·공격명 관리**에서 장비별 공격명(시그니처)의 뜻을 등록합니다. 같은 장비·같은 이름만 일치로 봅니다. 비슷한 이름을 자동으로 합치지 않습니다.
- 등록되지 않은 공격명은 "확인 필요"로 남습니다. 제품별 이름을 임의로 SQL 주입 등으로 번역하지 마세요. 확정 등록에는 뜻 설명이 필요하고, 변경 이력이 남습니다.

## 6. 내부 골든셋

- 확인 및 판단 영역의 **내부 골든셋**에서 조사 하나를 바로 저장합니다. 가명화·승인자·수동 해시 입력은 필요 없습니다.
- 저장 내용: 범위와 초기 로그, 관측 사실, 초기 판단과 질문, 후속 확인과 회신, 최종 판단, 남은 확인 사항. 관계사·기간은 항상 조사에서 가져옵니다.
- 수정할 때마다 새 버전이 쌓이며, 다른 사람이 먼저 고쳤으면 저장이 거부됩니다. 접근 권한과 관계사 분리는 그대로 적용됩니다.

## 7. 장비 관측 분석을 켜려면

FW·NDR·WAF·IPS·DDoS 장비 관측 분석(대용량 전송·주기 접속·스캔 등)은 기록의 장비(출처)가 등록돼 있어야 실행됩니다.

1. 조사의 원천 문맥 탭에서 장비를 등록하고, 열 이름(시간·대응·송신/수신 바이트·세션시간)과 대응 값(허용/차단)의 뜻, 바이트의 의미를 확인 근거와 함께 적습니다.
2. 한국형 방화벽 내보내기처럼 **한 행이 끝난 세션 1건**이고 바이트가 세션 합계라면 카운터 방식을 "완료 합계"로 확인(검증) 등록합니다. 이 경우 기록 종류 열이 없어도 각 행을 완료된 세션으로 봅니다.
3. 증거에 이 장비 문맥을 연결한 뒤 처리합니다. 등록하지 않으면 전체 요약의 분석 실행 칸에 "장비(출처) 미등록으로 분석하지 않음"이 표시됩니다.

## 8. 지원 범위

- 기본 지원: 한국형 FW CSV(ko_fw), NDR CSV(ko_ndr), 일반 CSV·웹 로그 등 기존 파서. 머리글 변형, BOM, CP949/UTF-8, 따옴표, 빈 값, 잘못된 시간, 열 수 불일치를 처리하고 읽은 행·사용한 행·실패 행과 이유를 처리 작업 화면에 보여 줍니다.
- 합성 골든 표본의 `ips.jsonl`·`waf.jsonl`·`ddos.jsonl`·`web.jsonl`은 개발용 스키마이며 **기본 가져오기 지원 대상이 아닙니다.**
- 장기 비교는 주별·일별 집계와 직전 구간 비교입니다. 짧은 비교 창을 장기 정상 기준선으로 쓰지 않습니다.

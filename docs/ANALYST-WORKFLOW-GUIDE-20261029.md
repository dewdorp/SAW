# 분석가 작업 흐름 안내 — 2026-11-03 작업대 개선

이 문서는 관계사별 조사 화면의 네 작업 영역, 후속 확인 회신 대조, 내부 골든셋, 공격명 등록부의 사용 방법을 설명합니다. 모든 예시는 가상 자료입니다.

## 빠른 시작: 한 활동의 근거를 확인하려면

1. 홈에서 **NDR·FW 로그 분석**을 누릅니다. 관계사와 파일을 선택합니다. 장비 정보가 없으면 미확인 상태로 시작할 수 있습니다. 자료 귀속을 확인한 것으로 기록하려면 장비·수집 설정에서 대상과 근거를 입력합니다.
2. 작업대 **자료 현황** 맨 위 한 줄(예: "가상 B사 | 2026년 9월 5일 ~ 10월 10일 | NDR HTTP 140건 · 방화벽(FW) 164건 | 전체 304건")로 누구의 어느 기간 자료인지 먼저 확인합니다. 그 아래에서 입력 파일, 원천별 건수, 일별 추이를 봅니다. 좁은 화면에서는 **검토할 활동으로 이동**으로 바로 내려갑니다. 읽지 못한 줄이나 기록 없는 날이 있으면 **자료 확인**을 엽니다. 누락의 원인이 수집 중단인지는 추가 확인이 필요합니다.
3. **검토할 활동**은 유형별로 묶여 있고, 유형 머리에 "계산된 12개 · 현재 표시 5개"처럼 계산한 수와 화면에 보인 수가 따로 나옵니다. 더 보기로 11·12번째도 열 수 있습니다. 첫 줄은 "10.31.1.30에서 약 1분 동안 목적지 8개의 TCP 443 포트에 접촉했습니다."처럼 문장으로 읽습니다. 행을 펼치면 **관측 사실[근거 N건 보기] → 판단 범위(로그로 확인된 것과 미확인인 것) → 다음 확인** 순서이며, 선정 이유·정상 가능성·조건은 접혀 있습니다. 자료 부족·일부 계산·실패는 조건에 맞는 활동이 없었다는 결과와 다릅니다. 후보는 조사 기간과 해당 질문 조건으로 계산합니다. 상단의 원문 검색 조건은 후보 계산 조건과 별개입니다.
4. **근거 N건 보기**를 누르면 후보의 원천·기간·조건을 유지한 원문이 열립니다. 표는 주장을 입증하는 열부터 보여 줍니다(예: 확산은 시각·출발지·목적지·포트·허용/차단·장비). 직접 고른 열은 바꾸지 않습니다. 원문 위에는 조사 기간·검색 기간·근거 구간이 따로 표시됩니다. **전체 현황**으로 돌아오면 민감도·미리 보기·조건·펼친 유형·펼친 활동·목록 위치가 그 조사에 한해 그대로입니다.
5. 판단을 남기려면 **판단 남기기**, 자료가 더 필요하면 **추가 확인 요청**을 누릅니다. 추가 확인 요청은 자동 관측 기록을 연결하고 요청 초안을 바로 엽니다. 자동 첨부 근거는 사람이 직접 확인한 기록과 별도로 집계합니다.
   - 초안의 대상은 표본 20건이 아니라 계산한 그룹 전체에서 만듭니다: "출발지 1개 → 목적지 8개 · 포트 443 · 기간"과 펼쳐 보는 연결(출발지→목적지:포트) 목록. 연결이 200개를 넘거나 표본만 있을 때는 "그룹 전체가 아닙니다"라고 표시합니다.
   - 응답이 늦게 와도 먼저 입력한 칸은 덮어쓰지 않고 비어 있는 칸만 채웁니다. 주소·포트를 직접 고치면 연결 목록은 요청에서 빠집니다.
   - 초안은 원문을 보러 갔다 와도 남습니다(그 브라우저 화면에만 임시 보관). 상태는 **작성 중 · 등록 전 → 요청 등록 · 회신 대기 → 회신 수신 · 검증 전 → 검증 완료**로 구분합니다. 임시 보관은 등록이나 발송이 아니며, **후속확인 요청 등록**을 눌러야 등록됩니다. 이 기능은 외부 메시지를 보내지 않습니다.
6. 같은 유형의 기준을 조정하려면 **이 유형의 검색 조건 조정**에서 현재 로그로 미리 보고 저장합니다. 후보 밖의 자료는 **자료 현황 → 전체 로그 보기 / 전체 로그 통계**로 엽니다. 이 두 버튼은 기존 검색 조건을 해제합니다. 현재 범위에 조건을 더할 때에는 **로그 직접 검색**을 사용하세요.

## 1. 조사 만들기 — 관계사 1개 + 기간 1개

- 조사는 **관계사 하나와 조사 기간 하나**를 단위로 만듭니다. 조사 목록의 "새 조사"에서 관계사와 시작·종료 날짜를 함께 입력해야 만들 수 있습니다. 기간은 최대 400일입니다.
- 관계사가 목록에 없으면 관리자·SOC 관리자·선임 분석가가 상단 메뉴 **관계사·공격명 관리**에서 추가합니다. 관계사는 이름이 아니라 ID로 구분하므로 이름이 같은 관계사도 서로 섞이지 않습니다.
- 증거를 올린 뒤에는 조사의 관계사를 바꿀 수 없습니다. 다른 관계사 자료는 새 조사로 만드세요.
- 같은 사설 IP(예: 10.20.1.10)라도 관계사가 다르면 다른 자산입니다. IOC 조회·위협 헌팅 집계·자산 일치·연관 분석은 사설·CGNAT·링크로컬 주소를 관계사별로 나누어 보여 주며, 다른 관계사의 과거 판정을 이 조사에 합치지 않습니다. 같은 관계사 안에서도 DHCP·NAT·VPN으로 IP 사용자가 바뀔 수 있으므로 IP만으로 같은 호스트라고 단정하지 않습니다.

## 2. 네 작업 영역

조사 화면 상단에 관계사·조사 기간·실제 관측 기간이 항상 표시되고, 아래 네 영역(① 전체 현황 ② 조사 ③ 전체 로그 ④ 확인 및 판단)으로 나뉩니다. 2026-11-02부터 원본 로그 검색과 로그 통계는 ③ 전체 로그에 있습니다.

### ① 전체 현황
- **전체 요약**: 입력 행 수와 분석에 쓰인 행 수, 로그 종류별 건수, 일별·주별 추이, 기록이 0건인 날, 조사 기간 밖 기록, 시간 없는 기록, 출발지·목적지·포트·서비스·대응(허용/차단/탐지)·장비 공격명 상위 값과 "기록 없음" 건수를 한 화면에 보여 줍니다.
- 필터를 걸면 "기준: 필터 결과 N건 / 전체 M건"처럼 분모가 함께 바뀌어 표시됩니다. 분모가 조용히 바뀌지 않습니다. 장비 공격명 카드도 같은 기준의 건수를 보입니다.
- 조사 기간은 종료일 하루 전체를 포함합니다([시작, 종료일 다음 날 00:00)). 기간 밖 기록은 '이전/이후' 건수로 따로 보이고 일별 차트를 흐리게 만들지 않습니다.
- "조사 전체에 기록이 없는 날"은 수집 공백으로 확인할 날이고, "현재 검색 조건에서 결과가 없는 날"은 다른 기록이 있는 날입니다.
- 분석이 진행 중이면 "진행 중"으로 표시되고 결과가 바뀔 수 있습니다. 기간을 바꾸거나 로그를 추가·재분석하면 모든 요약이 함께 새로 고쳐집니다.
- **최근 분석 실행** 칸은 끝나지 않은 분석과 그 이유를 보여 줍니다. 예: "기록의 장비(출처)가 등록·확인되지 않아 분석하지 않았습니다." 이것은 "분석했는데 이상 없음"과 다릅니다.
- 트래픽 개요·장비·자료 의미·분석 실행 이력도 이 영역에서 엽니다. 로그 통계는 ③ 전체 로그 또는 자료 현황에서 엽니다.

### ② 조사
- **조사 제안**: 규칙이 만든 후보입니다. 각 후보에 어떤 규칙(탐지기 id·버전)이 어떤 근거로 만들었는지가 표시됩니다. 후보는 판정이 아닙니다.
- 행위·타임라인과, 필요할 때 펼치는 전문 분석(공격 흐름·관계도·HTTP·포렌식·DNS·TLS·연결·ATT&CK)이 있습니다.

### ③ 전체 로그
- **로그 검색·원문**: 후보에 없는 기록도 직접 찾을 수 있습니다. 화면 위 검색 칸에서 출발지·목적지·포트·공격명 등을 골라 검색하고, 찾은 기록을 근거로 추가할 수 있습니다.

### ④ 확인 및 판단
- 확인 항목, 후속 확인 요청과 회신, 내부 골든셋, 메모가 있습니다.

## 3. 판단 상태 5가지

조사 종료 시 다음 중 하나를 고릅니다.

| 상태 | 뜻 |
|---|---|
| 정상(승인된 업무) | 범위가 맞는 회신·근거로 업무임이 설명됨 |
| 공격 시도 확인 | 공격 요청·탐지는 확인됐지만 성공 근거는 없음 |
| 침해 확인 | 실행·변경·유출 등 성공 근거가 있음 |
| 근거 부족 | 판단할 근거가 아직 부족함 |
| 자료 품질 한계 | 수집 누락·파싱 실패 등으로 판단할 수 없음 |

공격명, 장비 위험도, HTTP 200, 방화벽 허용만으로는 침해 확인을 고르지 마세요. 처리되지 않은 후속 확인(회신 대기, 범위 불일치, 일부만 설명)이 남아 있으면 "정상"으로 종료할 수 없습니다.

## 4. 후속 확인 요청과 회신 대조

1. 확인 항목에서 후속 확인을 만들면 그 확인 기록이 가리키는 원문 기록으로 **대상(출발지·목적지·포트)**, **기간**, 질문 초안, 필요 자료가 자동으로 채워집니다. 주소나 시간을 손으로 옮겨 적지 않아도 됩니다. 저장 전에 내용을 확인하세요.
2. 회신을 받으면 회신 문서가 다루는 범위(관계사·기간·출발지·목적지·포트)를 함께 입력합니다.
3. 화면이 요청 범위와 회신 범위를 비교해 결과를 표시합니다.
   - **일치**: 회신이 확인 대상 전체를 다룹니다. "확인됨"으로 검토할 수 있습니다.
   - **일부만 설명**: 다루지 않은 부분이 "남은 질문"으로 남습니다.
   - **불일치**: 다른 관계사·기간·대상입니다. 이 회신으로 해당 행위를 설명할 수 없고 "확인됨"으로 닫을 수 없습니다.
   - **범위 미기재**: 회신에 범위가 없어 같은 행위인지 알 수 없습니다. 근거 기록을 붙여도 "확인됨"으로 닫을 수 없습니다.
   - 회신에 붙인 근거 기록도 하나씩 출발지·목적지·포트를 대조합니다. 같은 시각이어도 다른 주소·포트의 기록이면 불일치입니다.
   - 요청에 연결(출발지→목적지:포트) 목록이 있으면 회신 연결과 하나씩 맞춥니다. 목록 칸이 모두 같아도 짝이 다르면 "요청한 연결 2개 중 0개 일치"로 불일치입니다. 회신에 주소·포트 목록만 있으면 "개별 연결 미확인"으로 일부만 설명입니다.
   - "정기 점검입니다"처럼 범위 없는 회신은 회신 수신일 뿐입니다. 범위 미기재로 남고, 근거를 붙여도 "확인됨"으로 검증하거나 "정상"으로 종료할 수 없습니다.
   - 기간을 따로 적지 않은 요청은 그때의 조사 기간을 확인한 것으로 기록됩니다. 나중에 조사 기간을 넓히면 새 구간은 다시 확인해야 하며, 그 전에는 "정상"으로 종료할 수 없습니다.
4. 범위가 일치해도 회신 내용(업무인지, 공격인지)의 판단은 분석가가 합니다. 이 기능은 이메일·메신저를 실제로 보내지 않습니다.

## 5. 공격명 등록부

- **관계사·공격명 관리**에서 장비별 공격명(시그니처)의 뜻을 등록합니다. 등록한 의미는 **같은 제조사·제품(·시그니처 ID)의 기록이 유효기간 안에 있을 때만** 적용됩니다. 로그의 장비 정보나 시각을 알 수 없으면 "확인 필요"와 그 이유가 표시됩니다. 장비 정보 없이 등록한 의미는 "이름만 일치"로 따로 표시됩니다. 비슷한 이름을 자동으로 합치지 않습니다.
- 등록되지 않은 공격명은 "확인 필요"로 남습니다. 제품별 이름을 임의로 SQL 주입 등으로 번역하지 마세요. 확정 등록에는 뜻 설명이 필요하고, 변경 이력이 남습니다.

## 6. 내부 골든셋

- 확인 및 판단 영역의 **내부 골든셋**에서 조사 하나를 바로 저장합니다. 가명화·승인자·수동 해시 입력은 필요 없습니다.
- 저장 내용: 범위와 초기 로그, 관측 사실, 초기 판단과 질문, 후속 확인과 회신, 최종 판단, 남은 확인 사항. 관계사·기간은 항상 조사에서 가져옵니다.
- **최초 입력은 첫 확인 요청을 만든 시점으로 고정**됩니다. 그 뒤에 바뀐 판단, 추가한 파일·근거는 "첫 확인 요청 이후" 구역에 들어가며 최초 판단으로 옮길 수 없습니다.
- 확인되지 않음·자료 부족·일부 확인·한계 종결로 끝난 확인 요청은 "확인하지 못한 사항"에 남습니다.
- 다른 조사(열람 권한이 없는 조사)를 근거로 쓴 회신은 그 조사를 볼 수 있는 사람에게만 보입니다. 초안·저장본·과거 버전·목록 모두 같습니다.
- 수정할 때마다 새 버전이 쌓이며, 편집을 시작한 뒤 다른 사람이 먼저 저장했으면(첫 저장 포함) 저장이 거부됩니다. 과거 버전을 열면 현재본과 달라진 구역이 표시됩니다.
- 평가용 내보내기: "최초 입력만(agent-input)"과 "정답·후속 자료(evaluator-answer)" 두 파일로 내려받습니다. 같은 계보 그룹이 서로 다른 분할(학습·검증·평가)에 있으면 내보내기가 거부됩니다. 내보내기는 학습·채점을 자동으로 실행하지 않습니다.

## 7. 장비 관측 분석을 켜려면

FW·NDR·WAF·IPS·DDoS 장비 관측 분석(대용량 전송·주기 접속·스캔 등)은 기록의 장비(출처)가 등록돼 있어야 실행됩니다.

1. 조사의 원천 문맥 탭에서 장비를 등록하고 **"한국형 FW 내보내기 기본값"** 또는 **"한국형 NDR 내보내기 기본값"**을 누르면 열 이름과 대응 값이 채워집니다. 분석을 바꾸는 의미(시간이 시작·종료 중 무엇인지, 바이트가 세션 합계인지)는 장비 담당자에게 확인한 뒤 근거와 함께 "검증됨"으로 바꿉니다.
2. 한국형 방화벽 내보내기처럼 **한 행이 끝난 세션 1건**이고 바이트가 세션 합계라면 카운터 방식을 "완료 합계"로 확인(검증) 등록합니다. 이 경우 기록 종류 열이 없어도 각 행을 완료된 세션으로 봅니다.
3. **주기 접속**은 연결 시작 시각이 있어야 판단합니다. 시간 열이 "시작"으로 확인되면 그대로, "종료"면 세션시간(초)으로 시작을 추정하며(추정 표시), 둘 다 없으면 주기 접속을 판단하지 않습니다.
4. 증거에 이 장비 문맥을 연결한 뒤 처리합니다. 등록하지 않으면 전체 요약의 분석 실행 칸에 "장비(출처) 미등록으로 분석하지 않음"이 표시됩니다. 미등록 기록은 장비 관측 분석이 건수만 세고 지나갑니다.

## 8. 지원 범위

- 기본 지원: 한국형 FW CSV(ko_fw), NDR CSV(ko_ndr), 일반 CSV·웹 로그 등 기존 파서. 머리글 변형, BOM, CP949/UTF-8, 따옴표, 빈 값, 잘못된 시간, 열 수 불일치를 처리하고 읽은 행·사용한 행·실패 행과 이유를 처리 작업 화면에 보여 줍니다.
- 영문 헤더 NDR HTTP(`event_time,...,dest_ip,...,path,query,...,sc_bytes,cs_bytes`, `| # fields ` 접두 포함)와 FW(`_time,...,sent_bytes,rcvd_bytes`) 내보내기를 자동 인식합니다. 열 순서·공백·BOM·따옴표·탭 구분자 변형도 처리합니다. 쿠키는 이름만 저장합니다.
- 합성 골든 표본의 `ips.jsonl`·`waf.jsonl`·`ddos.jsonl`·`web.jsonl`은 개발용 스키마이며 **기본 가져오기 지원 대상이 아닙니다.**
- 장기 비교는 주별·일별 집계와 직전 구간 비교입니다. 짧은 비교 창을 장기 정상 기준선으로 쓰지 않습니다. 1~3개월 업무 기준선 비교는 아직 없습니다.
- 파일의 한 행이 잘못되어도(시차·날짜·포트 오류) 그 행만 실패로 표시되고 나머지 행은 처리됩니다.
- 행위 분석이 입력 상한에 걸리면 "일부만 분석: 대상 M건 중 N건 처리"로 표시됩니다.
- 원본 로그 표의 시간 열을 누르면 날짜별 건수가 보이며 "이 날로 좁히기"로 하루 전체를 검색합니다.

## 9. 네 가지 조사 질문과 필드 의미 (영문 NDR/FW)

1. 관계사와 기간을 정해 조사를 만들고 NDR/FW CSV를 올립니다. 정책·정규식·열 대응표를 쓰지 않아도 됩니다.
2. ① 전체 현황 맨 위 **확인할 질문 — 로그에서 바로 계산** 칸에서 네 질문의 상태를 봅니다.
   - A 웹 공격·영향, B 대량 전송(외부 반출 후보/다운로드 후보), C 일정 간격 반복 접속, D 여러 대상·포트로의 확산
   - 상태: 찾음 / 살펴봤으나 해당 없음 / 필드 부족으로 판단 불가(부족한 필드 표시) / 실패. **해당 없음은 정상이라는 뜻이 아닙니다.**
   - 민감도(낮음·보통·높음)를 바꾸면 기준값이 함께 표시됩니다.
3. 각 항목은 관측 사실, 판단 근거, 모르는 것, 정상 가능성, 다음 확인 질문을 보여 줍니다. **관련 로그 보기**는 그 항목의 기록만 원본 로그 표에 띄웁니다. **확인 기록 저장·요청 초안 열기**은 확인 항목을 만들고 후속 확인 요청 초안으로 이어집니다.
4. **필드 의미와 분석 연결** 칸을 펼치면 원래 필드마다 의미, 분석 연결 상태(연결/의미 확인 필요/원문 보존), 값이 있는 기록 수, 이번 분석에서의 사용·주의가 나옵니다. 바이트 방향·지속시간 단위·uuid 역할은 이름만으로 확정하지 않으므로 장비 담당자에게 확인하세요.
5. 원본 로그 표의 **NDR 기본 열**/**FW 기본 열** 버튼으로 자주 보는 열을 바로 고릅니다.
6. 같은 관계사의 이전 조사에서 확인한 장비 설정이 있으면 원천 문맥 탭의 **이전 조사의 확인된 장비 설정**에서 골라 **이 설정으로 장비 등록**을 누릅니다. 이 조사만의 사본으로 저장되며 다른 관계사 설정은 보이지 않습니다.

## 10. 질문 조건 고치기·저장·같은 범위 원문 (2026-11-02)

1. ① 전체 현황의 **검토할 활동**에서 관심 있는 행을 열고 **이 유형의 검색 조건 조정**을 누릅니다. 전체 유형은 **계산 결과와 조건**에서 수정합니다. 로그 종류, 관측창(분), 서로 다른 목적지·포트 수, 결합(또는/그리고), 포트 한정, 처리 결과, 제외할 IP를 한글 입력칸으로 고칩니다. JSON은 "고급"에서 보기만 합니다. CIDR 범위 제외는 아직 지원하지 않습니다.
2. **현재 로그로 미리 보기**는 저장하지 않은 조건을 지금 조사 자료로 실제 계산합니다. 카드에 "미리 보기 · 저장 안 됨"이 붙고, 조건 문장과 후보가 바뀝니다.
3. 카드 아래 줄은 세 가지를 따로 보여 줍니다: 조건 범위 기록 수, 계산한 그룹 수(전체·한도), 후보 중 표시한 수. "일부만 계산"이 보이면 전체 결과가 아닙니다. "조건에 맞는 기록 없음"과 "자료 부족"은 정상 판정이 아닙니다.
4. **조건 저장**: 이름·적용 범위(이번 조사 / 같은 관계사의 조사 / 공통 템플릿 — 공통은 선임·관리자만)·바꾼 이유를 적습니다. 저장된 조건은 "저장된 조건" 목록에서 다시 열고, 고치면 새 버전이 됩니다. 다른 사람이 먼저 고쳤으면 저장이 거부되니 최신 버전을 불러온 뒤 다시 고칩니다. 저장한 조건은 검색 조건이며 자동 분석이나 탐지 정책을 바꾸지 않습니다.
5. **근거 원문 보기**는 카드의 로그 종류·기간·대상 조건 그대로 ③ 전체 로그를 엽니다. 한 번에 20,000건씩 보고 "다음 20,000건"으로 넘어가며, **조건 전체 결과 CSV(서버)**는 화면에 불러오지 않은 기록까지 서버에서 만듭니다(100만 행 초과 시 그 사실을 알립니다).
6. **확인 기록 저장·요청 초안 열기**은 질문·조건·저장 버전·기간·다음 확인 전체를 확인 기록에 남기고, 후속 요청 초안과 골든 초안에 그대로 이어집니다.
7. **더 많은 예제 찾기**에서 명세 120개를 검색합니다. 각 명세는 실행 연결(가까운 질문이 계산되는지)·자료 준비·계산 상태(아직 실행 안 함)를 따로 보여 주며, 명세 자체가 실행 룰은 아닙니다.
8. NDR 쿠키 값은 이벤트 상세·주변 줄·업로드 미리보기에서 이름만 보입니다. 원문 비교가 필요하면 권한이 있는 사용자가 이벤트 상세의 원문 보기(사유 입력, 감사 기록)를 씁니다.

## 11. 분석 사례집과 내 로그 대조

홈의 **분석 사례집**에서 사례를 고르면 원본 로그, 판단에 사용한 근거, 추가로 확인할 자료, 모범 판단을 바로 읽을 수 있습니다. 사례 100개와 후속 자료 400가지를 제공합니다. 대표 행을 펼치면 원천 필드와 행 번호가 보입니다. 사례별 NDR·FW 전체 CSV도 받을 수 있습니다.

**C010 예시**. 관심 구간의 FW 24건에서 한 출발지가 목적지 8개의 같은 포트에 접속했습니다. 허용과 차단이 각각 12건입니다. 작업 회신을 받은 경우 승인 목록과 실제 목적지 8개를 각각 대조합니다. 한 서버만 승인 목록에 있으면 그 서버만 설명할 수 있고, 나머지 7개는 실행 기록을 추가로 확인합니다. 후속 자료 네 가지는 같은 초기 기록에 각각 적용하는 별개의 가정입니다.

**실제 조사에서 비교하는 방법**

1. **전체 현황 → 검토할 활동**의 **내 로그와 비교할 사례**에서 실제 관측값과 연결한 이유를 확인합니다. 자동 비교는 HTTP 응답량(C007), 방화벽 송신량(C008), 주기 통신(C009), 한 포트의 여러 목적지(C010), 한 목적지의 여러 포트(C011)를 지원합니다. 자료 부족과 일부 계산 여부는 **자동 비교 범위**에서 볼 수 있습니다.
2. **내 로그의 근거 보기**를 누르면 해당 조사·관계사·구간에 속한 실제 행을, **모범 분석 읽기**를 누르면 가상 사례의 분석 과정과 근거를 봅니다.
3. 다른 유형도 비교할 수 있습니다. 조사 활동 하나를 펼쳐 **이 활동과 사례 직접 대조**에서 참고할 사례를 고릅니다. 내 활동의 관측값과 선택한 가상 사례가 나란히 표시됩니다. **서로 대조할 항목**을 따라 원문과 회신을 확인하고 실제 조사 판단은 그 근거로 작성합니다.

사례 100개는 모두 가상입니다. 사례를 열거나 비교하면 읽기만 수행하며 조사 결과·통계·골든셋에 예제 판단을 쓰지 않습니다.

### 대량 로그에서 먼저 볼 활동 찾기

**홈 → 분석 사례집 → 63일 분석 과정 보기**에서 가상 관계사의 FW 77,300건, NDR 55,450건을 분석한 결과와 원본 행 번호를 볼 수 있습니다. **63일 원본 로그 받기**의 두 파일 `fw.csv`, `ndr.csv`를 별도 시험 조사에 넣으면 같은 분석을 재현할 수 있습니다. 조사 기간은 2026년 9월 1일~11월 2일(KST)입니다. `operations.csv`는 승인 범위 대조에, `truth.json`은 재현 결과를 검증하는 데 사용합니다.

실제 조사에서는 **전체 현황 → 검토할 활동 → 장기 로그 비교**를 누릅니다. SAW가 해당 조사에 속한 FW·NDR CSV를 읽어 최근 7일을 그 이전 8주와 대조합니다. 기간을 지정하지 않았으면 해당 원천의 마지막 관측일을 기준으로 삼습니다.

- **새 내부 목적지 접촉.** 같은 출발지·목적지 포트·프로토콜에서 이전 8주간 보이지 않은 내부 목적지가 최근 3일 이상에 걸쳐 6곳 이상 등장했고, 최근 1주의 전체 목적지 수가 이전 주간 최대를 넘은 경우를 찾습니다. 기준 기간에 해당 단말·서비스의 이력이 없으면 따로 표시합니다.
- **새 주소 범위로의 반복 송신.** 같은 출발지·목적지·서비스의 과거 FW 접촉이 없고 최근 3일 이상, 총 8 MiB 이상을 허용 송신한 경우를 봅니다. 이전 송신량을 비교할 수 있으면 같은 출발지·서비스의 외부 주간 평균 2배를 넘는 경우를 표시합니다. FW 합계와 함께 양쪽 주소·포트·프로토콜이 같고 시각 차가 5초 이내인 NDR POST·PUT 요청을 확인할 수 있습니다.
- **검토 범위.** 두 비교 구간의 각 날짜에 FW 관측이 있어야 합니다. 한 번에 250,000건까지 읽고 한도를 넘으면 전체 기준선 판단을 보류합니다. 유형별로 상위 10개 후보까지 표시합니다. 업무 승인 여부는 분석가가 별도로 대조합니다.

예제에서는 승인된 정기 스캐너와 정기 백업이 기준 기간에도 반복됩니다. 최근 새 목적지에 접촉한 두 단말 중 하나만 CHG-825의 범위와 맞습니다. 다른 단말의 허용 7건에서는 대상 서버의 인증과 공유 접근을 확인해야 합니다. 외부 송신 120 MiB의 파일·수신 계정은 FW와 NDR만으로 식별할 수 없습니다.

### 플랫폼 화면으로 조사 60건 따라보기

**홈 → 분석 사례집 → 플랫폼 분석 따라보기**에서 ID, 제목, 범주, 판단 분류로 사례를 찾습니다. **사례 범주**를 고르면 해당 범주에 속한 결과만 남습니다. 목록에는 한 번에 9건씩 표시되며, **다음 페이지**로 이동하면 그 페이지의 첫 사례가 열립니다. 처음 열리는 W07에서는 거래명세서 조회 요청과 문서 수신자를 대조합니다.

1. **조사 범위**에서 조사 기간과 FW·NDR 처리 건수를 확인합니다.
2. W01~W06의 **SAW 계산과 선정 근거**에서 SAW가 관심 활동을 고른 기준을 봅니다. W07~W60의 **경보 단서로 1차 조회**에서는 외부 경보나 담당자 제보에 나온 주소·경로 등으로 SAW 전체 로그를 조회한 조건과 일치 건수를 봅니다.
3. **원문 필터와 실제 행**에서 대상·시각·응답 등 조건을 더한 이유를 읽고 남은 원본 행을 비교합니다. CSV 행 번호에는 헤더가 1행으로 포함됩니다.
4. **추가 자료 대조**에서 같은 요청·계정·단말·시각을 서비스 감사, 단말 보안 기록, 승인 티켓 등에서 찾습니다.
5. **판단 예시**에서 어떤 행위가 확인됐는지, 결론을 바꾸려면 어떤 증적이 더 필요한지 확인합니다.

W07~W60은 같은 63일치 정상 배경 로그에 각 사건의 통신과 비교용 기록을 섞은 합성 조사입니다. 각 사례의 ZIP에서 FW·NDR 전체 원본과 해당 사건의 후속 증적을 함께 받을 수 있습니다. 화면에는 이 원본을 처리한 읽기 전용 조회 결과를 담았습니다.

**자동 후보 사례의 시작 화면**

| 사례 | 실제 조사에서 열 메뉴 | 무엇을 대조하는가 |
|---|---|---|
| W01 외부 웹 경로 탐색 | 검토할 활동 → 웹 요청 → 근거 보기 | URL 경로 수와 상태 코드, 공개 경로 및 오류 처리 방식 |
| W02 주기 통신 | 검토할 활동 → 반복 통신 → 근거 보기 | 인접 로그의 간격과 등록된 에이전트의 수신지 |
| W03 포트 점검 | 검토할 활동 → 다수 대상·포트 접촉 → 근거 보기 | 각 포트의 허용·차단과 변경 승인 포트 |
| W04 분할 HTTP 응답 | 검토할 활동 → 대량 전송 → 근거 보기 | 요청·응답 바이트 방향, 배포 명세 및 설치 영수증 |
| W05 새 파일 공유 대상 | 검토할 활동 → 장기 로그 비교 → 이 후보의 원문 보기 | 직전 8주 대비 최근 7일의 새 목적지와 자산관리 내역 |

직접 재현하려면 **이 사례 원본 ZIP 받기**를 선택하고 압축을 풉니다. 해당 사례에 표시된 기간으로 별도 시험 조사를 만든 뒤 **증거 추가**로 그 사례의 `fw.csv`, `ndr.csv`를 올립니다. W01~W04는 보통 민감도에서 **검토할 활동**을, W05~W06은 **장기 로그 비교**를 엽니다. W07~W60은 **로그 직접 검색**에서 2단계의 원천과 필터를 적용하고, 3단계의 조건과 시각 범위로 좁혀 원문 행 번호를 맞춥니다. `followup.json`에서 4단계에 제시한 증적과 같은 식별자·시각을 찾아 최종 판단과 대조합니다.

## 12. 골든셋 후보함 (0.2.5)

조사를 끝내거나 정답을 쓰기 전이라도, 나중에 골든셋으로 쓸 사례를 모아 둘 수 있습니다.

1. **담기**: 분석 사례집의 W01~W60 상세 화면, 또는 조사 화면 **④ 확인 및 판단**의 오른쪽 위에서 **골든 후보로 담기**를 한 번 누릅니다. 바로 저장되며 메모는 선택입니다(메모 남기기). 같은 사례·같은 버전은 여러 번 눌러도 한 건입니다. 조사에 증거 파일이 추가되면 새 버전으로 다시 담을 수 있습니다.
2. **후보함**: 왼쪽 메뉴 **골든셋 후보함**에서 제목, 출처(합성 예제/실제 조사), 관계사, 담은 날짜, 상태(후보/골든셋 저장됨), 분할을 보고 찾습니다. **사례로 돌아가기/조사로 돌아가기**로 원본을 엽니다.
3. **저장**: 저장할 후보만 선택하고 **선택한 후보를 골든셋으로 저장**을 누릅니다. 내부 골든 기록의 새 버전으로 저장되며 사례집 사례는 합성 표시가 붙습니다. 판단을 유보한 사례도 그 상태와 이유가 저장됩니다.
4. **내보내기**: 저장한 후보만 선택해 **선택한 저장본 내보내기**를 누르면 같은 식별자로 연결된 `agent-input.jsonl`(최초 로그·관측 사실, 중립 제목)과 `evaluator-answer.jsonl`(모범 판단·근거·후속 증거·미해결 사항)이 내려받아집니다. 선택하지 않은 후보와 다른 저장본은 들어가지 않습니다. 분할 기본값은 **미지정**이며, 같은 원본에서 나온 사례는 같은 분할이어야 내보낼 수 있습니다.
5. **빼기**: **후보함에서 빼기**는 후보 표시만 지웁니다. 원본 조사·원본 로그·이미 저장한 골든 버전은 남습니다.

후보는 로그를 복사하지 않고 원본 식별자와 버전(사례 파일 또는 증거 파일의 SHA-256)만 서버에 저장합니다. 실제 조사 후보는 그 조사를 열 수 있는 사람에게만 보이고, 열람 권한이 없으면 목록에 제목도 나오지 않습니다. 담기·저장·내보내기는 조사 판단, 확인 기록, 탐지 결과와 운영 통계를 바꾸지 않습니다.

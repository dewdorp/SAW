# 재검토 반영: 질문 범위·완전성·조건 편집 검증 (2026-11-02)

기준: PR #7(bb5c612, v0.2.2) 위 브랜치 `claude/review-scope-20261101`. 시작 시 main a6cd0a0, PR #6·#7 open, 로컬 bb5c612 일치를 다시 확인했다. 합성 자료와 격리 QA 저장소만 사용했고 운영 자료(var/objects, INV-20261008-001)·실제 계정·비밀정보·설정은 쓰지 않았다. 첨부 120개는 명세이며 SAW 실행 룰로 설치하지 않았다.

## 1. 재현하고 고친 정확성 문제

| 문제 | 재현(수정 전) | 수정 | 시험 |
|---|---|---|---|
| 카드 → 원문/확인 기록에서 기간 누락 | 원문 열기 `time:null`, 확인 기록 조회에 기간 없음 | 결과에 `scope`(조사·관계사·기간·버전·실행 시각)를 싣고 원문·확인 기록·조회에 같은 기간 전달 | `test_a_card_keeps_its_period...`, 화면 시험 |
| 로그 종류 범위 누락 | 전송 묶음은 로그 종류별로 집계하지만 카드 필터는 src/dst만 | 모든 카드 필터에 조건의 로그 종류(+전송은 해당 종류) 포함, 재조회 건수 = 카드 건수 | 같은 쌍의 NDR·FW가 별도 항목, 각 재조회 일치 |
| bytes_in/out 이중 계산 | 두 방향 값이 있는 행을 두 번 셈(NDR 12행 → 24) | 합집합 계산(in + out − 둘 다) | 12+3 = 15건 |
| 전체·계산·표시 혼동 | 그룹 200/500, 표시 10개 한도를 구분하지 않음 | `records`(조건 일치 고유 기록)·`examined`(계산한 그룹/전체/한도, 시간순 계산 수)·`found`/`shown`·`completeness`(complete/partial)+이유 | 한도 1로 낮춰 partial·이유 확인, 표시 한도는 complete 유지 |
| 일치 없음 vs 자료 부족 | 조건이 모두 제외해도 "자료 부족" | `no_match`(조건에 맞는 기록 없음)와 `insufficient_data`(필드 없음) 분리 | 출발지 전부 제외 → no_match |
| 원문 20,000행 누적 한도·불러온 행만 내보내기 | 더 이상 탐색·전체 내보내기 불가 | cursor 구간 이동(한 번에 20,000건, 이전 구간은 메모리에서 해제)과 서버 전체 CSV 내보내기(5,000건씩 기록, 100만 행 한도와 초과 시 헤더 표시) | 구간 이동 cursor, 내보내기 60/60건 |
| 질문 결과 기록 시 첫 질문만 남음 | 다음 확인 첫 줄만 메모 | 확인 기록 `scope.origin`에 질문·조건·매개변수·실행 범위·완전성·항목 전체 저장, 후속 요청 초안과 골든 초안까지 전달 | origin 저장·후속 요청 needed_data·골든 사실 문장 |
| 원문 화면의 쿠키 값 노출(이번에 발견) | 이벤트 상세·주변 줄·업로드 미리보기에서 `sid=값` 표시 | 표시 경로에서 쿠키 이름만 남김(파일 머리글로 열 위치 확인, 확인 못 하면 줄 가림). `data.unmask` 권한자는 사유 기록 뒤 원본 줄 열람 | 상세·주변 줄·미리보기 가림, 권한자 원문, 분석가 403 |

v0.2.2 문서의 "쿠키 값은 원문 표시에 넣지 않는다"는 정규화 필드에만 맞았고 원문 표시 경로는 틀렸다. 이번 수정으로 바로잡았다.

## 2. 대표 흐름(Q06 여러 대상·포트 접촉)과 조건 편집

- 한 구조화 조건 정의(`question_bundles.PARAMS`)가 한글 문장(`describe`), 입력 검증(`validate`, 한글 오류), 실제 실행(`run_one`), 저장값을 모두 만든다.
- Q06 조건: 로그 종류, 관측창(분, 0=조사 기간 전체), 서로 다른 목적지 수, 포트 수, 결합(또는/그리고), 목적지 포트 한정, 처리 결과, 제외 출발지·목적지 IP. 관측창은 출발지별 시간순 기록에서 이동 구간의 최대 고유 목적지를 정확히 계산한다.
- 같은 정의 구조로 A 웹(경로 수·패턴 사용·제외), B 전송(MB·방향·제외), C 반복(기록 수·변동계수·포트·제외)도 편집·미리 보기·저장된다.
- CIDR 범위 제외는 아직 지원하지 않으며 입력하면 그 이유를 한글로 거부한다.

조건 변경이 실제 결과를 바꾸는지(`test_editing_the_condition_changes_what_is_computed`):

| 조건 | 결과 |

| 같은 조건 + 관측창 10분 | 빠른 확산만("10분 안에 목적지 15개") |
| 포트 4개 이상 | 빠른 확산(4개 관리 포트)만 |

## 3. 저장·버전·충돌

- 저장된 질문 조건(`kn_question_preset` + 버전 표, 마이그레이션 0025는 추가만 하는 멱등 변경): 적용 범위 이번 조사 / 같은 관계사의 조사 / 공통 템플릿(선임·관리자만).
- 저장 전 미리 보기와 저장 후 실행이 같은 결과(상태·건수·항목·조건 문장·완전성)를 내는 것을 확인했다. 이전 버전으로도 실행할 수 있다.
- 오래된 화면에서 고치면 409로 거부하고 화면은 "최신 버전 불러오기"를 보인다. 버전 목록과 마지막 변경(이전→이후 값)을 돌려준다.
- 저장한 조건은 검색 조건이며 자동 분석·탐지 정책을 켜거나 바꾸지 않는다(화면에 명시).

## 4. 화면 구성

- 기본 작업 영역: ① 전체 현황(확인할 질문 포함) ② 조사 ③ 전체 로그(전체 로그·원문, 로그 통계) ④ 확인 및 판단. 전문 분석은 ② 조사에서 펼친다.
- 기본 질문 10개(Q01~Q10)를 실행 연결(엔진 연결됨 4개, 전체 현황에서 확인 1개, 연결 안 됨 5개)·자료/계산 상태·필요한 것과 함께 표시한다.
- "더 많은 예제 찾기": 첨부 명세 120개 검색. 각 항목은 실행 연결(자체 실행기 없음·가까운 계산 Qxx / 명세만), 자료 준비(제공 필드·장비 설정 확인·추가 로그 + 이 조사에 없는 자료), 계산(아직 실행 안 함)을 따로 보인다. 62개가 기본 질문에 연결되어 있다.
- 작은 창(높이 760px 이하)에서는 작업대가 내용만큼 늘어나고 페이지가 스크롤되어 아래 이벤트 상세 영역이 카드 버튼을 가리지 않는다.

## 5. 공격명 사전

장비 공격명 등록에 로그 원천, 장비 처리값, 관측하는 것, 입증하지 못하는 것, 필요한 후속 자료, 연결할 조사 질문(Q01~Q10), 특정 관계사 예외를 추가했다(기존 버전 이력 유지, 추가 필드는 JSON이라 마이그레이션 없음). NDR24·FW13에는 공격명이 없으므로 만들어 넣지 않는다.

## 8. 미검증·경계

- 대상 Windows LTSC 2019(17763) 설치·업데이트·복구는 PENDING_ENV, 운영 서버는 업데이트하지 않았다.
- OpenSearch/PostgreSQL native 실행, 대용량(10만~100만 건)에서 관측창 계산·서버 내보내기 시간은 측정하지 않았다. 관측창 계산은 출발지당 20,000건까지 읽고 넘으면 partial로 표시한다.
- 20개 사례·80개 후속 경로는 제품에 가져오지 않았다. 내부 골든의 계보 분할 거부(F11)는 기존 기능을 유지한다.
- Q02·Q03·Q07·Q08·Q09는 계산 연결이 없고 필요한 자료·구현을 표시한다.

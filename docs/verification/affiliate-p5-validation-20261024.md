# P5 검증 기록 — 소스 검증 완료·최종 매체 제작 전

**2026-10-25 갱신. 최종 소스의 검증 기록이며 새 설치 매체나 운영 인수의 완료 선언이 아니다.** 최종 수정 검토, 실제 저장소의 선별 통합 시험, 웹 검사, 취소 조회·패턴 처리·SQLite 커서 보완과 제한된 성능 재측정 결과를 반영했다. 커서 보완 후 pilot-r4가 완료됐고 matrix-r3의 1천·10만 건 결과가 일치했다. 100만 건은 PARSING 중 QA 대기 한도에 도달해 job_wait_timeout으로 종료됐다. 전체 행렬은 NOT_PASS이며 최종 전체 서버 r3는 2628통과·13건너뜀으로 완료됐다. 소스 검증은 완료됐고 새 매체·게시 절차는 NOT_RUN이다. 이전 matrix-r2의 진단 중단 이력은 보존한다.

모든 검증은 합성 자료를 사용했다. 아래 시험 수는 각각의 실행 결과이며 서로 더해 한 번의 전체 통과로 표시하지 않는다.

## 수정과 독립 검토

최종 수정 묶음은 이전 PCAP 추출 파일의 정확한 소유권·보존·삭제, 접근 가능한 자동 규칙의 후보 한도, 검토함·지원 요청의 현재 조사 권한 확인을 보완했다. 삭제 중 조사 처리 순서까지 고친 freeze revision 2에서 I1–I3가 해결됐다. 관련 82건과 마지막 받은함 27건은 각각 통과했다. 기존 전체 검토와 해당 수정 재검토는 종료됐으며 이번 문서 갱신에서 다시 검토하지 않았다.

취소 조회는 작업 실행마다 별도로 최대 0.2초 동안 직전 결과를 재사용하고, 분석기 전후와 실패 처리 경계에서 새로 확인한다. 원천 권한·세대·최종 결과 게시 검사는 유지한다. 집중 21건과 이를 포함한 관련 145건이 통과했고 독립 검토에서 조치할 결함이 남지 않았다. 콜백의 취소 감지에는 최대 0.2초와 기존 차단 작업만큼 지연이 가능하며 취소 완료 시간을 보장하지 않는다.

패턴 처리는 서버가 검증한 완전한 연결 관측만 중복 자유문장 분석에서 제외한다. 불완전하거나 검증되지 않은 자료는 기존 텍스트 분석을 유지한다. 조사 행 수 50,000개 상한도 유지한다. 첫 55건과 최종 관련 155건이 각각 통과했으며 후자는 추가 경계 시험을 포함한다. 독립 검토도 승인됐다. 빈 패턴 결과의 표본 표시와 저장·API의 조사범위 표시가 이번 수정으로 해결됐다는 주장은 하지 않는다.

SQLite 커서는 기존 정렬 순서를 유지하면서 다음 페이지를 같은 시각·이후 시각의 두 범위로 읽고, 바깥 정렬 대상을 최대 두 배치로 제한했다. 최초 관련 206통과·2건너뜀 뒤 독립 검토에서 매개변수 중복으로 기존 필터 용량이 줄어드는 **P2**가 나왔다. 실제 SQLite 한도를 낮춘 시험에서 3실패를 재현하고 공통 매개변수를 재사용하도록 보완했다. 최종 **209통과·2건너뜀**과 재검토 **APPROVED**를 확인했다. 집중 26건은 209건에 포함한다. 두 건너뜀은 전용 OpenSearch URL이 필요한 시험이다.

최초 커서 보완의 작은 실제 SQLite 진단에서 1만 건 순회 명령 수는 시각 그룹 입력의 3,509,000 → 411,100회, 동일 시각 입력의 3,885,300 → 320,900회였다. 입력 건수·순서 지문은 같았다. 이 값은 실제 PostgreSQL/OpenSearch 지연의 원인 비율이나 성능 개선을 입증하지 않는다. 기존 읽기 전용 세대에는 새 인덱스를 추가하지 않아 기존 성능 한계가 남고, 쓰기 가능한 저장소의 첫 인덱스 생성·저장·쓰기 비용은 별도 측정하지 않았다.

개발 중 실패, 취소된 전체 서버 r1/r2, 이전 성능 중단 기록은 보존한다. 후속 통과로 과거 실패를 지우지 않는다.

## 최종 전체 서버와 개발기 환경

전체 서버 r3는 **2628통과·13건너뜀·실패0·오류0**, 기존 경고2건으로 완료됐다. JUnit2486.955초·pytest2487.00초·실행기2510.516초이며 exit0이다. 소스663파일과 웹 빌드16파일은 동결 기준에서 변경되지 않았다.

건너뜀은 PostgreSQL URL 미지정5건, OpenSearch URL 미지정3건, 명시적 native PostgreSQL 바이너리 경로 없음3건, Windows 심볼릭 링크 불가1건, POSIX 권한 비트1건이다. 이13건을 별도 native 성공으로 바꾸지 않는다. 아래50·15·9·10건은 각 시점의 별도 선별 실행이다. 경고는 기존 Starlette/httpx 지원 중단 예고와 record_property의 xunit2 비호환이다.

실제 개발기는 **Windows11 Pro build26200·Core i5-12600·물리메모리 약32GB·Python3.12.10**이다. LTSC17763·물리16GB 환경의 검증이 아니다.

커밋 직전 공백 검사에서 새 시험 파일 하나의 끝 빈 줄 2바이트를 제거했다. 실행 코드와 웹은 바뀌지 않았고 해당 Python 시험의 AST가 동일함을 확인했다. 이 서식 정리 뒤 관련 9건이 통과했다(4.46초); 전체 2,628건에 더하지 않는다. 포장용 최종 동결은 p5-packaging-source-freeze-20261025.json이며 원래 전체 시험 동결과 서식 변경 영수증을 함께 보존한다.

## 성능 재측정

아래 계측과 pilot-r3·matrix-r2는 모두 SQLite 커서 보완 전 실행이다. 같은 생성기·프로필 의미를 사용한 별도 직렬 실행에서, 입력 SHA256·크기와 확인한 이벤트 건수가 앞뒤로 같았다. 다음은 계측을 넣은 진단 결과다.

| 합성 입력 | 자동 처리 전 → 후 | 취소 상태 SQL 조회 전 → 후 | 확인 이벤트 |
|---|---:|---:|---:|
| 1,000건 | 16.2031 → 8.5464초 | 12,689 → 10회 | 앞뒤 1,000건 |
| 10,000건 | 136.7337 → 38.2292초 | 126,790 → 42회 | 앞뒤 10,000건 |

1만 건의 분석기 단계는 88.3855초에서 8.1837초, 패턴 단계는 19.5191초에서 1.5138초로 줄었다. 각 구간은 중첩될 수 있으므로 시간을 더하지 않는다. 프로필 ID는 실행마다 다르고 OS 캐시를 강제로 비우지 않았다. 이 결과는 일반 성능 목표(SLO), 물리 16GB 환경, 10만·100만 건 수용성의 통과 근거가 아니다.

후속 **pilot-r3**은 저장 1,000건에 대해 요청자 1명·3명 모두 공개 결과 정확성 검사를 통과했다. 각 분석은 1,000레코드·330세션·차단 10건·후보 1개이며 표시 100세션·생략 230세션도 일치했다. 행별 경과시간은 11.6931초·14.6662초이고 전체 실행은 107.9523초였다. 행 시간은 전체 적재 시간이나 단일 분석기 시간과 다르다. 소유 프로세스 종료와 포트 닫힘을 확인했다. OpenSearch는 flush 후 소유 핸들 종료 방식이므로 JVM의 정상 자발 종료로 표현하지 않는다.

pilot-r3의 최종 상태는 **MATRIX_FINISHED_ACCEPTANCE_INCOMPLETE**다. 10만·100만 건은 이 파일럿에서 실행하지 않았다. API 결과 상한으로 전체 최종 바이트 합계가 노출되지 않고, 폴링은 정확한 영속 작업 배정 계측이 아니며 디스크 스냅샷은 중간 최고점을 보장하지 않는다. 부하 중 관측 요청 6건·29건은 기능·상태별 성공 표본 30개를 충족했다는 뜻이 아니다. 공정한 배정·취소·복구·독립 동시 적재의 성능 인수도 남아 있다.

이전 **matrix-r1**은 10만 건 색인 뒤 분석 지연을 진단하려고 950.879초에 협조 중단했다. 이 실행은 **NOT_PASS**로 보존한다.

후속 **matrix-r2**는 1천·10만 건 모두 1명·3명 요청의 공개 결과 정확성 검사를 통과했다. 10만 건 적재는 이벤트 100,000건·실패 0·거부 0이며, 각 분석은 33,000세션·차단 1,000건·후보 100개와 일치했다. 표시 100세션·생략 32,900세션도 일치했다.

| 입력·요청자 | 행 경과시간 | 각 분석 실행시간 |
|---|---:|---|
| 1천 건·1명 | 13.3815초 | 1.719초 |
| 1천 건·3명 | 16.7810초 | 1.515 / 1.500 / 1.500초 |

100만 건은 적재를 시작했지만 완료 전에 소유 실행기에 협조 중단을 요청했다. 읽기 전용 SQLite 실행 계획에서 페이지 정렬에 임시 B-tree를 반복 사용하는 경로를 확인했기 때문에, 좁은 합성 재현으로 인과를 분리하기 위한 진단 중단이다. 이 경로의 실제 소요시간 기여도나 실제 저장소에서의 수정 효과는 아직 확인하지 않았다.

matrix-r2 전체 시간은 **1,534.358339초**, 최종 driver 상태는 **FAILED_OR_STOPPED**, 진단 기록은 **DIAGNOSTIC_STOP_REQUESTED_NOT_PASS**다. 소유 프로세스 종료와 포트 닫힘은 확인했지만 전체 행렬은 완료하지 않았다. 완료한 10만 건 결과를 100만 건 지원이나 전체 성능 인수로 확대하지 않는다. 이후 SQLite 커서 보완·재검토와 pilot-r4는 완료됐다. 아래 matrix-r3도 별도 실패 기록으로 종료됐다. 최종 전체 서버 시험은 통과했으며 매체 인수는 미실행이다.

커서 보완 후 **pilot-r4**는 1천 건의 1명·3명 요청에서 **EXPOSED_CORRECTNESS_PASS**를 확인했다. 전체 105.144617초·driver exit0·종료·포트 닫힘이며, 최종 분류는 **MATRIX_FINISHED_ACCEPTANCE_INCOMPLETE**다. 파일럿 성공을 전체 행렬·용량 인수로 확대하지 않는다.

같은 제품 지문의 **matrix-r3**는 1천·10만 건의 1명·3명 네 행을 완료했다. 모두 공개 결과 정확성 통과이며 10만 건은 33,000세션·차단 1,000건·후보 100개와 일치했다. 10만 건 행 시간은 1명 40.2055162초·3명 97.9008946초이고, 3명 각각의 분석 실행은 39.234 / 28.577 / 29.327초다.

**이 시간은 적재가 끝난 자료의 별도 범위 분석이다.** 1명 분석 자체39.796초와 행40.2055162초·3명 행97.9008946초에는 파일 업로드·파싱·색인·최초 자동 분석 시간이 포함되지 않는다. 앞서 실행한10만 건 적재 Job의 기록된 시작→완료는 **571.535131초**로, 파싱·색인·자동 분석을 포함하고 파일 업로드와 Job 시작 전 대기는 제외한다. QA의 접수 관측→완료 관측은571.682644초이며 폴링 지연을 포함하므로 정확한 작업 배정·실행 시각과 구분한다. 이 기록으로 단계별 병목 비율이나 최적화 인과를 추정하지 않는다. 100만 건은 **PARSING** 상태에서 QA 실행기의 적재 Job 대기 기본값 **900초**를 넘겨 **job_wait_timeout**으로 종료됐다. 이는 제품의 범위 분석 예산 **120초**와 별개이며, 이 실패를 제품 자료 손상이나 100만 건 지원의 근거로 판단하지 않는다. 네 완료 행도 **INCOMPLETE_SEAMS_REMAIN**이므로 전체 성능 인수는 **NOT_PASS**다.

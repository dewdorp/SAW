# 기존 설치의 의존성 추가·복구 검증

기존 0014 설치를 현재 0023 패키지로 업데이트할 때 필요한 XlsxWriter 3.2.9의 추가 경로를 보완했다. 사용자가 따로 Python 패키지를 설치하거나 인터넷에 접속할 필요가 없도록 설치 매체 안의 정확한 wheel만 사용한다.

## 확인한 오류와 수정

- 기존 코드는 런타임 목록의 변경을 전부 거부했다. 실제 이전·현재 매체 비교에서 requirements 한 줄과 XlsxWriter wheel 한 개만 추가된 것을 확인했다. 이 정확한 전이만 허용하며, 다른 의존성 변경·삭제·버전·크기·지문 불일치는 거부한다.
- 적용 전에는 기존 설치, 적용 후에는 새 패키지, 복구 후에는 검증된 전체 복구본의 실행 환경을 확인한다. 아직 추가되지 않은 의존성을 적용 전부터 요구하거나 복구 후에 다시 요구하지 않는다.
- 전체 정지 백업과 검증이 끝난 뒤 의존성을 별도 준비한다. 완성된 파일의 내용과 접근 권한을 확인하고 같은 볼륨에서 원자적으로 반영해, 복사 중단으로 잘린 파일이 실행 경로에 남지 않도록 했다.
- 소유권 기록의 requirements 지문과 설치 RECORD를 실제 경로에 맞게 갱신한다. 이후 애플리케이션 교체나 기록 게시가 실패해도 명시적인 전체 복구가 가능하도록 정확한 일부 추가 상태만 인정한다.
- 새 설치 기록이 있는 상태에서 구형 복구본의 원래 매체 경로를 잃던 화면 제어 오류도 수정했다. 필수 실행 환경 기록이 없으면 서버 중지 전 점검에서 거부한다.
- 종료 중인 자식 프로세스의 종료 요청이 거부되는 경우에는 같은 핸들에서 기존 30초 범위 안의 실제 종료를 확인한다. 살아 있는 대상·시간 초과·확인 실패를 성공으로 바꾸지 않는다.

## 검증 구분

실제 종료 요청 거부 뒤 자연 종료하는 Windows 계약 시험, 화면 제어의 적용 전·복구 후 프로필 선택, 구형 복구본 경로 보존, 의존성 준비 실패와 일부 반영 후 전체 복구를 각각 시험했다. 독립 코드 검토에서 발견한 부분 복사·구형 baseline·사전 marker 검사 문제를 보완했다.

최종 전체r7 PASS: 2868통과·14건너뜀·실패0·오류0·경고2, JUnit3818.044초·실행기3841.344초. 675소스 변경목록[]이며 건너뜀 대상은r5와같다. 새 매체 인수는 진행 전이다. 중단한 r6는 870개 call 통과 관측·실패 관측 0이지만 전체 완료가 아니므로 PASS가 아니다. 이전 r5의 결과를 이번 소스의 결과로 사용하지 않는다.

새 매체에서는 신규 설치와 재개, 계정·MFA·자료 읽기, 0014 업데이트, 실패 후 전체 복구, 나중에 추가된 자료의 별도 보존, 재시작 및 합성 CSV 분석을 다시 검증한다. 설치된 Python의 실제 Excel 생성과 복구 후 의존성 제거도 별도 확인한다. 준비된 시험 코드와 실제 실행 결과를 구분한다.

## 적용 범위

원본 Claude 작업공간, 운영 설치, 사용자 계정·운영 자료, 기존 릴리스는 변경하지 않는다. Windows 11 개발기에서의 확인을 깨끗한 LTSC 2019 빌드 17763·물리 16GB·관리자 서비스·재부팅·폐쇄망 운영 인수로 확대하지 않는다. 모델 가중치와 모델 추론·학습 검증은 이번 모델 제외 설치 매체의 범위 밖이다.

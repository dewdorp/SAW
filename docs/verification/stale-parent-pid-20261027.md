# Windows 부모 프로세스 번호 재사용 — 수정·검증 진행 중

현재 상태는 **수정 및 회귀 검증 중**이다. 새 설치 매체의 전체 인수 또는 릴리즈 게시가 완료된 상태가 아니다.

## 실제 재현

- 소스 6c4d0f3의 동일 r4 매체로 Windows Temp 밖의 새 a6 합성 설치를 실행했다.
- 42단계 중 앞선 15단계(계획된 DB 포트 차단 1회 포함)는 완료했다. 실제 설치 재개, MFA, 정상 종료·재시작, 전체 백업, 전체 복원, 복원 후 계정·자료 비교가 통과했다.
- 16번째 standalone-backup-final-stop에서 process_identity_unverified로 실패했다. 종료 호출 전에 실패했으며 원래 실패 기록을 보존했다.
- 별도 읽기 전용 재현에서 WindowsController.claim의 자식 분류 거부 분기를 확인했다.
- 조회 전용 커널 핸들로 두 실행 파일의 정체성과 생성 시각을 확인했다. 자식으로 표시된 외부 프로세스는 현재 PostgreSQL 부모보다 14,591.8320164초 먼저 생성됐고, 두 프로세스 모두 실행 중이었다. 다시 조회해도 부모 번호와 이미지 연결은 같았다.
- 이 결과는 Windows가 종료된 부모의 번호를 재사용한 뒤, 오래된 외부 프로세스의 부모 번호가 새 PostgreSQL 프로세스를 가리키게 된 경우다. 원문 명령행·PID·경로·자격증명은 보고하지 않는다.

## 수정 범위

독립적으로 소유권을 확인한 부모의 기존 커널 핸들을 먼저 보존한다. 분류할 수 없는 설치 외부 프로세스만 조회 전용 핸들로 조사한다. 실제로 부모보다 먼저 생성된 외부 프로세스라는 증명이 있을 때만 종료 대상에서 제외한다.

원래 종료 대상의 핸들을 다시 PID로 열지 않는다. 외부 프로세스의 증명 핸들은 종료 권한 없이 별도로 보존한다. 불분명한 이미지·생성 시각, 내부 경로 별칭, 같은 시각 또는 나중에 생성된 자식, 조회 실패, 살아 있지 않은 대상, 두 번째 조회의 부모·이미지 변화는 계속 거부한다. 서비스 방식의 기존 동작은 확대하지 않는다.

## 검증 순서

1. 동일 결함의 회귀 시험이 수정 전 실패하는 것을 확인한다.
2. 최소 수정과 기존 부모·콘솔·PostgreSQL·PID 재사용 방어 시험을 실행한다.
3. 실제 a6 설치에서 수정 코드로 읽기 전용 소유권 확인을 수행한다.
4. 소유권·핸들·검색 flush·PostgreSQL 정상 종료 절차로 실제 종료를 검증한다.
5. 전체 서버 검증과 독립 검토를 마친 후 새 매체를 생성한다.
6. 새 매체로 설치·업데이트·복구 전체 및 설치 CSV를 확인한 뒤 비공개 초안 PR과 사전 릴리스를 게시한다.

현재 단계별 최종 결과는 진행 기록에 추가한다. 이전 r7의 2868통과 결과를 이번 수정 소스의 통과 결과로 재사용하지 않는다.

## 별개로 유지하는 한계

a5의 공개 OpenSearch 런타임 파일 소실 원인은 미확정이다. 임시파일 정리 작업과 시각상 관련성이 있으나 삭제 주체를 확정하지 않았다. a5는 별도 소유권 검증 후 정상 종료했지만 원래 인수 결과는 실패로 유지한다.

깨끗한 LTSC 2019 빌드 17763, 물리 16GB, 관리자 서비스·재부팅·실제 폐쇄망 공동 접속, 100만건 성능, 과거 History503·권한 조회 오류 원인은 별도 인수 범위다. 모델 가중치는 제외하며 실제 추론·학습 성공을 주장하지 않는다.

## 2026-10-27 실제 수정 후보 확인

- 최종 수정 후보의 읽기 전용 claim 통과: 원매체 전체 런타임·설정·ACL, noadmin, 소유 리스너 검사와 소유 핸들 11개를 확인했다. 종료 호출은 없었다.
- 같은 가드를 다시 검사한 실제 정상 종료 1회가 통과했다. 원래 controller.stop의 검색 flush·PostgreSQL 종료를 수행했고, 포트 4개 해제와 PostgreSQL PID 기록 제거를 확인했다. 재시도는 없다.
- 종료 기록은 WORKTREE_CANDIDATE_NOT_RELEASE로 분리한다. 원래 a6의 FAIL 기록은 그대로이며, 새 매체의 전체 42단계 인수 결과로 바꾸지 않는다.
- 두 독립 읽기 전용 코드 검토에서 추가 P1/P2 지적은 없었다. 핵심 소스의 desktop 94건 통과 뒤 최종 경로 제한을 보완했고, 최종 관련 29건은 통과했다. 최종 전체 서버 r8은 2889통과·1실패였다. 실패는 부하 속 컨테이너 교체 시험의 5초 대기 초과였고 단독 반복은 통과했다. 그 대기만 30초로 늘린 r9가 2890통과·14건너뜀·실패0으로 통과했다.

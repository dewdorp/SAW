# 업무 의미 지식과 흐름 분석 검증 — v0.2.6 (2026-11-12 ~ 11-13)

기준: v0.2.5(PR #13, `claude/golden-candidates-20261104`) 위 브랜치 `claude/flow-knowledge-20261112`. 설계와 선택 이유는 [ADR-0019](../adr/0019-flow-knowledge-and-state-analysis.md), 사용 순서는 [분석가 작업 흐름](../ANALYST-WORKFLOW-GUIDE-20261029.md) 13절.
합성 자료와 격리된 시험 저장소만 썼다. 운영 서버·운영 자료·실제 은행 자료(`var/objects`, `INV-20261008-001`)·기존 매체와 태그는 바꾸지 않았다.

## 1. 구현한 것과 확인 방법

| 요구 | 구현 | 확인 방법 |
|---|---|---|
| 본 자리에서 의미 저장 | 기록 상세 "메모하고 기억하기", 업무 흐름의 "업무 의미 등록"·"의미 기억하기"·"이 순서를 흐름으로 기억하기" | 화면 시험 |

| 재분석과 이전 결과 | 지식·기록이 바뀌면 "최신이 아님", 다시 분석하면 새 실행 + 달라진 지식·흐름·이유, 이전 실행 보존 | 서버·화면 시험 |

고친 것(측정 중 발견)
- 페이지 커서로 읽으면 저장소가 페이지마다 남은 기록을 다시 정렬해 10만 행에 88초가 걸렸다 → 한 페이지에 들어가는 시간 구간으로 나눠 읽어 41.6초.
- 분석이 도는 동안 조사 잠금을 잡아 다른 화면 응답이 멈췄다 → 계산 중에는 데이터베이스를 잡지 않고, 결과만 짧게 기록.
- 오래 조용한 세션은 중간에 흐름으로 정리해 메모리가 활성 세션 수를 따르게 했다(결과는 동일, 시험으로 확인). 위 100만 행 측정은 이 변경 전 코드로 잰 값이다.

측정하지 못한 것
- **100만 행의 제품 경로(업로드 포함)**: 이 PC에서 10만 행 업로드·기존 탐지 단계만 약 20분(NDR 1,241초)이 걸려 실행하지 않았다.
- native OpenSearch/PostgreSQL 구성, 대상 LTSC 2019·16GB 서버.
- 10만 행 업로드에서 **기존 탐지 단계(공격 스토리)가 한도 오류(`derived_source_scope_limit`)로 실패**했다(FW·NDR 업로드 2건). 이번 변경의 코드가 아니라 기존 한도이며 고치지 않았다. 기록은 색인됐고 흐름 분석은 그 단계와 분리해 먼저 저장하도록 바꿨다. 이 한도는 따로 검토가 필요하다.

## 6. 0.2.5에서 "사례가 반영되지 않고 예전 자료만 보인다"

확인한 사실
- 0.2.5 매체에는 분석 사례 60개 파일(JSON·그림·ZIP)이 들어 있고, 설치 리허설 a18에서 60/300/120/60을 세 번 확인했다.
- 0.2.5 화면의 **왼쪽 메뉴에는 "분석 사례집" 항목이 없었다.** 홈 화면 오른쪽 위 단추로만 들어갈 수 있었다. 0.2.5 운영 절차 문서는 "왼쪽 메뉴"라고 잘못 적었다(정정함).
- 업데이트 전에 열어 둔 브라우저 화면은 이전 화면 파일로 계속 동작한다. 새로 고치지 않으면 홈 단추가 "가상 로그 예제"로 남고 예전 예제(C001~C100)만 보인다.
- 실제 설치 환경에서 어느 쪽이었는지는 확인하지 못했다.

고친 것
- 왼쪽 메뉴에 **분석 사례집**을 넣었다.
- 서버 버전과 열린 화면의 버전이 다르면 화면 위에 새로 고침 안내가 뜬다.
- 사례집 맨 위와 왼쪽 메뉴 아래에 앱·화면·사례 콘텐츠 버전을 표시하고, 추가·변경 내역과 이유를 보여 준다. 사례 목록과 파일 수가 맞지 않으면(일부만 적용) 알린다.
- 사용자 메모·조사·판단·등록한 지식은 업데이트로 바뀌지 않는다(표 추가만).

## 7. 경계(미검증·제한)

- PENDING_ENV: 대상 Windows 10 Enterprise LTSC 2019에서의 설치·업데이트, 관리자 서비스·재부팅. 이번 변경으로 새 매체를 빌드하거나 설치 리허설을 하지 않았다.
- WAF·IPS·DDoS·애플리케이션 입력은 열 이름을 정한 가상 프로필이다. 실제 벤더 내보내기와 대조하지 않았다.
- Logpresso 실연동은 접속 정보가 없어 구현·검증하지 않았다(기존 모의 연결만 있음).
- 로컬 모델(Foundation-Sec-8B)은 쓰지 않는다. 문장에서 초안을 뽑는 것은 규칙 기반이며, 모델을 쓴 제안은 구현하지 않았다.
- RAW_DATA는 원문 그대로 보존·표시하고 잘림 여부만 기록한다. 인코딩 해석·디코딩 결과의 별도 보존은 기존 요청 분석 기능에 있으며 흐름 화면에는 연결하지 않았다.
- 0.2.5 이전에 올린 NDR 자료에는 연결용 참조가 없어 재처리해야 세션으로 묶인다.
- 흐름 실행은 요청 처리 중에 계산한다. 브라우저를 닫아도 결과는 저장되지만, 서버가 그 사이 재시작되면 그 실행은 남지 않는다(업로드 뒤 자동 실행은 작업 큐 안에서 돈다).
- native OpenSearch에서는 실행하지 않았다.

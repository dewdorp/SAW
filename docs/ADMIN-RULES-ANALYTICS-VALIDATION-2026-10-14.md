## 실제 사용자 흐름

브라우저에는 별도 합성 조사 2,080건(정상 2,000건 + 이상 표본 80건)을 넣었다. 준비 영수증은 `.qa/features-20261014/browser/ready.json`이다. 아래 화면 관찰은 이번 작업의 브라우저 조작 기록을 근거로 하며, 관리자 최종 삭제는 별도 HTTP 실행과 구분한다.

관리자 삭제는 별도 가상 대상에 실제 로컬 HTTP로 실행했다. 케이스 폐기·증거 묶음 삭제·조사 삭제의 영수증 3개가 모두 COMPLETED였다. 증거의 이벤트 5건을 삭제한 뒤 같은 조사의 나머지 5건은 유지됐고, 이어 조사 전체를 삭제한 대상은 404를 반환했다. 무관한 주 조사 2,080건은 보존됐다. 감사·인계·처리 이력과 케이스 스냅샷·리비전은 보존 대상이며 완전 소거로 보고하지 않는다.

근거: `.qa/features-20261014/browser/live-deletion-receipt.json` (`REAL_LOCAL_HTTP`, `browser_final_delete_clicked=false`). 브라우저·HTTP 흐름은 로컬 SQLite 시험 인스턴스에서 수행했으며, 위 PostgreSQL·OpenSearch 시험과 서로 다른 실행이다.

## 실패 발견과 재검증

- 최초 실제 PostgreSQL·OpenSearch 실행은 **2 FAIL, 31 PASS, 1 SKIP**이었다. 정상 압축 해제 파일의 기존 저장 키를 삭제 계획이 거부했고, 일반 분석가가 케이스의 예약 상태 `deleting`을 설정할 수 있었다. 두 원인을 수정한 뒤 별도 인스턴스의 최종 33 PASS 실행으로 재검증했다. 최초 실패는 `.qa/infra/feature-20261014-f038977eef/logs/pytest.log`에 남아 있다.
- 독립 검토에서 claim 직후 취소된 worker가 삭제 실패 뒤 이벤트를 다시 만들고, 재시도가 잔여 이벤트를 남긴 채 완료되는 상황을 합성 자료로 재현했다. 작업 상태 전환을 조사 잠금 안으로 옮기고 취소 시 최신 상태를 읽으며, 삭제 최종화 전 이벤트를 다시 정리·검사하도록 수정했다. 감사의 DB 잠금과 프로세스 잠금 순서도 회귀 시험으로 확인했다.
- 과거자료 룰 시험이 자료 삭제·권한 회수 뒤 결과 표본을 저장하는 경합 5건, 세션 무효화 경합 3건은 RED를 확인한 뒤 저장 직전 권한·자료 epoch·룰 버전·세션을 재검사하여 차단했다. 관련 최종 집중 시험 17 PASS와 위 실제 저장소 8 PASS로 확인했다. 초기 구현 과정의 SQLAlchemy `update` 이름 충돌도 보존된 실패 로그에 기록하고 alias 수정 후 재검증했다.
- peer 비교에서 동일 IPv6의 다른 표기를 서로 다른 출발지로 세던 문제를 수정했다. 비교에는 정규화 주소를 쓰고, 원문 연결에는 원래 표기를 보존한다. 시간 차트에서 범위를 선택할 때 기존 시간 필터 밖으로 넓어지던 문제도 수정·재검증했다.
- 최초 전체 UI 시험은 한글 화면으로 바뀐 제목을 기존 시험이 영문 `ANALYSIS OVERVIEW`로 찾으며 **1 FAIL, 128 PASS**였다. 실제 한글 화면에 맞게 기대값을 고친 뒤 최종 전체 UI 130 PASS를 확인했다. 근거: `.qa/features-20261014-ui-full.log`, `.qa/features-20261014-ui-full-final.log`.
- 시험 시작 전 설정 오류는 제품 실패와 분리했다. Vitest worker 최소·최대 설정 충돌은 시험 0건, 네이티브 진행 기록 hook의 인자 오류는 `PluginValidationError`로 제품 시험을 실행하지 못했다. 설정 수정 후 재실행했으며 각각 `.qa/baseline-20261014-ui.log`, `.qa/infra/feature-20261014-0bf1d5fd26/receipt.json`에 남겼다.

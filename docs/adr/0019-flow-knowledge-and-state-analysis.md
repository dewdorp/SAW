# ADR-0019: 분석가 지식의 자동 적용과 시간 흐름·상태 분석

- 상태: Accepted
- 날짜: 2026-11-13

## Context

분석가가 로그를 보며 확인한 업무 의미("auth.html은 인증 기능, memberinfo는 회원정보 조회")가 다음 자료에 자동으로 적용되고,
인증 → 조회처럼 시간순으로 이어지는 행위를 근거·미확인 사항과 함께 설명해야 한다.

저장소를 확인한 결과(2026-11-13, v0.2.5 기준):

| 영역 | 상태 | 근거 |
|---|---|---|
| NDR·FW CSV 파서, 정규화, 업로드·작업 큐, 원문 보존 | 작동함 | `saw/parsers/security_csv.py`, `saw/workers/pipeline.py`, 서버 전체 시험 |
| 임계치 기반 조사 질문 4개(웹·전송·반복·확산) | 작동함 | `saw/core/application/question_bundles.py` |
| 장비 공격명 해석 등록부(버전·정확 일치) | 작동함 | `saw/internal_kb/signatures.py` |
| 판단·후속 확인·내부 골든·후보함·사례집 | 작동함 | `saw/followups`, `saw/internal_kb`, 사례집 W01~W60 |
| 요청의 업무 의미 저장과 자동 적용 | 없음 | 경로·서비스 단위 지식 모델이 없었음 |
| 세션·인증 상태를 따라가는 흐름 분석 | 없음 | 쿠키 값은 저장하지 않아 요청을 세션으로 묶을 수단이 없었음 |
| WAF·IPS·DDoS·애플리케이션 로그 전용 입력 | 일부 | 일반 WAF JSON 파서만 있고 요청 ID·업무 결과 열이 없었음 |
| Logpresso 연동 | 모의만 | `saw/connectors/mock_logpresso.py` |
| 앱·콘텐츠 버전 구분 표시 | 없음 | 화면에 버전이 없고, 열려 있던 화면은 업데이트 뒤에도 이전 묶음으로 동작 |

## 비교한 접근

| 기준 | A. 분석가가 순서 규칙을 직접 작성(EQL식 시퀀스) | B. 메모를 모델·검색에 맡김(RAG) | C. 지식을 자료로 저장하고 결정적 엔진이 적용 |
|---|---|---|---|
| 분석가 작업량 | 높음(조건식 작성·유지) | 낮음 | 낮음(본 자리에서 문장·몇 칸) |
| 설명 가능성 | 높음 | 낮음(같은 입력에 다른 답) | 높음(적용한 지식 버전·연결 근거 표시) |
| 새 흐름 발견 | 없음(쓴 규칙만) | 우연 | 있음(전이 집계와 등록 흐름 비교) |
| 데이터 요구 | 세션 키 필요 | 모델·GPU | 세션 참조·결과 기준(없으면 '후보'·'미확인') |
| 폐쇄망·모델 없음 | 가능 | 불가 | 가능 |
| 100만 행 | 가능 | 어려움 | 가능(시간순 1회 통과) |
| 유지보수 | 규칙 수에 비례 | 모델 품질에 종속 | 지식 항목 단위, 버전 관리 |

**C를 선택**했다. 모델은 초안 제안에만 쓰는 선택 기능으로 남기고, 지식 적용·정렬·연결·상태 판정은 재현 가능한 처리로 둔다.
기존 기획에서 유지한 것: 쿠키 값 미저장, 장비 공격명 정확 일치, 판단과 지식의 분리, 실행 스냅샷 보존.
바꾼 것: (1) 메뉴를 새로 만들지 않고 조사 화면 "② 조사 > 업무 흐름"과 기록 상세에 넣었다. (2) 의미를 이벤트에 써넣지 않고
읽을 때 적용한다 — 지식이 바뀌어도 재색인 없이 다시 분석하고, 끝난 분석은 당시 버전을 그대로 갖는다.
(3) 인증 성공·업무 결과는 HTTP 상태에서 추정하지 않고 분석가가 등록한 "결과 확인 기준"으로만 정한다.

## Decision

1. **지식 모델** (`saw/flows/models.py`, 마이그레이션 0027, 추가만)
   - `fk_knowledge` + `fk_knowledge_version`: 종류 3가지
     - 업무 의미(activity): 서비스·메서드·경로(정확/시작/패턴)·파라미터 → 의미, 역할, 조회 대상 파라미터, 결과 확인 기준
     - 연결 기준(link): 세션 식별 쿠키 이름, uuid가 요청 ID인지 여부. 확인하지 않은 항목은 연결에 쓰지 않는다.
     - 흐름(flow): 업무 의미의 순서, 필요한 결과, 선택·반복 단계, 최대 간격, 분류(정상/의심/미확정)
   - 범위: 공통 또는 관계사 하나. 같은 범위의 다른 정의는 저장을 거부하거나 '상충'으로 남기며, 상충은 어느 쪽도 적용하지 않는다.
   - 수정·중지·복원은 모두 새 버전이고 이력은 지워지지 않는다. 동시 수정은 기대 버전으로 막는다(409).
   - `fk_judgement`: 이번 사건의 판단. 재사용 지식이 아니며 다른 조사에 적용되지 않는다.
2. **연결용 참조**: 파서가 쿠키·세션 값을 설치별 키의 HMAC 16자리로 바꿔 저장한다(값은 저장하지 않음). 같은 값이면 같은 참조라
   NDR 요청과 애플리케이션 기록을 세션으로 묶을 수 있다. 키는 기존 조회 키에서 파생해 새 키 파일을 만들지 않는다.
3. **엔진** (`saw/flows/engine.py`): 발생 시각 순으로 HTTP 기록을 한 번 읽는다.
   - 의미 적용(더 구체적인 정의 우선) → 세션 단위(확인된 쿠키) 또는 후보 단위(같은 IP·서비스·UA, 30분 침묵으로 분리) 묶기
   - 결과: 등록된 기준에 맞는 기록(요청 ID 일치 > 같은 세션 5초 이내 > 같은 IP는 후보)만 성공·실패로 본다.
   - 인증 문맥: 성공 뒤 / 실패만 있음 / 시도했으나 미확인 / 앞선 기록 없음(수집 구간 이전 가능) / 로그아웃 뒤
   - 등록 흐름 비교(순서·결과·간격), 전이 집계(직전 단계 → 다음 단계)와 등록 흐름으로 설명되지 않는 전이
   - 보안장비: 요청 ID 일치는 '같은 요청', 주소·시간 근접은 '관련 후보'. 장비 탐지·장비 조치·HTTP 응답·업무 결과는 따로 둔다.
   - DDoS: 서비스 단위 구간으로만 표시하고 흐름에는 "같은 시간대"만 붙인다.
   - 중복 기록 제외, 같은 시각은 순서 미확정, 시각 없는 기록은 흐름에 넣지 않고 센다.
4. **실행** (`saw/flows/service.py`): 업로드·분석 작업 끝에 자동 실행(실패해도 업로드는 실패하지 않음). 결과는 `fk_run`에 추가만 한다.
   같은 기록·같은 지식·같은 범위의 최신 실행은 재사용한다. 지식이나 기록이 바뀌면 "최신이 아님"을 표시하고, 다시 분석하면
   이전 실행을 남긴 채 달라진 지식·흐름과 이유를 기록한다.
5. **입력 프로필** (`saw/parsers/security_profiles.py`): WAF·IPS·DDoS·애플리케이션 CSV. 실제 벤더 자료가 없어 열 이름을 정한
   "연결 가능한 프로필"이며 벤더 지원이 아니다.
6. **버전 표시** (`/system/versions`): 앱·화면 묶음·스키마·사례 콘텐츠·지식을 따로 보여 주고, 열려 있는 화면이 이전 묶음이면 새로 고침을 안내한다.

## 개발 순서

1. 지식 모델·엔진·자동 실행·대표 시나리오(인증 → 회원정보 조회) — 완료
2. WAF·IPS·DDoS·FW 연계 — 완료(합성 프로필)
3. 새 전이 발견, 지식 수정·상충·복원·재분석, 사례 F01~F07, 버전 표시 — 완료
4. 통합 시험·성능 측정 — `docs/verification/flow-knowledge-20261113.md`

## Consequences

- 지식이 없으면 흐름은 나오지 않고 "등록된 업무 의미가 없음"으로 표시된다. 세션 쿠키를 모르면 모든 흐름이 '후보'다.
- 0.2.5 이전에 올린 NDR 자료에는 연결용 참조가 없다. 세션 연결을 쓰려면 그 증거를 재처리해야 한다.
- 흐름 실행은 요청 스레드에서 돈다(SQLite 10만 행 기준 수 초~수십 초). 더 큰 범위는 작업 큐로 옮길 여지가 있다.
- 한 번에 읽는 HTTP 기록은 300만 건, 보조 기록은 종류별 30만 건으로 제한하고 넘으면 '일부만 검사'로 표시한다.
- native OpenSearch에서의 실행, 실제 벤더 로그, Logpresso 실연동, 로컬 모델을 쓴 초안 제안은 검증하지 않았다.

# SAW 0.2.3 운영 설치·업데이트 점검표 (2026-11-02)

운영 서버에 SAW 0.2.3을 새로 설치하거나 기존 설치를 0.2.3으로 올릴 때 이 순서로 진행합니다. 자세한 명령과 화면은 매체 안의 `START-HERE.md`, `app/docs/INSTALL-WINDOWS.md`, `app/docs/DOUBLE-CLICK-UPDATE-GUIDE.md`, `app/docs/OFFLINE-UPDATE-GUIDE.md`를 따릅니다.

## 0. 먼저 알아둘 것

- 매체: `SAW-0.2.3-pilot.20261102-model-free-win-x64.zip` (1,448,566,089바이트, SHA-256 `2b9ba7c1187dbcda09a0d9b052b7f956af8899a0ddfdf82d17fae9e378004593`). 모델 가중치는 들어 있지 않습니다.
- 대상: Windows 10 Enterprise LTSC 2019 x64(17763), PowerShell 5.1, 폐쇄망. **이 대상 OS에서의 설치·관리자 서비스·재부팅은 아직 실제로 확인하지 못했습니다.** 개발 PC(Windows 11)에서는 신규 설치·업데이트·복구를 실제로 확인했습니다(아래 6절). 운영 반영 전에 대상 서버와 같은 환경의 시험 서버에서 먼저 한 번 실행하기를 권합니다.
- 이번 버전은 데이터베이스에 표 2개(저장된 질문 조건)를 **추가만** 합니다. 기존 계정·조사·자료·설정은 바뀌지 않습니다.

## 1. 반입과 확인

1. ZIP을 폐쇄망으로 반입하고 위 SHA-256과 같은지 확인합니다(PowerShell: `Get-FileHash .\SAW-0.2.3-...zip -Algorithm SHA256`).
2. 기존 설치 폴더 밖의 빈 폴더에 압축을 풉니다. 예: `D:\SAW-media-0.2.3`. 기존 설치 폴더 위에 풀지 않습니다.
3. 설치 폴더 드라이브에 여유 공간을 확인합니다(신규 설치 최소 20GB, 업데이트는 복구본을 만들 공간이 추가로 필요).

## 2-A. 새 서버에 설치

관리자 권한 PowerShell에서 매체 폴더로 이동한 뒤(호스트명·접속 허용 대역은 실제 값으로):

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\install.ps1 -InstallRoot "D:\SAW" -HostName "saw.corp.local" -AllowFrom "10.20.0.0/16"
```

실패하면 원인을 확인하고 **같은 매체·같은 경로·같은 옵션**으로 다시 실행합니다. 설치 폴더·data·secrets를 지우지 않습니다.

## 2-B. 기존 설치를 0.2.3으로 업데이트

1. 분석가에게 작업 저장을 알리고, 설치 방식(서비스/NoAdmin)에 맞게 SAW를 중지합니다(`OFFLINE-UPDATE-GUIDE.md` 2절).
2. 새 매체 폴더의 **UPDATE-SAW.cmd**를 실행합니다. 프로그램이 매체를 검사하고, 적용 전에 **복구본을 자동으로 만든 뒤** 새 앱을 적용합니다.
3. 적용 중 실패하면 프로그램이 업데이트 직전 상태로 되돌립니다. 결과 화면의 상태와 기록 위치를 확인합니다.

## 3. 설치·업데이트 뒤 확인

| 확인 | 기대 |
|---|---|
| 로그인 | 기존 계정과 MFA로 로그인됨(업데이트), 새 관리자 계정 설정(신규) |
| 조사 목록 | 기존 조사·관계사가 그대로 보임 |
| 조사 화면 | 상단 작업 영역 ①전체 현황 ②조사 ③전체 로그 ④확인 및 판단 |
| 확인할 질문 | 각 질문에 "조건 수정" 버튼, 계산 범위(조사 기간·question-bundles/2) 표시 |
| 시험 조사 | 가상 자료 조사를 하나 만들어 영문 NDR/FW CSV를 올리면 전용 파서로 인식, 질문 계산 |
| 종료·재시작 | 정상 종료 후 다시 시작해도 자료·저장 조건이 남아 있음 |

운영 자료로 시험하지 말고 가상 자료 조사로 확인한 뒤 그 조사는 보관 정책에 따라 정리합니다.

## 4. 문제가 있을 때 되돌리기

- 업데이트 직후 문제가 있으면 `OFFLINE-UPDATE-GUIDE.md` 6절의 "업데이트 직전 시점으로 복구"를 따릅니다. 업데이트가 만든 복구본으로 이전 앱과 자료로 돌아갑니다.
- 0.2.3에서 추가된 표(저장된 질문 조건)는 이전 버전이 사용하지 않으므로 남아 있어도 이전 버전 동작에 영향이 없습니다. 이전 버전으로 되돌리면 0.2.3에서 저장한 질문 조건은 화면에 보이지 않습니다.

## 5. 이번 버전에서 바뀐 사용 방법

`app/docs/ANALYST-WORKFLOW-GUIDE-20261029.md` 9·10절: 영문 NDR/FW 자동 인식, 확인할 질문의 조건 수정·미리 보기·저장, 같은 범위 전체 로그, 확인 기록에 질문 전체 보존, 예제 명세 120개 검색.

## 6. 실제로 확인한 범위

- 개발 PC(Windows 11 Pro 26200)의 별도 시험 경로에서 NoAdmin 사용자 프로세스 방식으로 0.2.3 매체의 신규 설치·재개·정상 종료/재시작·별도 백업/복구, 이전 파일럿 설치(v0.1.0-pilot.20261019 계열, 스키마 0014)에서 0.2.3으로 업데이트·주입 실패 뒤 자동 복구·업데이트 성공 뒤 전체 복구·계정/MFA/자료 비교를 단계별로 실행했습니다. 결과는 `docs/verification/review-scope-20261102.md` 9절에 있습니다.
- 확인하지 못한 것: 대상 LTSC 2019, 관리자 서비스 설치·재부팅, 실제 운영 자료 규모의 성능, OpenSearch/PostgreSQL 운영 구성.

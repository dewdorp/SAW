# 운영 환경 업데이트 안내 — 가상 공격 시나리오 코퍼스 · 분석가 안내 (2026-10-28)

지금 운영 중인 SAW(예: `C:\SAW`)에 이번 작업 결과를 반영하는 절차입니다. 두 가지는 **성격이 다르니 나눠서** 진행하세요.

| 반영 대상 | 지금 설치 가능한가? | 반영 방법 |
|---|---|---|
| **① 가상 공격 시나리오 데이터(72개 CSV)** | 예 — 지금 바로 | 운영 SAW에 **증거로 업로드**(아래 2절) |
| **② 분석가용 시나리오 안내(제품 화면 기능)** | 아니오 — 아직 설치 매체 없음 | **새 파일럿 매체 빌드 후 UPDATE-SAW.cmd**(아래 3절) |

> 중요: 분석가 안내(시나리오별 "지금 할 일" 등)는 소스 브랜치/PR #4에만 있고 **아직 설치용 전체 매체(ZIP)로 빌드·검증되지 않았습니다.** 데이터만 먼저 넣을 수 있고, 화면 기능은 새 매체가 나와야 반영됩니다.

---

## 0. 먼저 지킬 것 (운영 보호)

- **실제 은행 자료와 절대 섞지 마세요.** 가상 코퍼스는 **새 조사**에만 올리고, 운영 실조사(예: `INV-20261008-001`)나 `var/objects`에는 넣지 않습니다. 조사 이름에 "가상/합성/훈련"을 명시하세요.
- 운영 설치·계정·자료·기존 릴리스·`main`은 보존합니다. 이 절차는 **추가 업로드**이며 기존 데이터를 지우지 않습니다.
- 폐쇄망 반입은 조직의 **반입(reintroduction) 절차**를 따릅니다. 파일은 조직 검증·서명 절차를 거쳐 들여옵니다.
- 데이터는 전부 가상(문서용/사설 IP, `*.example.test`)이며 실행 가능한 공격 코드가 없습니다. 그래도 반입 승인 절차는 동일하게 거칩니다.

## 1. 반입할 파일 가져오기

사전 릴리스 **[v0.1.0-pilot.20261028-attack-corpus](https://github.com/dewdorp/SAW/releases/tag/v0.1.0-pilot.20261028-attack-corpus)**에서 내려받습니다.

- `catalog.json` — 63개 시나리오 요약(빠른 확인용)
- `manifest.jsonl` — 파일·행별 라벨(시나리오 id·MITRE 기법·공격 단계·공격/정상·기대 신호)

조직 반입 절차로 운영망 안으로 들여온 뒤, 기존 설치와 **다른 폴더**(예: `D:\SAW-training-corpus-20261028`)에 풉니다.

## 2. 운영 SAW에 데이터 올리기 (지금 가능)

반복 CSV 업로드 방식과 동일합니다. 자세한 화면은 [반복 CSV 안내](RECURRING-SECURITY-CSV-GUIDE-20261025.md)를 보세요.

1. **조사 목록 → 새 조사**를 만듭니다. 이름에 목적을 명시: 예 "가상 공격 시나리오 훈련셋 2026-10-28". (실조사에 섞지 않기)
2. 시나리오 단위로 올립니다. 한 시나리오의 FW/NDR 파일을 **한 조사**에, 한 사건(incident-*)은 그 FW+NDR를 같은 조사에 함께 올립니다.
3. 조사 작업대 → **증거 추가** → 종류 **자동 감지** → 파일 선택 → **업로드 및 분석 시작**.
4. 파서가 FW는 `ko_fw_csv`, NDR은 `ko_ndr_csv`로 잡혔는지, 읽은 이벤트·실패 건수를 확인합니다.
5. **대조군(benign-*)은 각각 별도 조사**에 올립니다. 공격 예제와 같은 조사에 섞으면 음성 대조가 되지 않습니다.

### 라벨 활용(골든셋·학습)
- `manifest.jsonl`의 각 레코드가 **정답 라벨**입니다. 분석 결과를 검토할 때 이 라벨을 근거로 탐지 정답(TP/FP/FN/TN)을 붙입니다.
- 골든셋은 플랫폼의 **분석가 승인 거버넌스**(작성자와 다른 검토자의 채택, 독립 반출 승인)를 따릅니다. 데이터를 올렸다고 자동으로 골든셋이 되지 않습니다. 자세한 흐름은 [골든셋 안내](AFFILIATE-GOLDEN-GUIDE-20261023.md).

### 탐지가 바로 안 뜨는 시나리오(정상)
- **방화벽(fw.observation)** 계열: 장비 프로필에서 시간·바이트 방향·세션·대응 매핑을 **확인(verified)** 해야 동작합니다(장비·자료 의미 설정). 미설정이면 "자료 부족"으로 남습니다 — 오류가 아닙니다.
- **NDR 정책 5종**(대량 송신·비표준 포트·해외 목적지·업무시간 밖/내부 관리): 사이트 기준값(내부망·정상 포트·기준 국가·관리 포트·업무시간)을 **켜야** 동작합니다.
- **업무시간 밖 민감 조회**: 자산 지식(예상 접근 시간)이 있어야 뜹니다.
- 이는 미확인 정보를 임의로 채우지 않으려는 설계입니다. 라벨(manifest)은 그대로 정답으로 쓰고, 탐지가 안 뜨면 위 설정 상태부터 확인하세요.

### 데이터 반영 되돌리기
- 잘못 올렸으면 **해당 가상 조사만** 운영 절차에 따라 정리합니다. 다른 조사·자료는 건드리지 않습니다.

## 3. 분석가용 화면 기능 반영 (새 매체 빌드가 필요)

분석 결과 화면의 **시나리오별 "지금 할 일"·확인 항목 안내**는 제품 소스 변경입니다. 현재 설치된 운영 버전과 최근 파일럿 매체(`v0.1.0-pilot.20261027`)에는 **포함돼 있지 않습니다.** 반영하려면 새 파일럿 매체가 필요합니다.

**순서(담당자 작업):**
1. 브랜치 `codex/affiliate-p0-20261020`(PR #4)를 검토·승인합니다.
2. 새 **모델 제외 전체 매체 ZIP**를 빌드하고 독립 해제로 무결성을 검증합니다(기존 매체 빌드 절차와 동일).
3. 합성 설치에서 **새 설치·0014/현행 업데이트·실패·전체 복구·설치 CSV smoke**를 확인합니다(이번에는 데이터만 릴리스했고 이 매체 리허설은 **미수행**입니다).
4. 반입 후, 새 매체를 기존 설치 밖 새 폴더에 풀고 **UPDATE-SAW.cmd**를 실행합니다. 기존 설치 폴더(`C:\SAW`)와 복구본 폴더(같은 드라이브의 새 폴더)를 지정하고 9개 점검 결과를 확인한 뒤 동의합니다. 자세한 절차·복구는 [업데이트 점검·복구 안내](UPDATER-STABILIZATION-GUIDE-20261019.md).
5. 적용 후 계정으로 로그인해 조사·분석 이력과 **새 시나리오 안내 표시**를 확인합니다. 문제가 있으면 같은 도구에서 **전체 복구본**을 선택해 되돌립니다.

> 화면 확인은 운영 분석가 계정 또는 점검용 계정으로 하고, 자동 시험으로도 확인할 수 있습니다.

## 4. 이번 작업의 검증 범위 (중요)

사용자 요청으로 **전체 검증은 생략**했습니다.
- **한 것**: 코퍼스 생성·전용 파서 인식/파싱(72파일·11,791행·실패 0), 코퍼스/시나리오 단위·화면 테스트 통과, 사전 릴리스 자산 게시 확인.
- **안 한 것**: 전체 서버 게이트 재실행, 63개 시나리오 전부의 탐지·흐름 파이프라인 종단 검증, **새 설치 매체 빌드·리허설**(3절은 그래서 담당자 작업으로 남겨 둠).
- 제품 코드·운영 설치·운영 자료·계정·기존 제품 릴리스·`main`은 변경하지 않았습니다.
